# G00 公司管理总览前端范围

开发预览入口：`/__preview/company-overview`。仅在开发构建中挂载，正式 `Dashboard.tsx` 和真实首页的数据接口保持原有实现。页面用于管理层按月份、产品核对出货目标和当前经办事项。

## 已完成的页面与交互

- 全局月份、产品和演示查看范围保存在 URL，切换上下文关闭旧详情和草稿；未知产品及范围保留原始入参并提示，不静默映射或放宽。
- 月度出货目标、整机完工、QA 授权放行、实际出货独立列示；每项可打开原始凭据及原业务页面。
- 研发、供应链、生产和质量按当前经办部门列示待办；按单一归属绘制横向数量条，没有虚构日趋势、环比或公司综合合格率。
- 事项表支持参与部门、经办人 / 单号 / 关键词筛选及分页，详情包含经办人、环节、原截止日期、原来源与证据链接。
- 跨月未完为独立常驻提醒，含所选月份之前的未完和其他月份已逾期事项；部门、搜索和分页不隐藏此提醒。
- 来源状态可演示正常、生产来源缺失、本次读取失败、空来源。失败保留上次成功读取的值和本地读取时间；缺失不补零，正常来源无当期记录与来源不可读分别呈现。
- 管理层演示岗位可生成包含原单编号、当前经办、期限和来源链接的本地催办草稿；仅查看岗位禁用生成。没有调用模型、改期、指派或实际发送。

## 指标与来源

| 项目 | 原始来源 | 日期与数量口径 |
| --- | --- | --- |
| 出货目标 | S14 `ShipmentState.months[month].target` | 原来源仅提供全部产品目标，未按产品或经办人分摊 |
| 整机完工 | P01 `PlanningBatch.completed` / `completionSource` | 按 `completedDate` 归月，仅整机完工凭据；组件和工序报工不相加 |
| QA 放行 | P03 `InspectionRelease` | 只计终检、单位为台的授权记录，按上海业务日期归月 |
| 实际出货 | S14 `ShipmentRecord` | 按实际出货日期，只计已确认登记，待确认和冲销不计入 |
| 终检首次合格率 | P03 `InspectionRecord` | 同月份终检「台」的首次合格数量 / 初检数量；复验、过程检验不混入 |
| 待办 | P00 原任务投影及 P08 流程依据 | P01 / P03 / P05 / P08 / P10 样例，保留原单日期、当前经办和期限 |

2026-09 全产品样例：P01 完工 216 台、P03 QA 放行 100 台、S14 实际出货 180 台、S14 出货目标 1,000 台。三套样例的批次覆盖不同，页面明确说明不能用这些数相减推算在制、待放行或待出货库存。S14 自带的完工摘要和批次放行数不并入 P01 / P03 指标。P01 的生产计划目标 1,200 台也不替代 S14 出货目标。

生产产品编码为 IN-100 / IN-200；Q7 / Q5 属于 S15 / S18 的独立齐套样例。通过明确相同的原始产品名称确认 P03 记录的 IN 系列归属，不把 Q 系列与 IN 系列建立推测映射。无匹配产品时显示缺失值。

当期生产待办的覆盖范围在页面明确列出。研发、采购真实工作台中的独立待办没有读取，卡片数量不代表对应部门全部业务量。今日在岗尚未有共享来源，因此不显示虚构人数。

## 事项去重与当前节点

P08 不良采用 `defect-origin:<sourceKey>` 作为统一事项标识，同一原不良在质量、生产和研发协同只算一项。其他业务采用原任务唯一键，不按标题或人员去重；部门筛选可按参与部门命中，统计条只按当前经办部门计一次。

当前经办沿用 P00 / P04 流程投影。技术协同完成后归质量；现场验证阶段按当前验证岗位归生产，仍显示研发参与。P08 已全部取得 QC 合格回执且没有活动 P04 技术协同时，利用现有进度计算和关闭条件校验识别「QC 复验通过，待质量关闭」，显示质量管理岗和原 QC 凭据，不改写不良原单的 `ownerId`；QC 回执齐全不覆盖正在办理的研发协同节点。

## 入口与范围

- S15：`/__preview/monthly-readiness?month=YYYY-MM&product=...&scope=...`。
- S18：`/__preview/key-materials?month=YYYY-MM&product=...&scope=...`，包含无需求目录入口。
- R00 / S00：通过现有 `routePath` 解析正式可配置路径，标明需要正常登录和页面权限；预览不自动登录或请求正式业务接口。
- P00 / P03：使用已存在的开发预览路径。原页未实现 G00 的产品 / 经办筛选，因此仅在全部产品、全部范围下提供全量入口；其他上下文提示该限制，事项原单仍按准确 ID 跳转。
- `scope=owned` 仅展示王晴经办事项。现有生产样例没有王晴事项，显示空态；无经办归属的指标及其明细一并隐藏。未知范围同样隐藏数据，防止静默退回全量。

这些是前端演示范围约束，不代替后端权限。各页面的真实数据、权限及跨模块同步属于后续业务接通阶段。

## 设计与验证

采用项目既有 Horizon 风格：Klein Blue `#002fa7`、业务墨色 `#1b2559`、画布 `#f4f7fe`、白色 `#ffffff`、质量绿 `#087855`、风险棕 `#87522f`。标题使用现有 Inter / 苹方字族，中英数据使用等宽数字特性；主要视觉结构是「出货目标基线 + 三种独立凭据」，不把独立来源画成一个生产漏斗。桌面使用密集业务表，手机转换为带原单入口的事项卡，控制可键盘访问且有明确焦点。

`node --test scripts/company-overview-*.test.mjs`：23 项通过，覆盖独立数量口径、初检分母、上海归月、来源去重、责任节点迁移、活动研发节点保护、范围明细保护、跨月提醒、可配置正式路由、深链保留、来源状态、筛选分页及只读来源草稿。

类型检查通过。整站构建和实际浏览器桌面 / 手机验收由本轮父任务统一执行，避免把组件模拟测试表述为端到端业务验收。
