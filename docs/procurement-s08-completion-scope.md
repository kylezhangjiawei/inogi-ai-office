# S08 供应商承诺、ERP 交期历史与全量镜像日期视图

2026-09-14。本轮把原 S08 前端占位接至现有 PostgreSQL `RuntimeState` 持久化和订单镜像；未创建新表、执行迁移、调用真实业务写接口或通知。旧的 S08 前端范围文档是阶段记录，供应商承诺和 ERP 历史缺口以本文更新为准。

## 业务能力与边界

- **供应商承诺独立登记**：精确镜像行 ID + 订单号读取。首次登记必须明确勾选且有凭据才能称为“最初承诺”；未勾选则最初承诺继续未知。后续改期或撤销必须填写供应商沟通日、凭据出处和原因，保留版本、操作者、登记时来源和完整分页历史。不会把第一笔人工可用日、ERP 日期或没有证据的第一笔登记当最初承诺。
- **ERP 同步观察历史**：`tplus-sync.service.ts` 的镜像 upsert 接至 `persistMirrorDelivery`，镜像写入、观察状态、不可变历史和审计在同一事务。第一次只建立观察基线；若旧镜像与本次同步不同，记录此次已知前后变化。之后预计到货日、订单日期或物料/供应商/单位/数量等来源变化产生新版本，单纯同步时间变化不生成重复历史。日期清空也记录。观察时间不等于供应商实际改期时间，启用前不存在的历史不补造。
- **全量镜像日历与甘特**：采购工作台新增可展开区域，通过独立服务对账号有权查看的全部已同步镜像分页查询，不依赖任务关联、不受本人任务列表分页影响。支持月份、订单/物料/规格搜索、精确供应商、本月/全部/无日期/月外、按日定位、日历与甘特切换；日历每天统计全范围订单行数，明细默认每页 20 行，甘特明确只画当前页。
- **日期口径**：日历归日采用 ERP 当前预计到货。甘特表示已有订单日期至预计到货的区间，跨月截取、缺订单日仅画预计到货点、日期倒置标为待核对；无预计日期不生成假条。供应商登记承诺单独并列，不改 ERP、不等于检验后可用量。
- **现有订单详情接入**：S14 代理已按精确行 ID 挂“供应商承诺与 ERP 交期”抽屉。其他人工预计检验后可用日期和统一审计抽屉继续独立；旧抽屉不再声称供应商来源一概未提供，而提示查看新的独立交期记录。
- **上下文与状态**：日期筛选、页码、视图写入独立 `delivery*` URL 字段。订单导航带经过白名单校验的工作台返回地址与目标行 ID，返回时恢复日期上下文；不按 SKU 猜替代行。账号/权限变化卸载旧范围；异步请求按当前范围及请求代次隔离。读取失败显示未知和重试，不能作为 0 行。历史表单关闭时保护脏草稿，保存期间阻止关闭与重复提交。

## 权限与持久化合同

读取需 `page:purchase-orders` 或 `page:purchase-order-detail`，沿用现有订单全镜像页面授权范围。只有 `page:proc-my-workspace` 不会放开全部镜像。登记还需 `page:purchase-order-detail` **以及**新动作 `proc-purchase-order:record-commitment`；通配权限沿用系统惯例。新控制器和服务由根代理注册，新权限由根代理加入目录；没有自行扩展采购任务或研发测试权限来读订单。

存储前缀 `procurement:delivery:v1:`，按行分 supplier/erp 的 current 和 history，历史版本 key 固定补零保证排序。供应商登记事务先锁提交标识，再锁精确镜像行，校验来源 `updatedAt` 与承诺版本，写当前值、历史、幂等标识和审计。同一账号和完全相同请求 ID/内容可在超时或重启后安全重试；同 ID 不同内容/账号被拒绝，同版本并发改动只有一个成功。ERP 首建采用按订单号+行号的事务 advisory lock，避免尚无镜像行时并发建基线。任何审计写失败整笔回滚。持久化格式错误显示不可用并保留原值。

日期分页接口采用 Repeatable Read；日历和行分页在一个数据库快照内读取。翻页携带与账号权限、筛选、镜像/人工承诺更新时间关联的指纹，来源改变返回 409 并要求刷新，避免把不同批次分页拼成“全量”。“全量”仅表示系统已同步镜像及当前订单页面权限范围，不表示 ERP 尚未同步的订单。

HTTP：

- `GET /api/procurement/delivery/schedule?month=YYYY-MM&bucket=all|month|undated|outside&page=1&pageSize=20`，可附 date/q/supplier/snapshot。
- `GET /api/procurement/delivery/lines/:lineId?orderNo=...&supplierPage=1&erpPage=1`。
- `POST /api/procurement/delivery/lines/:lineId/commitments`，日期、沟通日、证据、原因、原承诺声明、来源版本、承诺版本、requestId 全部明确传入。
