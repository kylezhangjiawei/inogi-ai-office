## 已完成

- 采购订单商品明细的右侧操作区增加“收货与检验”，与既有人工可用日期确认并列。按订单行 ID 打开，关闭返回触发行；同料号不同订单行分别保留。
- 桌面抽屉上方展示订单行与 ERP 来源，下方左侧分批收货及历史，右侧数量汇总与登记表单。手机单列，打开表单自动滚入并聚焦，保存成功回到结果提示。
- 收货逐笔记录送货单号、实收数量、收货日期、备注、登记人及时间。数量为正数，最多三位小数；日期不得晚于北京时间当日。登记前显示本台账剩余可登记量。
- 同一订单行的送货单号只能登记一次，本台账实收合计不得超过当前订单数量。收货原始记录不可直接修改或删除；保存前展示核对提示。
- 每批次可追加多次检验结果，使用本批累计合格、不良、待判定数量，未检验量由剩余计算。检验依据和结论说明必填；日期不得早于收货日或晚于今天。新判定替换当前结果，历史版本全部保留，不重复累计各版数量。
- 批次列表每页 10 条，分页位于列表上方；每批可展开检验历史。原订单身份、编码、名称、规格、单位、供应商和下单量保存为不可变快照。
- ERP 来源身份、物料、规格、单位或供应商变化时保留历史并阻断继续登记，提供原始来源核对。历史数量使用登记时单位，异常混单位不合计。正常订单量调整按已登记实收总量验证。
- 分别提供订单查看、收货登记、检验登记权限；前后端同时校验。无写权限可以查看历史。
- 保存中防双击与关闭；失败保留草稿；30 秒超时说明结果尚未确认，原内容重试使用同一提交标识。版本冲突须重新载入并明确核对后才可提交。离开已填写表单先确认是否放弃。

## 数据边界

新增 `ProcPurchaseReceipt` 与 `ProcPurchaseReceiptInspection` 两张表，以及三条读写接口：

- GET/POST `/api/procurement/purchase-order-lines/:lineId/receipts`
- POST `/api/procurement/purchase-order-lines/:lineId/receipts/:receiptId/inspections`

所有写操作在事务内先锁定所属采购订单行，再执行数量、来源及版本校验；收货、检验与操作审计一并成功或回滚。请求标识支持幂等，同一标识变更内容或操作者会拒绝。响应仅包含本台账需要的业务字段，不下发价格、原始 ERP metadata 或提交指纹。

当前 ERP `receivedQty` 来自 T+ 同步汇总，本期没有确认其是否代表完成检验/入库。因此与本地台账分开展示，不加总、不从可登记量中扣减，也不据此生成收货批次。登记收货和检验不会修改 ERP 镜像、采购任务到货量、备货计划合格量、库存或齐套结果。

已应用本地迁移 `20260910120000_purchase_receipts`，当时它是唯一待执行迁移。验收后只读确认两张表均为 0 条业务记录。真实订单只做读取；所有模拟收货、检验和冲突操作都在内存或已清理的随机 PostgreSQL 测试 schema 中完成。未发布生产。
