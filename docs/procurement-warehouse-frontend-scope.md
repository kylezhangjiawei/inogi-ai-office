# 仓管工作台：库存、发料、生产退料与盘点前端预览

2026-09-11。按本轮授权，先完善页面和交互，再接入正式接口与业务。参考开发资料中的 S09 库存台账、S05 仓管工作台、S11 生产退料和 S12 盘点流程；资料作为设计参考，不视为真实接口、库存记账规则或上线授权。

开发预览路由：`/__preview/warehouse`。页签与选中记录使用 `tab=inventory|issues|returns|counts&selected=记录ID` 保存到 URL。新增记录只在当前页面内存保留；刷新或重置演示后恢复初始数据，旧新增记录链接显示未找到提示。

## 本批范围

| 页签 | 页面和交互 |
| --- | --- |
| 库存记录（S09） | 按物料、批次、仓库筛选；显示仓库/库位、规格/版本、来源；区分合格现存、占用、未占用可用、待检、不良隔离与冻结；查看本批库存事务、线边及待签收记录；从具体批次发起盘点 |
| 发料与签收（S05） | 派工用料与领料单列表；展示组件数量、BOM 版本、单位用量与原料需求，缺少换算依据时先核对；从同码物料的具体批次登记发料；生产按实际数量签收，数量不符保持核对状态；签收不再次扣仓库 |
| 生产退料（S11） | 关联已签收的原领料单和物料批次，登记申请数量、去向及依据；仓管核对实收；数量差异可退回核对后重新提交；接收到指定状态库存，按实际接收扣减线边；不自动新增报废数量 |
| 盘点复核（S12） | 选择批次及库存状态，保留账面数量和版本快照；实盘数量、差异原因及依据；草稿修改、提交复核、退回修改、复核通过；只有通过后产生一次库存调整 |
| 通用交互 | 每页签保留搜索和状态筛选、八条分页、选中上下文；操作区在详情右侧；数量精度和范围校验；保存前核对；防重复提交；切换/导航/刷新草稿保护；保存失败保留并重试；只读、空态、读取失败和重置演示 |

表单覆盖 `issue`、`sign`、`return_create`、`return_receive`、`return_discrepancy`、`return_resubmit`、`count_create`、`count_edit`、`count_submit`、`count_approve`、`count_reject` 共 11 类动作。经办人、物料、批次、仓库与库位均为演示上下文；文字依据或关联单号不代表附件已上传或正式单据已校验。

## 数据与接口边界

- 页面、模型和动作表单分文件管理。模型只操作独立内存状态，保留实体 ID、状态、版本及事件记录；不调用业务 API、ERP、浏览器持久化存储或真实消息服务。
- 不新增数据库表、迁移、正式业务接口、正式菜单、权限配置或真实业务记录。预览路由和页面懒加载仅在开发模式注册。
- 正式 `/inventory-management` 使用 T+ 按物料/仓库聚合的只读镜像，当前没有本批演示的完整批次、库位、状态库存和事务事件。演示数量不会回写正式库存、齐套、采购订单或生产报工。
- `orderProcessingApi.createStockOut` 与 `adjustInventory` 仍指向另一套旧 `OrderProcessingInventoryItem` 库存表，不能与当前 T+ 镜像混用。本批不复用这些写接口，也不把直接扣库、覆盖数量包装成正式发料或盘点审核。
- “可用 = 合格现存 − 已占用”仅表达本预览中的未占用库存；尚未实现计划专属可用、真实预占、跨计划分配或按期齐套预测。待检、不良隔离与冻结不并入合格可用。
- 生产退料与收货处置预览中的供应商退换安排是不同业务。本批退料关联原生产领料记录，不生成供应商退货、补货收货、质量异常或报废单。
- 页面内的操作、复核与数量限制用于评审交互，不能替代服务端授权、事务、并发、幂等及审计。正式人员职责、同人复核限制、状态释放、批次追溯和库存账务归属还需业务确认。
