# 电子阀门与 FactoryQc v0.5.1 上线联调

日期：2026-09-09。本轮已将当前正式默认配置接入后台，并与 Windows 客户端完成本地 HTTPS 联调。源码改动尚未推送或部署，不代表线上已生效。

## 公开配置下载

| 用途 | 无鉴权 HTTPS GET 地址 |
| --- | --- |
| 串口连接参数 | https://www.weoxymedical.com/api/factory-qc/serial |
| 读取协议目录 | https://www.weoxymedical.com/api/factory-qc/protocol |

200 响应直接返回 JSON 对象，不包含 code/data 外层。保持 no-store、不使用 ETag，不把条件请求变成304。管理接口仍需电子阀门页面权限，公开接口只返回已发布的契约字段，不包括草稿、操作员、工单或设备数据。

本轮只读访问线上这两个地址，HTTPS 可达，均返回404。后台代码部署后应按本说明检查200 JSON；未完成发布快照的保留域可能返回503。

## 首次默认初始化

启动生命周期在 Prisma 数据库连接完成后执行 initializeDefaults。使用现有 SystemSetting，不新增表或数据库迁移。

| 范围 | 仅在全空时生成 |
| --- | --- |
| 读取协议 | builtin-20260909-v3 完整目录、active、逐命令管理状态和不可变历史 |
| 连接参数 | serial-config-001 完整快照、12个连接项active和不可变历史 |
| 质检/人工/返工 | 不自动发布；继续保留未确认标准与既有草稿 |

连接默认值：autoConnect=true、portName=auto、115200、8位、无校验、1停止位、无流控、DTR=true、RTS=false、单条超时1500ms、扫描1000ms、重试5000ms。

协议默认值与 FactoryQc v0.5.0 的正式 JSON 完整相同。新版22项里20项启用，73未开发、78待修正固件，均停用；79使用大端int16整数℃；7D为有符号差值并保留字节序/单位待确认；83抹平值保存原始HEX；77为最多23条当前报警的数量+编号列表。旧7项固件目录保留。

两种配置分别使用事务和数据库 advisory lock。重启、多实例启动不会重复创建；失败回滚该域，下一次可重试。串口草稿保存、发布、回滚与初始化使用相同锁。

**已有内容不覆盖。** 协议域存在任何管理/草稿/历史记录，或串口域存在任意连接项、管理或历史记录，均保留整个对应域。两个域分别判断：保留协议不会阻止全空的串口初始化，反之亦然。未知损坏记录不自动修复。

如果已有旧串口草稿导致该域未初始化，需在“连接参数”核对并发布完整12项；不存在的项仍在页面提供已确认默认草稿参考值。已有协议可载入当前正式目录、检查并保存草稿后发布；不自动覆盖自定义枚举、阈值或固件匹配条件。任何已发布内容修改须使用新版本号，不能复用旧版本号改内容。

## 后台页面与后续编辑

“读取协议”主要模板与逐项建议改为当前v0.5.0正式目录；r5收于历史说明，v2参考保留。78停用，主界面不会建议直接启用旧错误固件。两个生产HTTPS地址均可复制，下载就绪状态仅依据已发布active。

首版仍支持完整草稿和逐命令草稿，首版须完整发布；已有正式目录后可逐命令独立保存、发布。单项发布汇入最新active并产生新完整版本，未发布草稿不进入客户端下载。

协议回滚恢复历史原JSON与原版本，保留独立草稿；串口回滚同步12项active并保留草稿。历史不可变，发布前仍执行结构、样例解码和来源检查。历史r4候选及r5审核模板不是本版正式配置。

## Windows 客户端

本轮客户端为0.5.1，协议schemaVersion仍为1，目录minAppVersion仍为0.4.0。旧解析引擎能读该格式；主检测联动与人工掉电比对至少需要0.5.0。

新工位没有本地配置时已预设两个生产地址。已有本地connection.json完整保留；升级后可在“查看连接 → 连接参数与后台配置”点“填入联调地址”，再“保存并应用连接参数”。该按钮只更新两地址并清空鉴权字段，其他参数保留。同步成功后查看实际配置版本；新协议在下次连接使用，当前连接冻结原目录。
