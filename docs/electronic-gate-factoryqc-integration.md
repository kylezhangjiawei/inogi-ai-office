# 电子阀门与 FactoryQc v0.6.14 上线联调

2026-09-14：新工位默认改为 auto / 9600，备用协议为本批同固件设备确认使用的 0910 版。后台配套源码已更新默认模板并补齐规则下载。本次尚未推送、部署或修改生产发布值。

## 公开配置下载

| 用途 | 无鉴权 HTTPS GET 地址 |
| --- | --- |
| 串口连接参数 | https://www.weoxymedical.com/api/factory-qc/serial |
| 读取协议目录 | https://www.weoxymedical.com/api/factory-qc/protocol |
| 已发布自动检测规则 | https://www.weoxymedical.com/api/factory-qc/rules |

成功响应直接返回 JSON 对象，没有 code/data 外层；使用 no-store、不返回 ETag，不将成功的条件请求变成 304。管理接口仍需要原有页面权限。

规则下载只包含已发布的 critical/routine 项，按标识排序生成稳定内容版本；未发布草稿不会改变下载内容或版本。响应不包含人工项、设备指令、操作员、发布人或设备记录。没有已发布项时返回 200 和空 items；客户端仍保留全部 23 项内置目录（其中旧开机大气压默认停用）。部分发布按项覆盖，显式停用也保留；无效已发布内容报错，客户端沿用最近有效规则。空目录可清除已撤回的覆盖，不能用错误响应替代。

## 默认配置及已有内容

全空协议域初始化为 builtin-20260910-v3（最低客户端 0.5.8），包含 0910 的 23 条查询和旧 7 条兼容查询。73 为 40 字节八槽参数，74 为 STATUS + TYPE，78/79 包含状态，87 为 16 字节 UID；当前协议默认模板和逐行建议使用同一目录。旧格式固件仍须使用原适配目录，不能只根据相同固件版本号判断回包格式。

全空串口域初始化为 serial-config-003：autoConnect=true、portName=auto、9600、8N1、无流控、DTR=true、RTS=false、查询超时 1500ms、扫描 1000ms、重试 5000ms。客户端自动选择唯一 USB 串口，无 USB 标记时只选择唯一串口；有多个候选等待选择，固定端口设置仍只连接指定端口。

启动只使用现有 SystemSetting 表，在事务及既有 advisory lock 内初始化全空域。任一域已有草稿、管理状态或历史就保留整个域，不因升级覆盖。无需新增表或数据库迁移；不自动发布任何质检、人工或设备指令项。

质检模板与当前客户端的功能标准对齐：压力使用 gear-range / gearRanges，包含上下限（1档120～175、2档135～205、3档140～240、4档160～270、5档180～285、6档及A档200～300、S档210～305kPa）；型号、市场和完整固件使用 present；FPGA 等于37。已有 gear-upper、固定范围、display、allowlist 仍可读取和编辑；发布新方式须清空冲突的旧字段。来源依据和原有适用范围填写要求仍保留；profile-slots、gear-upper 与 gear-range 可采用原有通用范围方式。

## 发布步骤

1. 发布本次后台 API 与管理前端代码。源码默认改变不会替换现有线上发布快照。
2. 在设备串口项选择“自动发现”，保存草稿并发布；核对公开串口响应为 auto / 9600。
3. 对已确认采用 0910 回包格式的工位，载入并检查当前 0910 协议模板，保存草稿后以新版本发布。旧格式工位不得共享该新版配置。
4. 按当前批准标准核对需要覆盖客户端的质检规则，填写原有必需的适用范围和依据，保存并发布。只保存草稿不影响客户端；未发布项继续用内置默认。
5. 检查三个公开地址返回 200 完整 JSON，客户端立即同步后核对生效参数、协议和规则版本。协议更新用于下一连接，规则更新用于下一次检测。
6. 在新电脑实际接入相同设备，核对 Windows 分配的端口及读取结果。客户端更新保留本机 connection.json 和来源匹配的有效缓存；已有固定端口不会自动改成 auto。

本次修改前线上只读核对为串口 serial-3 / COM3、协议 builtin-20260909-v3、规则 404。后台更新前可清空客户端连接和协议两个后台地址，保存 auto / 9600 与 0910 备用协议供本机使用。配置下载成功不能代替结果上传、真实设备读取或整机质检验证。

- apps/api/test/factory-qc.defaults.spec.ts：当前默认契约、旧内容保留、初始化事务和回滚。
- apps/api/test/factory-qc.rules.spec.ts 与 electronic-gate.service.spec.ts：公开规则边界、草稿隔离、发布校验及新旧规则兼容。
- scripts/electronic-gate-preview：隔离管理页面，验证默认模板、逐行回填和保存发布分离。
- scripts/factory-qc-integration-fixture.cjs：真实 Nest 控制器/服务与 .NET 客户端进行本机 HTTPS 联调，覆盖三类配置下载、发布更新、缓存恢复及错误响应。只绑定 127.0.0.1，使用内存存储，不读取 .env 或真实数据库，10 分钟自动关闭；测试证书不安装到系统。
- 客户端 scripts/test.ps1 -NoRestore 运行离线回归；显式指定 BackendFixtureDirectory 时附加 HTTPS 与实际页面规则合并验证，参数见该脚本。

以上隔离验证不能代替真实 PostgreSQL 持久化、生产部署或另一台电脑的实际 USB / 串口驱动验收。
