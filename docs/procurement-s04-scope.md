## 第三批已完成：缺料导出与人工可用日期

用户明确选择“按订单行人工确认可用日期”，适应不同物料的检验时长。该日期是预计检验或处置完成后的可用日，与 ERP 预计到货日分开展示，不自动增加库存，也不替代检验结论。

1. 齐套明细右上方增加“导出缺料清单”。导出当前型号已加载的全部缺料及待核实物料，不受搜索、筛选和分页影响。文件含“当前缺料”“待核实物料”“核算说明”，保留当前缺口和全部在途到齐后缺口、目标套数、仓库范围及数据时间。未知数量显示“—”，真实零值保留 0；独立包材参考表未混入装配需求。
2. 采购订单详情新增行级预计到货、预计检验后可用、确认人、确认时间、备注及需重确认提示。商品明细独占内容区全宽，右侧固定操作，下方再分栏展示其他信息。窄屏保留局部横滚和可见提示；采购订单列表及单段详情通过原页面权限后可在手机访问。
3. 首次日期保持空白，由经办人确认；不能早于已知的本行预计到货日。清空日期必须填写原因，保留确认记录和版本。保存中防重复提交；409 冲突后需重新载入来源，填写中的日期及备注继续保留。
4. 新权限 `proc-purchase-order:confirm-availability` 与 `page:purchase-order-detail` 同时满足才可写入；普通角色未自动授予。无动作权限的用户仍可按原页面权限查看记录。
5. 新表 `ProcPurchaseOrderAvailability` 保存本地确认，与 ERP 镜像独立。来源指纹检查 ERP 内部单据 ID、物料、规格、单位、数量、到货日、供应商及状态；仅同步时间更新不要求重确认，实质来源变化或 ERP 同号重建会提示重确认。来源版本与确认版本同时校验，行锁、写入和审计在同一事务中完成。

增量迁移 `20260910090000_add_purchase_order_availability` 已在本机开发数据库应用；执行前确认仅此迁移待执行。未保存真实订单可用日期，未改真实库存、BOM 或备货计划。数据库写入测试使用随机隔离 schema，模拟数据在测试后清理。
