# MateChat 文件检索与资料包

本功能把“查找原始资料 → 选择文件 → 后台打包 → 校验权限后下载”接入 MateChat ReAct，并提供不依赖模型判断的“查找并打包”界面。代码和迁移已准备；部署前仍须执行数据库迁移、确认 OSS 和临时磁盘容量。

## 使用方式

可直接在开启 ReAct 的 MateChat 会话中输入：

- “把研发项目 A 下面所有子任务的图片整理成 ZIP，按任务分文件夹。”
- “找出 2026-09-01 到 2026-09-07 的项目附件，只保留 PDF 和 Excel，打包给我。”
- “把我生成的包装设计图片找出来，先展示清单，暂时不要打包。”
- “将刚才两次找到的文件合并成一个资料包，命名为‘产品 A 交付资料’。”

资料包卡片可查看进度、取消、重试、读取失败清单及下载。关闭聊天不影响后台任务；重新打开相同会话可恢复任务与最近的有效检索结果。手工界面可选择具体文件，或打包全部结果（包括尚未加载的文件）。

### 支持范围

| 来源 | 实际范围与权限 |
| --- | --- |
| 项目任务附件 | 研发、中美协同、生产工作区的任务留痕附件；包含子任务，沿用工作区、任务及留痕可见性 |
| 知识库文件 | 研发与已配置部门知识库的文件；沿用部门入口权限及适用的分值限制 |
| 图片作品 | 当前用户的图片作品；有 OSS 时直接取原件，否则支持已有内嵌图片 |
| 视频作品 | 当前用户已生成成功、具有存储原件的视频 |
| 聊天附件 | 当前用户会话中、归该用户上传/生成且仍有效的文件；排除跨业务历史引用 |

按项目/任务/工作区筛选仅适用于任务附件。需要其他来源时分开检索，然后合并快照。关键词匹配文件名和已有描述，不等于图片视觉识别、OCR 或文件内容全文搜索。未经接入的采购等业务附件、任意本机路径和外部网址不在范围内；采购部门知识库属于已接入知识库。

## ReAct 与接口

- `search_project_files`：生成完整检索快照，向模型提供前 30 条预览、总数、限制与警告；不返回对象存储键或下载签名。
- `inspect_file_selection`：每页最多 100 条，仅在精确挑选时需要；全部打包不必逐页读取。
- `create_file_archive`：以有效快照创建后台任务；可合并最多 20 次检索并指定文件子集。工具描述明确要求用户已表达打包意图，排队不能说成已完成。

文件名/描述等资料内容属于不可信数据，不应被模型当成工具调用指令。后台执行只接受真实快照引用，不接受任意 URL 或路径；归档操作不发送邮件、不分享给其他人，也不修改原件。

REST 接口均继承应用鉴权，并在服务层校验当前用户与会话归属：

| 方法 | 路径（前缀 `/api/chat`） | 用途 |
| --- | --- | --- |
| POST | `/files/search` | 检索；请求含 `conversationId` 和筛选条件 |
| GET | `/file-selections/:id?conversationId=…&offset=…` | 快照分页 |
| GET | `/conversations/:id/file-selections` | 最近 5 个有效快照 |
| POST | `/archives` | 创建；请求含 `conversationId`、`selection_ids`，可选 `file_ids`、`filename`、`grouping` |
| GET | `/conversations/:id/archives` | 最近 50 个任务 |
| GET | `/archives/:id?offset=…` | 任务信息与结果清单分页 |
| POST | `/archives/:id/cancel`、`/retry`、`/download` | 取消、重试、校验后签发下载链接 |

## 容量与配置

“高容量”不等于无限制。以下环境变量在 API 进程读取，非法值回退默认值，超过硬上限则限幅。单位 MB 均按 MiB（1024² 字节）计算。

| 环境变量 | 默认 | 硬上限 | 含义 |
| --- | ---: | ---: | --- |
| `CHAT_ARCHIVE_MAX_FILES` | 2000 | 10000 | 每包源文件数 |
| `CHAT_ARCHIVE_MAX_MB` | 1900 | 1900 | 每包原始文件总量 |
| `CHAT_ARCHIVE_MAX_FILE_MB` | 512 | 1900 | 单文件大小 |
| `CHAT_ARCHIVE_CONCURRENCY` | 2 | 4 | 同一数据库全局执行并发 |
| `CHAT_ARCHIVE_USER_CONCURRENCY` | 3 | 10 | 每用户排队与执行中任务总数 |
| `CHAT_ARCHIVE_TIMEOUT_MINUTES` | 30 | 120 | 一次执行最长分钟数 |
| `CHAT_ARCHIVE_RETENTION_HOURS` | 24 | 168 | 从任务创建起算的有效小时数 |

总量硬上限保留在 ZIP32 安全边界内。超过范围需按项目、日期或类型拆包；本版不自动分卷，不提供 ZIP64 超大归档。检索命中超过配置文件数时只展示预览和明确警告，不生成可执行快照；扫描资料超过 50,000 条会要求缩小范围，不静默截断。

原件通过流式读取写入临时磁盘，再流式生成 ZIP 和分片上传，不把整个资料包读入内存。保留原始字节，ZIP 使用 STORE，不保证体积比原件更小；特别是图片/视频通常已压缩。已知大小在排队前检查，未知大小在实际读取时计数。相同 SHA256 内容只保存一份，清单保留各来源；重名文件自动编号。

默认 2 并发下，建议为 API 临时目录预留至少约 **10 GiB** 可用空间（原件 + ZIP + 余量）；若调到 4 并发，按至少约 20 GiB 规划。需要独立留意现有研发 JSON/内嵌 base64 数据源的内存开销：流式归档并不消除上游列表读取开销。更高文件数/并发须在目标环境压测后启用，不建议未经容量确认就把所有配置调到硬上限。

## 一致性、权限与清理

- 检索快照保存 1 小时，仅所属用户、会话可用；快照不含原文件字节、对象存储键或签名。
- 执行时重新读取账号状态和权限，并根据来源元数据版本验证引用。源文件变更或无权访问会记入失败清单；全部失败不会发布空的“成功包”。
- 下载时再次核验包内所有成功/去重来源的当前权限和元数据版本，再签发 **60 秒**有效链接，绑定中文下载文件名。已签发链接在短暂有效期内仍可使用，已下载的本地副本无法远程撤回。
- 元数据版本检查不等同于对象存储版本锁定；若绕过业务系统直接覆盖同一个 OSS 对象键且不更新来源元数据，本版不能在下载时检测该情况。
- 相同请求幂等；数据库事务锁限制并发，90 秒租约与 15 秒续租支持多实例接管；旧执行者不能覆盖新执行结果。自动接管多次中断后显示失败，可手动重试。
- 取消由数据库状态与执行者中止信号共同处理。其他实例通常在下次续租看到取消；正在进行的存储请求还可能等待请求超时或上传进度回调。
- 部分失败仍可下载成功文件；ZIP 内附 `文件清单.csv` 和 `打包说明.txt`。重试使用原快照，源文件已改变时应重新检索。
- 正常结束删除本次临时目录。每分钟回收过期资料包、快照及已登记的历史上传对象；清理失败保留记录下轮重试。
- 异常退出后，只回收超过 10 分钟、属于当前系统用户且能在当前数据库确认任务归属、没有对应有效执行租约的临时目录；不扫描删除其他应用目录。数据库不可用时不清理。
- 正常上传失败会尝试中止未完成分片。强制杀进程/主机故障仍可能留下 OSS 未完成分片，需配置 OSS 生命周期中止未完成分片（例如 1 天）。可对专用归档前缀加大于最长任务有效期、留有余量的对象生命周期，作为极端迟到上传的兜底；不要影响其他业务前缀。

## 发布步骤与需要确认的条件

1. 确定目标环境，按项目正常发布流程备份并审核迁移。此次功能新增两张独立表，不需要修改原业务数据。
2. 在启动新版 API 之前，从 API 目录执行 `pnpm exec prisma migrate deploy`，应用 `20260907093000_chat_file_archives`；构建前执行 `pnpm exec prisma generate`。本次开发验证没有迁移业务数据库。
3. 确认现有 OSS 已配置：原文件可读，业务前缀 `chat-archives` 下支持分片上传、完成/中止上传及删除；公网签名 URL 可由浏览器访问。不要将 bucket 改为公开。
4. 确认临时磁盘、配额、存储生命周期与日志保留策略；先使用默认并发。无需新增 npm 依赖或独立消息队列。
5. 发布 API 与前端后，用测试账号真实走一次“有权限文件检索 → 打包 → 下载 → 取消/重试”，再用无权限账号核验。真实模型调用与目标 OSS 联调需要已配置的目标环境；离线/合成测试不能替代这一步。

如迁移未完成就启动新版，归档队列会报告缺少表，资料包接口不可用。回滚应用时可以保留两张新表以便恢复，不要随意删除未过期任务。容量、上线环境和迁移执行需要维护者确认，不需要扩容聊天上下文。

## 开发验证

从 API 目录运行专项测试：

```sh
TS_NODE_TRANSPILE_ONLY=1 node --test --test-reporter=spec -r ts-node/register -r tsconfig-paths/register test/chat-archives.spec.ts
pnpm exec tsc --noEmit
```

`chat-archives.postgres.spec.ts` 默认跳过，只有显式配置 `CHAT_ARCHIVE_TEST_DATABASE_URL` 才执行。它只接受 `/private/tmp/matechat-archive-db-…` 下独立 PostgreSQL 的本地 Unix socket，随机建测试 schema 并在结束后删除；不能传业务 `DATABASE_URL`。覆盖真实迁移、并发幂等、跨实例抢占、租约恢复和事务回滚释放锁。

从项目根目录运行独立界面验收：

```sh
node scripts/matechat-archives-preview.mjs
```

浏览 `http://127.0.0.1:5176/`。该环境仅使用 42 个合成文件、内存任务和本地合成 ZIP，没有业务 API 代理、不读取项目环境凭据、不连接数据库；只用于界面与交互验收，不代表真实文件检索或模型行为。停止脚本后合成任务状态即清空。桌面和手机尺寸可检查全量/已选打包、取消、重试、页面刷新恢复、中文长文件名与实际下载触发。
