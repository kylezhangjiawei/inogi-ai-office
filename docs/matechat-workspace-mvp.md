# MateChat 研发任务上下文与结项资料检查

本次实现研发任务单对象上下文与可保存的结项资料检查。它是 MateChat V2 的首个业务场景，不包含今日作战台、跨任务批量行动计划或采购写操作。

## 使用流程

1. 在研发任务详情点击「问 MateChat」。聊天输入区显示经服务端核验的关联任务，发送问题时重新读取任务状态、负责人、日期及最近进展。
2. 点击「分析下一步」先填入问题；用户自行发送。切换到另一任务时提示切换关联，已发出的请求保持原对象。任务引用、草稿和待发附件按会话隔离。
3. 点击「检查结项资料」，或在聊天底部打开同名面板，输入研发任务编号后开始检查。自然语言明确要求检查结项资料时，也可由工具生成检查记录。
4. 清单默认包含需求规格、设计图纸、BOM、测试验证、说明交接和验收记录。它是可编辑的参考清单，不是公司正式交付标准。可修改名称、检索词和必需标记，新增或删除项目。
5. 匹配项显示「待核对」。查看原件、勾选文件并点击「确认所选资料」后，才计入已确认项。也可以明确标记不适用，或恢复核对。
6. 未找到资料的项目可「准备补充任务」，将关联编号和资料要求填入聊天草稿。发送后复用现有任务确认卡；真实创建仍需用户确认，负责人和截止日期不自行猜测。
7. 「打包已确认资料」将已核对证据交给现有后台资料包队列。可以只打包已确认部分；未解决必需项始终明确显示。进度和下载沿用 MateChat 资料包区域。

## 范围与判断口径

- 首版只支持研发工作区的一条任务及其子任务。采购、中美协同和生产任务不在这个入口范围内。
- 只检查当前用户有权查看的任务附件，按文件名及已有描述寻找候选。多个检索词按任一命中匹配；不执行正文全文检索、OCR、视觉识别或正式版本审批。
- 「未找到」表示当前可见附件没有匹配项，不表示其他位置不存在资料。「已确认」表示用户确认了选定文件，不代表系统完成合规审查或正式验收。
- 每份清单最多 20 项，每项最多 10 个检索词；最多展示 20 个候选并显示实际候选总数，最多确认 10 个证据文件。候选过多时可细化关键词。
- 原件版本依据现有文件目录的元数据指纹。绕过业务系统直接覆盖 OSS 同名对象且不更新元数据的情况，沿用现有归档功能的限制。

## 保存、更新和权限

- `ChatMessage.pageContext` 仅保存引用。上下文和用户消息在同一事务中保存；发送重试复用原绑定，重新回答使用原用户消息的引用。
- 模型收到服务端最新白名单数据。页面标题、备注和描述作为业务数据处理，不作为工具指令。旧页面答案、摘要及工具记忆不会被重新当作最新业务事实。
- 历史消息读取会重新核验关联资源；任一关联任务不可读取时，隐藏该会话的历史正文、附件和工具输出。上下文会话列表使用通用标题以免标题泄露任务信息。
- 首版暂不支持站内分享含页面上下文的回答。分享接口从已保存消息取正文并在服务端阻止此类分享，普通无上下文回答保留分享能力。
- `ChatDeliveryCheck` 保存所属用户、会话、任务及清单。每次读取、核对、预览、重新检查和打包都核验当前账号及资源权限。
- 文件改变、移出范围或不可访问后撤回对应确认；文件来源读取失败不会生成「没有缺项」结论。并发变更返回冲突，界面重载最新记录并要求重新核对，不自动重放确认。
- 文件预览链接短时有效；打包和下载沿用现有归档服务的权限、版本、配额和逐项失败处理。

## 发布

目标环境发布前按项目流程备份数据库、应用迁移，再启动新 API：

```sh
cd apps/api
pnpm exec prisma migrate deploy
pnpm exec prisma generate
pnpm run build
```

新增迁移：

- `20260908120000_chat_page_context`：为消息增加可空的引用字段。
- `20260908160000_chat_delivery_checks`：保存用户核对的资料清单。

资料检查依赖当前文件归档代码及其 `20260907093000_chat_file_archives` 迁移。真实打包、预览和下载仍要求现有 OSS 配置可用。不要在未迁移时启动新 API；回滚应用时可保留新增字段和表。

2026-09-08 已完成本地数据库完整备份，并把备份恢复到独立 PostgreSQL 中演练迁移。演练成功且旧用户、会话、消息数量保持一致后，已为本机数据库应用全部 5 项待执行迁移：除上述三项外，还包括此前的 `20260902120000_add_chat_message_client_id` 和 `20260902210000_add_ai_gateway_route_source`。生产环境尚未发布，不能将本地迁移状态视为生产状态。


脚本启动仅能通过临时 Unix socket 连接的独立数据库，应用真实增量迁移，结束后停止并删除测试库；不读取应用 `.env` 或连接业务 `DATABASE_URL`。可通过 `CHAT_TEST_PG_BIN` 指定 PostgreSQL 工具目录。已通过 9 项检查、无跳过，覆盖旧消息保留、JSONB 读取稳定性、多连接并发确认和打包、证据失效、权限变更及页面绑定事务。常规 API 测试会跳过未提供隔离连接的 PostgreSQL 用例，不能用该跳过结果替代此脚本。

本地真实模型连接已使用一条合成提示验证，默认对话模型成功返回回复；未向模型发送业务任务或文件内容。此连接检查与上述 HTTP、持久化验证分别进行，不等同于用真实账号完成整段业务对话验收。

真实 OSS 联调使用 194 字节合成 ZIP，验证上传、原件读取、60 秒签名下载、中文下载文件名及下载字节一致性，测试对象已删除。联调发现当前存储桶拒绝下载链接中的 `response-content-type` 覆盖，返回 HTTP 400 `InvalidRequest`；下载签名已移除此冗余覆盖，继承上传时的 `application/zip`，同场景重测返回 HTTP 200，并保留 `private, no-store`。归档、HTTP、CDN 相关 35 项回归及 API 类型检查均已通过。
