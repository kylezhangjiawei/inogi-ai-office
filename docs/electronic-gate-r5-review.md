# FactoryQc r5 与当前电子闸门实现的差异审阅

审阅日期：2026-09-09。范围为 r2、r5 资料包及当前后台和页面代码。本轮只做文件对比与内存校验，不修改业务配置、示例版本、运行中的服务或客户端。

结论：需要调整协议配置草稿、部分页面说明和 V 压负数校验；不需要重做页面结构或两个下载接口。r5 提供的是新增研发结论，包内 JSON 没有全部同步这些结论。

## 必要调整

| 项目 | 当前实现 | r5 结论及应调整内容 |
| --- | --- | --- |
| 7D / V 压 | 协议示例为 `uint`；检测规则 `v-pressure` 的前后端校验禁止负数 | 改用有符号 `int` 的新协议草稿。检测规则须按字段允许负值，不能仍用“非温度就不能负数”的通用限制。字节序、单位、换算及真实负值完整帧仍待核对，不填猜测单位或合格阈值。 |
| 77 / 报警 | v2 示例最大数量 64、最大载荷 65，名称为报警记录 | 面向本次确认的固件，新草稿使用当前活动报警、`maxCount:23`、`payloadLength:24`，更新 0/4/23 条样例。引擎的通用容量 64 不必改；不把零报警当作传感器有效或整机合格。 |
| 78 / 压力 | v2 为两字节 HEX，期待返回码 78 | 已明确目标是大端 uint16、整数 kPa，不缩放。该解析可以用现有字段表达，但正式采用须先确认固件已修复及准确匹配条件。 |
| 79 / 内部温度 | v2 为两字节 HEX | 新草稿可用大端 int16、整数 ℃，包含正负温度样例；不再次除以 10。读数有效性仍未由该返回值解决。 |
| 7A / 风扇 | 示例名称“风扇输出” | 改为“风扇实际反馈比例”，不是控制目标或 RPM；约 0～100 不等于批准的质检范围。 |
| 7C / 重启 | 示例名称“重启次数” | 改为“压缩机异常自动重启次数”；复位和掉电规则仍待确认。 |
| 83 / 84 | 230 后两字节笼统叫“数值”；状态显示 0/1 | 83 后两字节标为“230 抹平值”。状态可以注明已确认的未完成/已完成含义；不据此推断抹平值单位、完整有效性或持久性。 |
| 7F / 80 / 86 | 仍有“持久回读来源待确认”“读取字段待确认”等说明 | 7F、80 已明确直接读 EEPROM；86 读 RAM 当前档位。把未确定项缩小为音量合法等级和完整验证流程等。出厂目标仍可为 3，但单次 86=3 不能证明掉电保存成功。 |
| 73 / 参数组 | 停用原因仍是字段布局待确认；质检模板看起来可以直接回读参数组 | 保持协议停用，说明改为当前固件预留、未开发、无有效回包。质检模板注明当前客户端无法通过 73 完成该项。 |

## 可以保持的部分

- `GET /api/factory-qc/serial`、`GET /api/factory-qc/protocol`；无鉴权 HTTPS、成功直接返回 JSON、无 code/data 包装的约定不变。
- `schemaVersion:1`、应用 v0.4.1、最低应用版本 0.4.0，以及 12 项串口字段不变。
- 独立草稿、单项发布、完整快照、原版本回滚及权限保护可继续使用。
- 当前协议校验器已经支持 int/uint、字节序、线性换算、枚举、报警计数列表和完整帧样例，不需为上述已确认普通字段重写解析能力。
- 当前新协议的 76 已按分钟换算小时；旧三字节协议保持原样，不能将新版本结论套用于旧固件。
- 超时、扫描和重试参数保持当前配置。文档里的 100～300 毫秒、重试 1～2 次是建议，不是对现有串口参数的强制变更。
- 页面框架、系统视觉样式以及单一顶部标题均无需重做。

## 正式下发前仍需解决的边界

1. 研发反馈指出旧 78 仍只返回低 8 位，且返回码误为 85。丢失的高位不能通过配置还原；85 又是现有大气压命令，不能靠改 responseCode 为 85 兼容。需要修复后的真实固件版本和 72/78 完整应答。
2. 历史候选仍用 `V4.0UA81` 主版本前缀。当前客户端不使用 `sub` 子版本作为匹配条件；若修正版只改变子版本，需要客户端识别能力及后台契约共同扩展，新建 version 本身不能解决固件区分。
3. 78/79 没有可靠的有效性与数据更新信息。范围正常或零报警不能证明数据有效；状态、读数、新鲜度联合判断须等待协议定义和客户端逻辑，不能自行向 schema 1 塞入新字段。
4. 掉电回读、独立开机基线、完整风扇测试及质检放行仍是客户端流程。85 当前大气压不能直接当作独立开机基线。

## 实际验证结果

- 当前示例与 r2/r5 正式示例一致。
- r5 所附 `candidate-20260909-v3` 可以通过当前后台纯校验器，34 个完整样例的解码结果和 expected 一致，无自动质检判定规则。
- 该候选仍是 r4 历史候选，没有吸收 Word 的 7D/7A/7C/83 等修正；校验通过不等于完整适配 r5，更不等于可以正式发布。
- 已实际复现 `v-pressure.minimum=-5` 被前端拒绝，错误为“不能填写负数”；后端存在同样的非温度负数限制。
- 已验证同载荷长度、同固件前缀的两个 profile 会被现有校验器拒绝；不能简单追加一个同前缀 profile 区分旧版和修正版。
- 没有执行包内引用的 DLL、访问生产接口、连接数据库或设备，也没有发布候选。

建议实施顺序：先修 V 压字段负数校验和过时说明，保留原 v2 历史；再整理吸收 r5 的新草稿及样例；固件修正和适用范围确认后才正式发布。需客户端扩展的有效性、子版本识别、掉电与开机基线流程单独安排。
