# P04 生产问题转研发前端范围

2026-09-14。独立 DEV 预览入口 `/__preview/production-rd`，组件 `ProductionRdPreviewPage`。参考 V1.1 开发说明第 509–520 行及 `高保真页面/生产/P04_生产问题转研发.png`，沿用 Horizon 蓝白视觉与问题列表、处理人交接、技术意见、现场验证的结构。

## 已实现

- 复用 P08 原异常的编号、来源、批次、工序、物料、数量、处理人及期限；从 P08 的研发协同记录跳转时携带同一 `issueId`。独立进入时展示已有待指定研发的过程不良样例，明确指定处理人才建立协同，不在页面加载时自动转交。
- 质量管理岗指定研发处理人及截止；研发处理人请求补充资料或提交技术意见；发起方/质量管理岗补充资料。保留发起人、当前处理人及历史记录。
- 技术意见记录分析、依据、是否更新图纸/SOP，需更新时要求引用依据；页面不自动更新受控文件。
- 最新意见绑定现场验证人和计划日期；仅指定验证人登记实际日期、结果及证据。验证不通过返回研发，须提交新意见才能再次安排验证。
- 最新意见有对应验证通过依据后，由发起方或质量管理岗关闭技术协同。关闭后只读。
- 人员范围、状态、关键词筛选；保存失败保留填写和重试；空态、只读、读取失败恢复；切换人员/异常/分类及跨路由、刷新时保护未保存内容。

## 共享与业务边界

`defects/defectPreviewSession.ts` 为浏览器模块内存会话，P08/P04 路由间保留同一原异常对象链。P04 技术状态独立按原 `issueId` 和已有研发协同 ID 关联，不含另一份不良数量。页面刷新清空；任一页面重置时同时恢复 P08 原异常与 P04 技术记录。不使用 API、localStorage、sessionStorage 或数据库。

技术意见、补充资料、验证和技术关闭均不修改 P08 的原数量、整改、QC 回执或原不良关闭状态。技术验证通过不生成 QC 合格量，不回填初检合格率，不产生 QA 放行、库存或出货。原异常仍有待交接/待复验数量时，沿用 P08 校验阻止改向研发。

当前人员为演示岗位候选，资料为明确标记的样例摘要；尚未接入正式员工表、真实权限、附件原件、跨设备会话、正式研发接单、通知与业务验收。已有技术协同关闭后的再次开启、正式受控图纸/SOP 变更、P03/P09 及库存的真实联动属于后续业务接通阶段。
