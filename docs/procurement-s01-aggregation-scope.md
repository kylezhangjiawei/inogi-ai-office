# S01 采购工作台业务聚合收尾

2026-09-14。继续“先补页面和交互”，在现有 `/proc-my-workspace` 上汇总可读取的原业务来源。沿用 Horizon 样式、本人账号归属、原权限及原任务操作；不新增任务总账，不执行真实采购写入。

## 已确认缺口

- 原工作台已有本人采购任务和订单到货安排，但没有把样品、相关备货列为可发现的业务来源。
- 跨月未完成与日期待确认的数量来自包含状态、关键词的筛选结果，容易被零结果搜索隐藏。
- 备货计划接口只有创建人和关联采购任务，没有“采购经办人”字段；不能直接把创建人当作经办人。
- 采购任务接口提供的订单未收数、预计到货日，仍不能替代未验收量、检验后可用日或确定齐套缺口。

## 本批行为

| 来源 | 原数据与口径 | 查看入口 |
| --- | --- | --- |
| 普通采购 | 本人未完采购任务，排除有样品要求或样品记录的任务 | 选中原任务，复用右侧详情和原处理器 |
| 样品采购 | 同一采购任务的互斥分类；包含历史样品记录，不能当作当前待测试数量 | 原采购任务；有权限时进入样品协同 |
| 相关备货 | 关联本人采购任务，或由本人账号创建的计划；创建关系单独标注 | 原备货计划，精确展开和聚焦 |
| 待到货 | 原订单行未收数量与预计到货日；数据冲突保留待核对 | 对应采购任务，使用已有订单及到货操作 |

四项分别计量任务、计划和订单行，不相加为统一任务总数。样品不新建记录，重复任务 ID 只保留最新快照；不同任务不按物料名称合并。订单行沿用 ERP 内部 ID、单号与行号去重，保留全部关联来源。多供应商任务按订单行筛供应商；作废、取消、终止订单不计入待到货。

相关备货使用全部本人任务 ID（含已完成任务）判断关联。计划“下单达标”但尚未收齐、待检验，仍保留跟进；下单与合格均完成且无数据问题才退出该待办投影。计划独有的产品和供应商会加入主筛选，避免没有普通任务时无法选到计划范围。

## 月份、失败与权限

- 采购按需求日期、备货按目标日期、订单行按预计到货日归月，不互相借用日期。非法或缺失日期单列待确认。
- 当前来源分别显示所选月、跨月未完、日期待确认；未来月份可展开。跨月按早于所选月且未完定义。
- 聚合只服从本人、产品与供应商范围，状态和搜索不会隐藏跨月或无日期来源。原任务页签点击跨月或无日期时清除状态、搜索和快捷过滤，产品与供应商保留。
- 备货只在 `page:proc-cockpit` 权限下读取现有 `listProcStockPlans`，无权限显示未读取；不记为零。
- 成功快照保留读取时间。刷新失败显示错误、保留上次结果并禁用旧来源打开；重读成功恢复。首次读取失败显示未知。
- 相关计划依赖本人任务关系。采购来源未完整读取时，备货总数显示未知，已知记录与范围不完整提示并列。
- 账号或权限范围变化立即隐藏旧快照并取消旧请求；晚返回响应不能覆盖新范围。旧范围来源回调失效。

## 返回与数量边界

原任务选中仍写入现有地址参数，选中筛选外任务不擅自改变原筛选。业务来源使用 `source=sample/stock/arrival` 保存到工作台地址，切换来源保留任务、页码和筛选，跨页面返回恢复所选来源。跨页面导航继续携带受限的采购工作台返回地址。计划使用现有 `stockFocus` / `stockOpen` 精确定位，不新建计划、不带新建表单参数。

本月来源明细默认折叠，数量始终可见；跨月和无日期分组各先显示两行，可继续展开更多，桌面并列。主采购任务列表和原操作保持可发现。

本批不计算按期缺料、建议新增采购、整月生产完工或出货实绩，也不把未收量当成可用库存。备货接口未提供的经办归属、统一分配及真实跨模块验收仍是后续业务接通范围。
