# 应聘登记：使用与部署说明

应聘登记包含内部模板编辑、公开手机填写、版本历史和登记记录管理。内部入口为「人事与行政 → 应聘登记」(`/applicant-forms`)，公开链接为 `/apply/:slug`。

## 权限与入口

| 权限 | 能力 |
| --- | --- |
| `page:applicant-forms` | 打开管理页，查看模板、草稿和发布历史 |
| `applicant-form:edit` | 新建或复制模板、修改草稿、获取 AI 建议 |
| `applicant-form:publish` | 确认发布新版本 |
| `applicant-form:records` | 查询登记、查看原始资料与附件、维护状态和内部备注 |

为需要使用管理页的角色分配页面权限，再按职责分配操作权限。编辑、发布和处理登记可分别授权。权限目录增加默认项不等于给现有角色自动授权；发布后需在权限管理中核对目录及角色配置。现有 `*` 权限遵循系统通配规则。

应聘人员通过公开链接填写，无需内部账号。公开接口只提供加载表单、上传附件和提交资料，不提供查询他人登记或下载附件的入口。

## 创建、调整与发布

1. 在管理页「新建模板」，使用默认应聘字段，或通过「复制模板」以当前草稿创建独立模板。
2. 调整标题、说明、分组、字段类型、显示和必填设置。支持文本、长文本、电话、邮箱、数字、日期、单选、多选、确认框、重复记录和附件；重复记录支持一层子字段。显示条件根据同层其他字段的答案判断。
3. 使用右侧手机预览逐步试填。预览不会上传真实附件，也不会生成登记记录。
4. 点击「保存草稿」。只有草稿发生变化，正式填写链接仍使用上次发布内容。
5. 检查完成后点击「发布表单」并确认，生成新版本。复制正式链接发给应聘人员。

字段分为「应聘填写」「入职补填」「内部审核」。公开页面只接收可见的应聘填写字段；隐藏字段和其他阶段字段不会下发给公开页面。当前入职补填和内部审核阶段可配置模板字段，尚无对应的独立补填流程；内部跟进使用登记详情中的状态和备注。

模板草稿与审核备注都有修改版本校验。多人同时编辑发生冲突时，系统拒绝覆盖，并保留当前页面中的本地输入。先保留需要的内容，再读取最新版本；模板也可复制当前草稿为新模板。

## 正式链接与版本

每个模板的 `slug` 固定。再次发布沿用同一链接，新的访问获得最新发布版本；复制模板会产生另一个链接。

每次发布保存独立版本，后续修改草稿不改变已发布版本。已打开的填写会话固定使用打开时版本，可在 24 小时有效期内继续提交。服务端同时核对填写凭证、模板、版本和会话，不会把已填答案迁移到新版。历史登记详情始终使用提交时的表单结构展示。

当前没有撤回发布、删除版本或恢复旧版本的操作入口。需要调整正式内容时，修改草稿并再次发布。

## 手机填写与提交

公开页按字段分组逐步填写，提供进度、上一步、必填校验、条件显示和重复记录增删。小屏采用单列布局，底部操作区考虑手机安全区域。正式页面在提交成功后显示登记编号、表单版本和提交时间。

填写答案保存在当前页面内存，不写入浏览器持久存储。提交失败后可在当前页面重试；同次填写沿用提交标识，避免网络重试生成重复记录。刷新、关闭页面或重新打开链接会开始新的填写，未提交内容不会自动恢复。会话过期时需要重新打开链接。

## 登记表格与跟进

「登记记录」以表格展示应聘人员、电话、岗位、版本、提交时间和状态，支持分页、搜索、版本、状态和日期筛选。选择具体版本后，可按该版本的公开普通字段进一步筛选；重复记录和附件不提供字段筛选。日期筛选及登记时间统一使用北京时间（Asia/Shanghai），结束日期包含当天。

点击记录查看完整资料和附件。处理状态包括新登记、待审核、面试中、已录用、未录用和已归档。内部备注最多 5,000 字符；修改状态和备注不改变应聘人员原始答案。

「导出当前页」在浏览器生成 CSV，只包含当前已加载的一页登记，不是全部筛选结果，也不包含附件二进制或内部备注。重复记录转换为文字，文件不导出可直接访问的地址。CSV 对公式起始字符进行转义。当前没有在线修改候选人答案、删除登记或批量导出全部记录的接口。

## AI 建议及失败处理

在编辑区描述调整要求，例如「增加预计到岗日期，设为必填」。AI 接收当前模板结构和编辑要求，返回经服务端校验的建议结构与变更摘要。此过程不读取或发送已提交的候选人答案。

先查看建议效果，再明确点击「应用到草稿」；应用后可继续编辑或撤销，仍需保存并发布才影响正式链接。生成期间如果草稿发生变化，旧建议不会覆盖新的修改。

AI 使用已有的可用文本模型配置及 AI Gateway 路由。未配置模型、模型超时、调用失败或返回非法结构时，会显示错误，草稿保持原样；可继续手动编辑或稍后重试。无需为正常的手动编辑和填写流程启用 AI。

## 附件与日志边界

| 限制 | 当前值 |
| --- | --- |
| 照片字段 | JPG、PNG、WebP，单个不超过 5 MiB |
| 文档字段 | PDF、DOC、DOCX，单个不超过 10 MiB |
| 单次填写上传额度 | 最多 8 次文件额度，合计 25 MiB |
| 同一 IP 每日上传额度 | 100 MiB |
| 全部填写每日上传额度 | 1 GiB |
| 同一 IP 创建填写会话 | 每小时最多 30 次 |

每日额度按 UTC 日界线计算。上传前预留额度，替换文件及存储失败的尝试也计入额度，避免失败重试绕过限制。超过额度会返回明确提示。

服务端校验扩展名、MIME、文件头和实际字节数，排除 SVG、HTML 等类型；该校验不等于完整文档解析或恶意文件扫描。附件绑定具体填写会话和字段，提交时再次核对归属。尚未提交的会话不能通过记录下载接口读取附件。

附件经 API 上传到现有 OSS，显式设置对象 ACL 为 `private`、缓存策略为 `private, no-store`；上传从内网回退公网时保留相同设置。原有其他业务未传私有选项的调用保持既有缓存和 ACL 行为。授权人员从登记详情获取有效期 60 秒的签名下载地址，公开接口不返回 OSS 对象地址。

应聘登记的请求日志、审计和全局异常日志省略请求体、响应体、查询参数、文件信息及错误详情，并使用规范化路由。登记答案、`fillToken`、Base64 内容和签名地址不进入这些采集内容。反向代理、外部监控和 OSS 的日志配置仍属于部署环境验收范围。

当前没有遗留会话、未提交附件或历史登记的自动清理任务。数据保留和清理策略需要单独配置或实施，不应直接套用可能删除已提交附件的通用对象生命周期规则。

## 部署条件与顺序

本次 Prisma 迁移为 [`20260908200000_applicant_forms`](../apps/api/prisma/migrations/20260908200000_applicant_forms/migration.sql)，新增模板、版本、填写会话、提交记录和附件五张表及关联约束。需要 PostgreSQL；事务依赖行锁和 advisory lock。

部署前确认：

- 使用同一候选提交的前端、API、Prisma schema 和迁移。构建前生成匹配 schema 的 Prisma Client。
- 环境具备有效的数据库连接和 `JWT_SECRET`。填写凭证使用该密钥；轮换密钥会使现有填写凭证失效。
- 需要附件的模板具备可用 OSS 配置：沿用 `OSS_REGION`、`OSS_BUCKET`、访问凭据及端点配置。服务端需具备上传私有对象、签名读取和清理失败对象的权限。不要将凭据放到前端。
- 公网使用 HTTPS；前端服务器需支持 `/apply/:slug` 的 SPA 回退；`/api/public/applicant-forms` 路径需到达 API，不能被内部登录网关拦截。
- 附件使用 JSON Base64 传输。当前 API JSON 上限为 25 MB，反向代理的请求体上限需容纳编码后的 10 MiB 文件及 JSON 开销（约 14 MB）。
- 核对反代后的客户端 IP。通过 `TRUST_PROXY` 配置真实可信代理地址，默认不信任代理。本仓库同机 Nginx 部署设置 `TRUST_PROXY=loopback` 后重启；跨机代理配置明确的 IP/CIDR 列表。不要设置 `true`、跳数或全网网段。未配置时各候选人可能共用代理 IP 的会话和上传额度，需用实际链路验证客户端 IP。
- 禁止对包含填写凭证、登记答案和下载签名的 API 响应启用共享缓存；核对上游日志不采集上述内容。

在仓库根目录准备同一份候选构建：

```sh
pnpm install --frozen-lockfile
pnpm --dir apps/api exec prisma generate
pnpm typecheck
pnpm --dir apps/api exec tsc --noEmit --incremental false
pnpm build
pnpm --dir apps/api build
```

完成测试并备份目标数据库后，在受控部署环境执行生产迁移命令，再启用与之匹配的 API 和前端构建：

```sh
pnpm --dir apps/api exec prisma migrate deploy
```

生产不要使用 `prisma migrate dev`、数据库 reset 或演示数据 seed。迁移为增量新增表；应用回滚时保留已产生的登记和附件，另行核对旧版本应用兼容性，不通过删表回滚。

以下为可复现检查入口，不表示每次部署都已运行：

```sh
node --test scripts/applicant-form-state.test.mjs
cd apps/api
TS_NODE_TRANSPILE_ONLY=1 node --test -r ts-node/register -r tsconfig-paths/register test/applicant-forms.spec.ts test/applicant-form-log-redaction.spec.ts test/oss-private-upload.spec.ts

```

隔离 PostgreSQL runner 创建临时、仅 Unix socket 可访问的测试实例，不读取 `.env`，不连接生产数据库；需要本机 PostgreSQL 工具，可用 `APPLICANT_FORMS_TEST_PG_BIN` 指定工具目录。当前脚本临时目录使用 `/private/tmp`，直接运行环境为 macOS；其他系统需先提供对应路径或调整测试 runner。

本轮新增 OSS 私有上传的 4 项回归及既有 OSS/CDN 的 7 项测试已在内存客户端下通过（11/11），验证私有 ACL、缓存策略、端点回退、旧调用默认行为及失败返回。此结果不替代真实云端权限与缓存验收。

发布时用合成资料完成：无内部账号打开手机链接、必填和条件校验、附件上传、重复提交重试、管理表格与当前页导出、权限不足时拒绝读记录、私有附件不可匿名访问和签名下载。另验证发布 V2 后旧会话仍可提交 V1、历史详情保持 V1；验证 AI 失败时草稿保留。核对 API 健康、前后端版本、权限目录、迁移状态和日志省略策略后，再分享正式招聘链接。
