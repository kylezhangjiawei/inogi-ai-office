# S08／S14：采购订单行日期确认记录

2026-09-14。承接“先补页面和交互”的采购页面收尾。本批在真实采购订单详情的逐行操作区增加“日期确认记录”，复用现有只读审计接口。没有更改 ERP 订单、库存、采购任务或后端接口。

## 已实现

- 右侧抽屉按稳定镜像行 ID 查询该行的人工预计检验后可用日期确认记录，不按 SKU、供应商或展示行号匹配。
- 并列区分供应商原承诺日（当前来源未提供）、ERP 当前预计到货、人工预计检验后可用日期。人工确认展示版本、确认人、时间和需重确认状态。
- 历史逐条展示操作人、时间、可用日期／确认说明／确认版本的真实变更前后值。没有返回的字段显示“未记录”，明确的空值显示“未设置日期”或“无说明”。首条确认不作为供应商原承诺。
- 每页 10 条，第一页获取服务端截止时间，后续翻页沿用同一 `snapshotAt` 和筛选指纹；刷新从第一页读取新快照。页码随成功响应更新，读取或格式验证失败保留上次成功页，并可重试原请求。
- 桌面展示前后两列，手机使用可换行卡片；关闭恢复触发按钮焦点，“返回原订单行”保留来源状态和原查询条件，准确定位、聚焦原行。

## 读取与权限

复用 `fetchAuditLogPage`：`GET /api/audit/logs`，传入 `module=procurement`、`actions=purchase-order.availability-confirmed`、`resource=proc-purchase-order-availability`、`resourceId=镜像行 ID`。审计数据来自现有日期确认服务事务写入的 `availableDate`、`note`、`version`、`sourceFingerprint` 前后值；不展示内部指纹文本。

需同时具备 `page:purchase-order-detail` 和 `page:audit-log`。没有操作留痕查看权限时，抽屉说明权限要求且不发请求，原订单明细保持可用。仍由服务端决定当前账号的实际可见范围；统一审计返回的 `canViewAll` 不是采购全量权限的保证，因此界面始终提示“可能不是该订单行的全部历史”。

订单、行、订单来源版本、确认版本、账号、姓名或权限变化使旧结果立即失效；晚到响应不回填其他范围。校验响应的模块、动作、资源类型、精确行 ID、日期、分页及重复字段，关联不符不替换已成功读取的结果。失败状态与“当前可见范围内暂无记录”区分。

## 验证

- `scripts/purchase-order-history.test.mjs`：14 项模型及实际抽屉行为检查，覆盖权限零请求、首条／撤销／缺失字段语义、错行响应、异常响应、分页快照、首次错误恢复、第 2 页刷新失败保留、账号／姓名／权限范围变化及晚到响应。
- `scripts/purchase-order-line-navigation.test.mjs` 新增 2 项真实订单页与 React Router 导航检查：原镜像行返回、查询和来源状态保留、行焦点、关闭按钮焦点及权限／订单切换。
- 与既有日期确认和订单导航合计 56 项检查通过；前端类型检查通过。浏览器验收由本轮总体验收记录补充。

## 尚未接通

供应商原承诺与历次 ERP 交期变更没有可用的历史查询来源，本批没有推算或伪造。日期确认记录也不等于按日期可用数量：收货、检验、剩余义务和受影响齐套重算继续使用各自业务口径。S08 日历／甘特、改交期原因、真实计划重算仍属后续业务接通范围。
