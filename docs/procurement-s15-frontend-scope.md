# S15 月度齐套与历史预测：前端范围

## 入口与状态

- 开发预览：`/__preview/monthly-readiness`，导出 `MonthlyReadinessPreviewPage`。
- `product=Q7|Q5`，`month=YYYY-MM`，`mode=month|date`，`deadline=YYYY-MM-DD`。不传产品时默认 Q7；显式 `all`、IN-100、IN-200 或任何未知产品保留原值并显示待选择空态，不能自动映射。
- 保留 `scope` 及其他来源 query；页面明确批次范围、管理入口责任范围尚未接通，不据此放宽或改变库存分配。
- 白底蓝色 Horizon 页面，包括计算范围、整月需求、物料级覆盖、预测时间线、未下单独立情景、物料来源抽屉、历史快照比较。
- 只读、读取失败恢复、来源变更过期提示、未保存离开/刷新保护、保存失败后重试、重置二次确认。

## 计算口径

1. 月剩余整机需求 = 有效本月整机目标 − 归属该月已确认整机完工事件；按事件去重。组件报工、出货和单批次可配套数不抵扣需求。
2. 所有必需 BOM 项参与取最小可配套数，包括非重点的机架固定螺钉。缺 BOM 完整性、单机用量、单位或库存来源记录时输出数据待补齐。
3. 当前库存按物料合并：合格仓库 − 冻结 − 他计划占用 + 已确认未耗用线边。已耗用在制品折算量不另行叠加。缺线边确认、库存负值或数量矛盾时不返回确定套数。
4. 已下单供给以明确且有效的到货日期及预计检验可用日为条件，可用日不得早于到货日。每份订单剩余义务 = 订购 − 批准取消 − 合格验收 − 他用分配。晚到、日期不明、尚未确认供给单列。
5. 完全相同库存记录/订单分配去重；同一产品物料下同订单行存在多份分配会要求核对，不将整行义务重复相加。
6. 未下单采购计划仅进入显式勾选的独立情景，不消除已下单预测的净缺口。
7. 下月没有正式目标时，填写目标后输出草稿情景；不把它展示为正式生产目标。该草稿按当前产品余量假设，尚未扣除本月后续消耗及跨月滚动分配；页面明确展示此假设，正式下月供给留后续数据阶段确认。
8. 多产品共享料需人工确认分配；本演示每个型号使用明确分配份额，各产品独立套数不可直接相加。单批次齐套未接通本月模型。
9. 当前快照晚于历史需求日时，页面明确“按当前数据模拟旧需求”，不倒推历史当日可用库存、不输出历史满足日期。原当日结论以保存快照为准。

## 快照与编辑

历史查看直接读取保存时输入、版本、来源及结果。“按当前数据重算并准备另存”生成新的待保存结果，保存时追加快照并保留 `sourceSnapshotId`。库存/交期样例更新提升来源版本，旧屏幕结果变为过期，必须重算后保存。缺失数据结果不能保存为已确认预测；草稿情景可以另存且保留草稿属性。

所有演示状态仅在当前 React 页面实例内存在，无 API、库存写入、本地存储、正式权限或跨模块同步；刷新恢复种子。与 S18 通过产品、月份链接切换，但两页当前为独立样例，不声称同源。

## 模型读取契约

路径：`src/app/procurement/monthly-readiness/monthlyReadinessModel.ts`。

- `createMonthlyReadinessState()` 返回独立的演示状态。
- `defaultReadinessInput(product = 'Q7', month = '2026-09')` 返回整月输入。
- `calculateMonthlyReadiness(state, input)` 返回完整结果、BOM 行、数据问题、时间线及快照版本。
- `getMonthlyReadinessSummary(state, product = 'Q7', month = '2026-09')` 返回 `product, month, target, completed, remaining, currentKits, predictedKits, status, dataIssues, deadline`。
- `status` 为 `incomplete | gap | ready | draft`；缺数据的套数为 `null`，不能解释为 0。
- 默认 Q7：目标 1,000、整机完工 216、剩余 784；阀体线边待核，确定套数为 null。补齐演示线边后当前 600、按期预计 784，预测日期 09-26。
- `saveMonthlyReadinessSnapshot()` 检查来源版本、保留原记录、追加克隆结果、对相同快照 ID 幂等。
