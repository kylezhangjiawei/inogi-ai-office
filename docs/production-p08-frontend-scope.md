## 本轮实施范围

| 范围 | 页面和交互 |
| --- | --- |
| 异常清单与筛选 | 按产线、人员范围、处理状态和搜索核对同一异常；当前异常展示来源、日期、批次、工序、优先级、责任人及期限 |
| 指派责任人 | 核对人员、期限、优先级及分派说明；保留原异常号，未解决问题持续保留下一责任人 |
| 确定处理方向 | 现场整改、研发协同或采购协同；允许原因待确认，确认原因时再填写依据说明，不强迫未知问题假填根因 |
| 现场整改 | 分批记录实际处理量、日期、措施、完成依据和可选照片；完成量与复验合格量分开，未获复验的范围仍是不良待处理 |
| 提交复验 | 绑定具体整改记录，从尚未提交的完成量取量；明确核对后建立本页交接记录，不能重复占用同一整改范围 |
| 复验回执 | 展示已有 QC 只读回执的数量、合格、不良、SIP 版本及依据；新交接等待实际接口回执，不由 P08 代填合格结论 |
| 历史与来源 | 四个视图为问题与协同、整改记录、复验交接、操作记录；有准确来源时打开 P02/P03 原任务或 P09 历史批次 |
| 角色与恢复 | 按质量、产线、研发、采购、QC 和查看岗位控制可见范围与动作；关闭记录只读，提交错误保留输入，切换受未保存保护 |

## 数量与状态边界

1. 原不良量取明确来源范围；异常转交、整改次数和重复复验不增加原不良件数。不同单位分别阅读，不能把终检的“台”、组件的“件”及物料的“块”合计。
2. 未解决数量、已整改尚待交接量、已交接等待复验量、复验合格量分别计算。新整改和新交接不冲减未解决数量。
3. 每条整改记录的可交接量为整改量减去已交接量，实际送复验数量不得超过该条记录的余额。等待回执范围不能再次当成新整改量占用。
4. 复验仍不良的部分回到原异常继续处理，已合格范围不能再次整改。回执必须关联交接记录及原异常，后续真实接口需要逐台或受控子批次证明物理范围唯一。
5. P03 当前支持多轮不良记录链，但缺跨模块完整实物/SN对应。本轮来源去重不能替代真实物理唯一性，也不把 P02 自检与 P03 QC 新发现的不良强行合并。
6. 尚未解决时不能强行关闭；已有全量合格依据时，由相应质量权限核对关闭。关闭异常不创建 QA 放行、库存流水或出货，也不回填初检合格率。
7. 报废及让步接收政策尚未确定，本轮不提供直接执行这些结果的普通岗位按钮。正式阶段需确认申请、授权、实物处置、库存和质量放行边界。
8. 高频现象按明确时间范围、产线和去重来源样本统计；演示样本须明确标识，不足样本时只给常用现象，不伪造真实 Top10。
