# S02 转采购未提交保护

2026-09-14，继续“先补页面和交互”。本次修改共享转采购表单，同时覆盖研发任务详情、研发个人工作台的现有入口。

## 交互范围

- 全部采购字段、产品及附件选择参与修改判断，以本次打开时的实际初值为准；取消勾选或把字段恢复原值后，可直接关闭。重新提交以已回填需求为初值。
- 已修改后点击取消、右上角关闭、遮罩或按 Esc，先选择“继续填写”或“放弃并关闭”。继续保留内容和附件；明确放弃才退出。新附件仅暂存在当前弹窗内，确认生成时才上传。
- 提交开始立即锁住重复提交及旧事件回调；字段、日期、产品、附件增删和关闭入口同步禁用。失败保留当前内容并允许重试；成功正常关闭。
- 任务关联查询晚到时保留正在填写的内容，显示既有采购编号并禁止重复生成。提交入口及上传完成后均检查最新关联。已经发出的请求按正常结果处理，不把后续读到本次关联当作外部冲突。
- 弹窗卸载、任务／账号／工作区改变后，旧上传结果不能继续发起转采购；已发出请求的旧结果不回写当前页面。忽略旧结果不等于取消已发出的服务器请求。
- 工作台底层抽屉识别嵌套 alertdialog，不抢走确认框的 Tab 和 Esc。关闭确认与主弹窗分别恢复焦点。表单内容滚动，底部操作保持可达。

## 验证与复现

使用实际表单及原工作台弹层算法，搭配无登录令牌的本地隔离查询与提交夹具。夹具位于 `artifacts/qa/s02-transfer-guard/harness/`，入口为 `http://127.0.0.1:4185/__qa/s02-transfer-guard`。业务请求在夹具中按明确路径处理，未知接口拒绝，不代理真实业务。

20 项新增保护测试与邻近回归合计 88 / 88 通过，覆盖原值恢复、文件选择、确认继续／放弃、同步重复点击、失败保稿、卸载／切换范围后的迟到响应和晚到关联；类型检查和生产构建通过。同一组新增测试换入修改前备份得到 3 通过、17 失败，日志在 `artifacts/qa/s02-transfer-guard/`。

浏览器已验证桌面和 390×844 手机：未改直接关闭、取消／Esc／遮罩确认、继续保稿、恢复初值、重提回填、失败后原表单重试成功、双击只增加一次调用、提交中全部字段与关闭禁用、晚到关联禁用生成。嵌套场景使用原工作台弹层算法与真实表单，Tab／Shift+Tab／Esc 不关闭父层，放弃子表单后父备注保留且焦点恢复。手机页面宽度为 390，底部操作与关联提示在视口内。
