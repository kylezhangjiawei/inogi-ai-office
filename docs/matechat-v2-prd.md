# MateChat V2 产品需求文档

- 状态：Draft v0.1（可进入产品与技术评审）
- 日期：2026-09-08
- 首期范围：桌面端、研发任务场景；接口预留采购、订单与质量域扩展
- 核心功能：当前页面上下文、今日作战台、批量行动方案

---

## 一、执行摘要

MateChat 当前已经具备多轮会话、多模型路由、附件理解、结构化数据与知识库检索、联网搜索、来源引用、ReAct 工具调用、写操作确认、文件与媒体生成、分享、反馈和运营分析等能力。

V2 不再以“增加聊天能力”为主，而是把 MateChat 升级为工作入口：

1. **知道用户正在看什么**：在任务、采购单等页面中直接围绕当前对象提问。
2. **知道今天什么最重要**：主动整理本人必须处理、正在形成风险和可以推进的事项。
3. **能安全完成一组变更**：先生成可编辑计划，用户确认具体版本后再确定性执行。

产品定位：

> MateChat 是一个能解释当前业务状态、展示证据，并在用户确认后安全改变业务状态的企业工作助手。

### 1.1 首版成功标准

- 用户无需复制任务编号，即可针对当前页面获得基于最新数据的回答。
- 今日作战台能够稳定找出真正等待本人处理的事项，并避免重复、过期和越权提醒。
- 两项及以上写操作不会直接并发执行，而是形成一份可检查的行动方案。
- 所有业务答案、简报和行动计划都能追溯到来源、更新时间、权限判断和审计记录。
- 未授权数据曝光、未经确认写入、重复业务副作用三项均为 0。

### 1.2 北极星指标

**每周通过 MateChat 完成至少一个可验证工作闭环的活跃用户数。**

“可验证工作闭环”包括：从上下文回答进入并完成业务动作、简报事项在业务 SLA 内解决、行动方案成功执行，或输出产物被明确采用。消息数、打开次数和连续使用天数只作为采用度辅助指标，不作为核心成效指标。

## 三、产品目标与原则

### 3.1 产品目标

1. 将“找到对象—复制编号—打开聊天—重新说明”缩短为“点击问 MateChat—直接提问”。
2. 将“用户想到才问”升级为“系统给出少而准确的今日事项”。
3. 将“逐条确认操作”升级为“先审阅一份整体计划，再确认执行”。
4. 保持所有能力可解释、可回放、可撤销或明确不可撤销、可审计。
5. 首版形成可复用的实体解析器、简报提供器和行动注册表，而不是为单个页面写死逻辑。

### 3.2 设计原则

- **服务端事实优先**：客户端只传引用，不把页面文本当成权威业务数据。
- **规则筛选、模型解释**：权限、优先级、风险阈值和执行条件由确定性逻辑决定；模型负责摘要、解释和计划建议。
- **上下文不扩权**：能看到入口不代表能读取对象；每次读取和执行都重新鉴权。
- **确认具体版本**：用户确认的是不可变的计划版本与差异，不是仍在变化的草稿。
- **状态可恢复**：刷新、切换会话、网络重试或服务接管后，不能丢失上下文、简报状态、计划与执行回执。
- **低打扰主动性**：没有重要变化时保持安静；不为提高聊天次数制造提醒。
- **先单域、后跨域**：先把研发任务域做稳，再扩展采购、订单、质量和售后。

### 3.3 首版不做

- 不读取页面 DOM、截图或浏览器缓存作为业务事实。
- 不允许 MateChat 在没有确认的情况下批量写入。
- 不做任意跨业务域的混合行动方案。
- 不做共享项目房间、长期个人记忆或部门自建 Agent。
- 不做会议实时录音与转写；只为后续“纪要转行动项”预留计划能力。
- 不把放弃、合并、审批通过/驳回、外部发送和付费生成混入普通批量计划。

## 五、整体体验

### 5.1 三项能力的衔接

1. 用户在业务页面点击“问 MateChat”，当前对象以卡片形式附在输入框上方。
2. 用户可以直接提问，也可以选择页面场景快捷问题。
3. MateChat 用服务端最新数据回答，并展示“当前页面”来源。
4. 如果问题包含多项写操作，MateChat 不直接执行，而是生成行动方案。
5. 用户在方案卡内编辑、检查并确认具体版本。
6. 执行完成后给出逐项回执，并刷新当前对象和今日作战台。
7. 次日或状态发生重要变化时，今日作战台继续承接后续推进。

### 5.2 MateChat 首屏信息架构

| 区域 | 内容 | 默认行为 |
| --- | --- | --- |
| 今日作战台 | 必须处理、风险与临期、可推进 | 最多展示 5 项，可展开完整列表 |
| 当前上下文 | 当前页面对象或用户选中对象 | 用户显式关联，可移除或切换 |
| 快捷建议 | 从简报和页面上下文派生 | 点击后先填入输入框；高风险意图不直接发送 |
| 会话区 | 问答、来源、工具步骤、行动方案与回执 | 保持现有流式体验 |
| 后台任务 | 资料包、媒体和行动方案执行状态 | 可关闭聊天后继续，完成后统一通知 |

## 六、功能一：当前页面上下文

### 6.1 功能定义

业务页面向 MateChat 传递稳定的对象引用。MateChat 在用户发送消息时由服务端重新读取最新数据并应用原业务权限，使“这个任务”“这张采购单”“这些选中项”成为可靠指代。

### 6.2 MVP 场景

| 页面/对象 | 典型问题 | MVP 动作 |
| --- | --- | --- |
| 研发任务详情 | 为什么延期、风险是什么、下一步做什么 | 查询、进展、优先级、负责人、截止日、分类与父子关系操作 |
| 研发任务已选项 | 按风险排序、总结共同问题、形成调整方案 | 首期只读分析；写意图进入行动方案 |
| 采购任务详情 | 卡在哪一步、预计能否到货 | 首期只读；后续接入采购动作 |
| 采购订单详情 | 哪些未到货、风险金额和跟进内容 | 首期只读与沟通草稿 |

研发任务详情是首个灰度范围。采购任务和采购订单在实体解析器与权限策略稳定后开启。

### 6.3 用户流程

1. 页面数据加载完成后，在标题区、详情抽屉或已选项工具栏显示“问 MateChat”。
2. 点击后打开聊天，并显示“当前上下文：研发任务 RD-…”。入口只传对象类型和 ID。
3. 用户可移除上下文；页面切换时不静默替换，提示“切换到新页面”或“继续使用原对象”。
4. 发送时，上下文引用与用户消息使用同一个幂等请求绑定并持久化。
5. 服务端调用对应业务服务读取最新对象，完成页面权限、资源权限、工作区与字段级裁剪。
6. 回答显示对象标题、来源、读取时间和站内链接；无权限时不得泄露对象是否存在或标题。
7. 重新回答复用原用户消息绑定的上下文，不使用用户当前所在的新页面。
8. 后续写操作继续走单项确认卡或批量行动方案。

### 6.4 客户端引用契约

```ts
type PageContextRefV1 = {
  schemaVersion: 1;
  pageKey:
    | "rd_task_detail"
    | "rd_task_selection"
    | "procurement_task_detail"
    | "purchase_order_detail";
  scope: "entity" | "selection";
  refs: Array<{
    entityType: "rd_task" | "procurement_task" | "purchase_order";
    entityId: string;
    workspace?: "rd" | "us-collab" | "production";
    revision?: string;
  }>;
  capturedAt: string;
  displayHint?: { label?: string; title?: string };
};
```

约束：

- `displayHint` 只用于打开瞬间展示，不进入模型上下文，也不能用于权限或事实判断。
- `entity` 只允许一个引用；`selection` 只允许同类型对象，MVP 最多 50 个。
- 页面使用稳定 `pageKey`，不依赖可配置路由路径。
- 不传整页 JSON、原始 URL、HTML、附件签名地址或隐藏字段。
- 未知版本或不支持的组合只降级为普通聊天，不阻断会话。

建议发送消息接口增加：

```ts
type SendMessageInput = {
  content?: string;
  model?: string;
  clientMessageId?: string;
  regenerateMessageId?: string;
  attachments?: AttachmentRef[];
  pageContext?: PageContextRefV1;
};
```

### 6.5 服务端解析契约

```ts
type ResolvedPageContextV1 = {
  schemaVersion: 1;
  status: "resolved" | "partial" | "stale" | "denied" | "not_found" | "timeout" | "unsupported";
  pageKey: string;
  scope: "entity" | "selection";
  entities: Array<{
    entityType: string;
    entityId: string;
    title: string;
    workspace?: string;
    revision?: string;
    canonicalUrl: string;
    fields: Record<string, unknown>;
  }>;
  resolvedCount: number;
  filteredCount: number;
  missingCount: number;
  truncated: boolean;
  resolvedAt: string;
};
```

实现要求：

- 建立 `PageContextResolverRegistry`，每种实体通过原业务服务读取，不在聊天模块复制权限逻辑。
- 每类实体使用字段白名单；单对象建议不超过 8 KB，选择上下文建议不超过 16 KB。
- 默认只持久化引用、解析状态、版本和数据哈希，不持久化完整敏感快照。
- 来源类型增加 `page`；历史消息必须能恢复上下文卡和来源状态。
- 页面描述、备注、文件名和附件内容统一作为不可信数据，不能触发工具或覆盖系统规则。

### 6.6 状态与降级

| 状态 | 用户体验 |
| --- | --- |
| 数据加载中 | 入口显示加载态；仍可打开普通聊天 |
| 解析超时 | 提示当前页面暂未读取成功，继续普通问答，不声称已看过页面 |
| 权限被撤销 | 移除上下文并提示无法读取，不展示残留标题和字段 |
| 对象已更新 | 使用服务端最新数据回答，并显示“已按最新数据回答” |
| 部分选择项不可用 | 说明成功读取 N 项、另有 M 项未纳入，不泄露被过滤项内容 |
| 超过 50 项 | 明确要求缩小范围，不静默截断 |
| 文字出现另一编号 | 指出与页面对象冲突，等待用户明确选择 |
| 页面发生切换 | 不影响已发送请求；草稿由用户决定是否切换上下文 |

### 6.7 验收标准

- [ ] 在研发任务详情点击“问 MateChat”，输入区展示正确对象类型、编号和标题。
- [ ] 用户发送“这个任务为什么延期”时，请求只携带引用，后端使用发送时最新业务数据。
- [ ] 篡改标题、工作区、版本或展示提示不能改变服务端解析结果。
- [ ] 无权用户构造对象 ID 时不能获得对象存在性、标题或任何字段。
- [ ] 页面对象已更新时回答标记 `stale`，且不会使用旧值执行动作。
- [ ] 回答显示“当前页面”来源，点击后重新鉴权并进入原记录。
- [ ] 上下文与消息一起持久化；刷新和重新回答后仍使用原引用。
- [ ] 生成期间切换页面不会污染当前回答。
- [ ] 同一 `clientMessageId` 重试只落一条消息和一份上下文绑定。
- [ ] 详情解析 P95 不超过 500 ms；50 项选择上下文 P95 不超过 1,000 ms。
- [ ] 上下文派生回答分享给无资源权限的接收人时，服务端阻止发送或生成脱敏版本。

## 七、功能二：今日作战台

### 7.1 功能定义

今日作战台把现有个性化快捷建议升级为结构化、可解释、可执行的每日工作简报，帮助用户回答：

- 今天必须处理什么？
- 哪些事项正在形成延期、缺料或审批风险？
- 下一步可以直接做什么？

“今日”统一按 `Asia/Shanghai` 自然日计算。简报本身不得自动审批、改任务或通知他人。

### 7.2 MVP 数据范围

| 数据源 | 入选范围 | 权限 |
| --- | --- | --- |
| 研发任务 | 本人逾期、今日截止、未来 3 日临期、重要未完成任务 | 普通成员仅本人；管理者按既有管理权限 |
| 审核队列 | 明确等待当前用户处理的审核事项 | 必须具有对应审核权限 |
| 站内待办 | 当前用户未处理、可行动的待办 | 仅本人收件范围 |
| 采购缺料 | 扣除库存、在途和进行中任务后仍存在缺口 | 现有采购查询权限 |
| 采购在途 | 预计到货日已过或未来 3 日临期且未到齐 | 现有采购查询权限 |
| 采购任务 | 高优且临期、等待本人推进 | 现有采购任务权限 |

### 7.3 首屏结构

默认最多展示 5 项：

1. **必须处理（P0）**：等待本人动作、已经逾期或今天到期。
2. **风险与临期（P1）**：未来 3 个自然日内需要干预，或已有明确缺口。
3. **可推进（P2）**：重要但不临期，或适合 MateChat 协助完成的事项。

每项至少展示：

- 标题、对象编号与业务来源；
- 入选原因，例如“已逾期 2 天”“等待你审核”；
- 截止日、预计到货日或同步时间；
- 来源更新时间与简报生成时间；
- “查看原记录”“问 MateChat”“稍后提醒”“不再关注”；
- 有权限时显示可执行动作。

无 P0/P1 时显示“今日暂无高优先事项”，不使用低价值信息制造虚假风险。

### 7.4 确定性优先级规则

| 优先级 | 规则 | 示例 |
| --- | --- | --- |
| P0 | 已逾期、今天到期或明确等待本人动作 | 逾期任务、本人待审核、ETA 已过且未到齐 |
| P1 | 未来 3 日内临期或已有明确缺口 | 临期任务、有效缺料、临期在途 |
| P2 | 重要但不临期，适合继续推进 | 其他本人未完成任务、周报和沟通建议 |
| 不展示 | 已完成、已处理、纯结果通知或无依据预测 | 历史完成任务、陈旧普通通知 |

同级排序：等待本人动作 → 超期/距截止时间 → 显式优先级 → 影响数量 → 最近更新时间 → 稳定对象编号。

补充约束：

- 同一对象同时命中任务、通知和审核时合并为一项，保留多个入选依据。
- 未设置截止日不能判定逾期。
- 缺料必须扣除有效库存、在途和进行中采购任务。
- 陈旧数据不能单独触发 P0。
- P0 超过 5 项时只展示前 5 项并标明剩余数量，P1/P2 不挤占 P0。
- 大模型只生成摘要和解释，不决定权限、数量、优先级或风险等级。

### 7.5 主流程

1. 用户首次进入个人工作台或打开 MateChat。
2. 服务端并行读取权限内任务、审核、消息和采购数据。
3. 规则引擎筛选、去重、排序，先返回结构化卡片。
4. 自然语言摘要异步补充；生成失败不影响卡片可用。
5. 用户查看原记录，或带着对象上下文进入 MateChat。
6. 进展、审批、催办等操作继续生成确认卡；动作成功后刷新简报。
7. 已解决事项移入“今日已处理”，不再占据高优先位置。

### 7.6 主动通知策略

- 默认在当天首次进入系统或首次打开 MateChat 时静默展示。
- 只有存在 P0 时，上午首次活跃可投递一条聚合铃铛通知。
- 当日只在新增 P0 或严重程度升级时发送增量通知；同一状态指纹只通知一次。
- 默认每日主动通知不超过 2 次；18:00 至次日 09:00 静默。
- 连续操作页面不弹遮挡式窗口，只显示非遮挡卡片或角标。
- 已展示简报时，不再叠加通用“今天还没用 MateChat”提醒。
- 用户可以选择“今天静默、仅保留 P0、关闭主动通知”。关闭通知后仍可主动查看作战台。
- MVP 不发送短信、邮件或企业微信。

### 7.7 数据契约

```ts
type TodayBrief = {
  briefId: string;
  date: string;
  generatedAt: string;
  status: "complete" | "partial" | "failed";
  items: Array<{
    id: string;
    source: string;
    entityType: string;
    entityId: string;
    priority: "P0" | "P1" | "P2";
    title: string;
    reason: string;
    dueAt?: string;
    sourceUpdatedAt: string;
    freshness: "fresh" | "stale" | "unknown";
    fingerprint: string;
    availableActions: string[];
    deepLink: string;
  }>;
};
```

缓存与新鲜度：

- 研发任务、审核与消息允许最多 60 秒短缓存。
- 采购内部任务与库存计算允许最多 5 分钟缓存。
- 外部在途同步超过默认 30 分钟时标记可能过期；阈值可配置。
- 任一数据源失败时，其他分区继续展示；失败不能被解释成“没有风险”。
- 点击来源、进入问答或执行动作时必须重新鉴权并读取最新数据。

### 7.8 验收标准

- [ ] 2 条逾期任务和 1 条今日截止任务均进入 P0，数量和日期与源数据一致。
- [ ] 未来 3 日临期事项进入 P1，不得显示为已逾期。
- [ ] 审核权限撤销后刷新，审核明细和动作立即不可见。
- [ ] 无采购权限用户的响应中不存在采购标题、数量、价格或隐藏数量侧信道。
- [ ] 陈旧外部数据明确标记过期，且不能单独产生 P0 主动通知。
- [ ] 同一对象命中多个来源时只展示一张卡片。
- [ ] 事项解决后从待处理区移除并进入今日已处理。
- [ ] 点击“问 MateChat”携带对象引用，回答前重新读取最新状态。
- [ ] 未确认、已过期或权限变化时，任何简报动作均不得执行。
- [ ] 同一事项状态未变化时，一天内不得重复投递主动通知。
- [ ] 局部数据源失败时显示“暂未更新”，不得显示虚假零风险。
- [ ] 缓存命中时首屏结构化简报 P95 小于 2 秒。
- [ ] 所有事项均可追溯至对象、命中规则和生成时间。

## 八、功能三：批量行动方案

### 8.1 功能定义

当用户提出多个目标、多个字段或多个写动作时，MateChat 先形成一份可编辑、可校验的变更集。只有用户确认一个不可变的具体版本后，确定性执行器才调用业务服务。

### 8.2 进入行动方案模式的条件

满足任一条件时必须进入行动方案模式：

- 用户明确使用“批量、全部、统一、这些、分别、按清单执行”等表达。
- 同一轮涉及两个及以上写动作。
- 涉及两个及以上业务目标。
- 同一目标需要修改多个字段。
- 动作有先后依赖。
- 用户明确要求“先列方案，我确认后执行”。

服务端必须检查完整工具批次；不能只依赖模型提示词判断。批量场景中的现有 `direct` 动作自动提升为必须确认。

### 8.3 MVP 支持范围

- 仅研发任务域、单一工作空间。
- 单计划最多 20 个执行项。
- 批量修改优先级、描述、负责人和截止日期。
- 批量移动分类、并入父任务。
- 为后续会议纪要批量创建行动项提供接口。
- 支持草稿查看、行内编辑、删除和取消勾选。
- 支持完整校验、版本确认、执行进度、逐项回执和刷新恢复。

MVP 不支持：

- 放弃、合并、审批决定、外部发送、付费媒体等 R3 动作。
- 跨工作空间或跨业务域计划。
- 多人共同编辑、他人代确认、定时执行。
- 混合跨服务计划的全局事务或自动补偿承诺。

### 8.4 计划卡必须展示

- 计划标题与一句话目标；
- 可执行、警告、阻塞项数量；
- 涉及对象数、人员数和最高风险；
- 每项业务对象及“当前值 → 目标值”；
- 执行顺序与依赖；
- 执行保证：全量原子、失败即停止，或可能部分成功；
- 不可自动回滚项；
- “检查计划”“确认执行”“取消”和“查看全部变更”。

### 8.5 完整流程

#### A. 生成

1. ReAct 先用只读工具解析任务、人员、分类和当前状态。
2. 模型调用一次 `prepare_action_plan` 提交结构化意图。
3. 服务端完成工具白名单、参数归一化、稳定 ID 解析、去重、冲突检测、当前值快照、资源版本、风险与依赖计算。
4. 保存 `draft` 计划并返回计划卡；此阶段不调用任何业务写服务。
5. 同名人员、无效日期、目标不存在等问题明确标记阻塞，模型不得猜测。

#### B. 编辑

- 用户可以改负责人、日期、优先级、描述、分类，删除或取消勾选项目。
- 每次编辑携带 `baseRevision`，成功后产生新版本并重新计算摘要。
- 工具名、权限结果、风险、当前值、资源版本、幂等键和执行器不能由前端编辑。
- 任意编辑都会使旧校验和旧确认卡失效。
- 版本冲突返回 `409 PLAN_REVISION_CONFLICT`，不得静默覆盖。

#### C. 校验

服务端检查：

- 参数 schema、枚举、长度与日期；
- 对象存在性、状态、工作空间和操作权限；
- 用户是否仍为允许操作的主责人、协作者或管理员；
- 资源版本是否与计划快照一致；
- 同一对象同一字段是否冲突；
- 依赖是否循环或缺失；
- 规模是否超过上限；
- R3 动作是否被夹带；
- 执行策略是否真实可保证。

结果分为 `valid / warning / invalid / stale`。无效项不得静默跳过；用户可主动取消该项后重新校验。

校验成功后生成不可变 `revisionHash`、有效期、确认摘要与最终执行策略。沿用 30 分钟确认有效期，但执行前仍再次校验权限和资源版本。

#### D. 确认

确认卡只保存计划 ID、版本、内容哈希和执行策略，不复制一份可能与草稿失配的载荷。

确认时依次检查：

1. 确认者是计划创建人；
2. 卡片仍待确认且未过期；
3. 计划版本与哈希完全一致；
4. 计划处于 `ready`；
5. 权限、资源版本和配额仍有效；
6. 通过条件更新原子抢占执行权。

#### E. 执行

- 确认后返回执行编号，由确定性执行器完成，不再让模型参与决策。
- 根据依赖图排序；同一对象的动作串行，不同且无依赖的对象可有限并发。
- 每项执行前再次检查权限、资源版本和业务前置条件。
- 每项使用稳定幂等键，服务重试或实例接管不能重复产生业务副作用。
- 进度通过 SSE 推送，同时持久化，刷新后可恢复。

#### F. 回执

必须区分全部成功、部分成功、全部失败、数据已变化未执行、已回滚和需要人工处理。逐项显示实际结果、失败原因、执行前后值和审计入口。

### 8.6 风险分级

| 等级 | 定义 | 典型动作 | 产品控制 |
| --- | --- | --- | --- |
| R0 | 只读 | 查询任务、人员、知识 | 不进入行动方案执行 |
| R1 | 可逆元数据 | 优先级、描述 | 单项可直接；批量必须确认 |
| R2 | 影响安排或结构 | 负责人、截止日、分类、父任务、创建任务 | 必须确认并展示完整差异 |
| R3 | 不可逆、对外、付费或审批 | 放弃、合并、审批、发送、付费生成 | MVP 排除；后续独立强化确认 |

超过 10 个业务目标显示“大范围变更”并二次确认。计划风险取所选项目的最高等级。

### 8.7 执行策略

| 策略 | 适用条件 | 失败行为 |
| --- | --- | --- |
| `atomic_batch` | 同一业务存储和原子边界，且已有批量执行器 | 全部成功或全部不生效 |
| `stop_on_error` | 混合动作或无法全局事务 | 已成功项保留；失败后停止后续与依赖项 |
| `continue_independent` | 用户明确允许且项目互不依赖 | 独立项继续，失败项单独记录 |

MVP 默认优先使用既有原子批量服务；混合动作使用 `stop_on_error`，并在确认前明确“可能部分成功”。不支持时不得宣称可全量回滚。

### 8.8 数据模型草案

| 模型 | 关键字段 | 用途 |
| --- | --- | --- |
| `ChatActionPlan` | 会话、创建人、源消息、状态、当前版本、最高风险、执行策略、过期时间 | 计划主记录 |
| `ChatActionPlanRevision` | 版本、内容哈希、注册表版本、校验结果、有效期 | 不可变版本与确认依据 |
| `ChatActionPlanItem` | 工具、目标、当前值、目标值、资源版本、风险、依赖、校验状态 | 可编辑执行项 |
| `ChatActionExecution` | 确认卡、幂等键、租约、总体状态、回执 | 执行批次与恢复 |
| `ChatActionExecutionItem` | 单项幂等键、状态、执行前后值、错误 | 逐项事实与审计 |

`ChatPendingAction` 继续作为确认入口，新计划和执行表作为事实来源。

### 8.9 API 草案

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/chat/conversations/:conversationId/action-plans` | 幂等创建草稿 |
| GET | `/api/chat/action-plans/:planId` | 获取计划与执行状态 |
| PATCH | `/api/chat/action-plans/:planId` | 按 `baseRevision` 编辑 |
| POST | `/api/chat/action-plans/:planId/validate` | 校验指定版本 |
| POST | `/api/chat/action-plans/:planId/prepare-confirmation` | 为已校验版本创建确认卡 |
| POST | `/api/chat/actions/:actionId/confirm` | 复用现有确认入口并启动执行 |
| POST | `/api/chat/actions/:actionId/cancel` | 复用现有取消入口 |
| GET | `/api/chat/action-executions/:executionId` | 获取进度与逐项回执 |

所有写接口接受 `Idempotency-Key`。关键错误码包括：`PLAN_REVISION_CONFLICT`、`RESOURCE_STALE`、`PLAN_EXPIRED`、`PLAN_VALIDATION_FAILED`、`ATOMICITY_NOT_SUPPORTED`。

### 8.10 验收标准

- [ ] 两个及以上目标或写动作必须生成一份计划，确认前业务数据零变化。
- [ ] 每项显示稳定目标、当前值、目标值和风险，不能只显示汇总数量。
- [ ] 编辑产生新版本，旧确认卡不能执行。
- [ ] 计划包含无效、越权或过期项时不得确认，也不得静默跳过。
- [ ] 确认前权限撤销或对象变化时，不覆盖最新数据，并返回 `RESOURCE_STALE`。
- [ ] 双击、多标签页、多实例和网络重放最多创建一个执行批次。
- [ ] 业务写入后服务退出，恢复后不得重复写入。
- [ ] 原子组失败时不存在部分变更；非原子部分成功时回执准确说明。
- [ ] R3 动作不能混入普通计划。
- [ ] 刷新和切换会话后可恢复计划、确认卡与执行进度。
- [ ] 全生命周期具有关联审计记录，敏感内容脱敏。
- [ ] 20 项计划的服务端校验 P95 不超过 2 秒，不含模型生成耗时。

## 九、跨功能权限、安全与可信度

### 9.1 上线前置项

在页面上下文和主动简报灰度前，必须统一结构化预取、RAG 和只读工具的数据可见性策略。所有数据入口都应通过同一资源访问策略判断用户、角色、部门、工作空间、知识等级和字段级权限，不能先读取全量数据再依赖模型过滤。

建议将现有文件归档的“检索时校验—执行时复核—下载时复核”模式推广到上下文、简报、分享和行动方案。

### 9.2 权限检查点

| 阶段 | 必须检查 |
| --- | --- |
| 展示入口 | 页面功能权限；入口隐藏不作为安全边界 |
| 解析上下文 | 会话归属、对象存在性、页面/资源/工作空间/字段权限 |
| 生成简报 | 用户范围、数据源权限、敏感字段与缓存隔离 |
| 调用工具 | 工具权限、资源归属、额外业务约束 |
| 准备计划 | 动作白名单、目标范围、风险与当前状态 |
| 最终确认 | 用户身份、权限、版本、状态、配额、过期时间 |
| 执行每一项 | 权限、资源版本、业务前置条件与幂等状态 |
| 分享/打开来源 | 接收人当前权限；必要时阻止或脱敏 |

### 9.3 数据新鲜度

- 所有业务卡展示“更新于”或来源同步时间。
- 缓存失效、数据源失败和数据过期必须是三个不同状态。
- 数据源失败不能显示为 0，也不能被解释为没有风险。
- 执行动作永远重新读取最新状态，不直接使用回答或简报快照写入。

### 9.4 审计

审计至少关联：用户、会话、消息、上下文引用、简报事项、行动计划、计划版本、确认卡、执行批次、业务对象、工具、权限结果、执行结果和时间。

埋点与普通日志不得保存消息正文、描述全文、供应商联系方式、单价、附件签名地址或其他敏感字段。

| `ChatBriefPreference` | 简报启用状态、类别、静默策略与时区 |
| `ChatBriefSnapshot` | 当日简报结构、来源状态和去重指纹 |
| `ChatBriefItemState` | 稍后提醒、不再关注与解决状态 |
| `ChatActionPlan` | 行动计划主记录 |
| `ChatActionPlanRevision` | 不可变计划版本与校验结果 |
| `ChatActionPlanItem` | 计划项、差异、风险、依赖与资源版本 |
| `ChatActionExecution` | 确认后的执行批次与租约 |
| `ChatActionExecutionItem` | 单项幂等账本与回执 |

### 11.4 兼容与迁移

- 现有消息没有上下文引用时保持普通聊天逻辑。
- 现有单项确认卡继续可用；计划确认作为新的工具类型接入。
- 所有新增表采用独立迁移，不改写历史聊天或任务数据。
- 新能力使用功能开关，关闭后不影响现有 MateChat。
- 数据库迁移先于应用版本发布；旧 API 进程必须能忽略新表与新字段。

### M0：安全与底座收口（发布阻断项）

- 为新增能力准备功能开关、审计事件和灰度用户组。

### M1：当前页面上下文 MVP

- 研发任务详情“问 MateChat”。
- 上下文卡、场景快捷问题、服务端解析与页面来源。
- 消息绑定、历史恢复、重新回答与分享拦截。
- 小范围研发用户灰度，验证准确性与首字延迟。

### M2：今日作战台 MVP

- 先接本人研发任务、本人待办和授权审核队列。

### M4：扩展方向

- 定时监控、事件触发和官方岗位工作流。

## 十三、测试与发布门槛

### 13.1 必测矩阵

| 类别 | 关键场景 |
| --- | --- |
| 权限 | 构造他人对象 ID、权限中途撤销、字段权限、工作空间隔离、分享接收人无权 |
| 幂等 | 消息重放、双击确认、多标签页、多实例抢占、写入后响应丢失 |
| 并发 | 页面对象更新、计划版本冲突、同一对象多字段、执行器接管 |
| 降级 | 上下文超时、部分数据源失败、模型摘要失败、陈旧在途数据 |
| 计划 | 冲突项、无效日期、同名人员、循环依赖、原子组失败、部分成功回执 |
| 恢复 | 刷新、切会话、关闭聊天、服务重启后恢复状态 |
| 安全 | 页面备注/文件名提示注入、未注册工具、额外执行字段、敏感日志 |
| 可用性 | 键盘、读屏、非颜色状态、移动端查看、长标题与 20 项计划 |
| 性能 | 上下文解析、简报首屏、20 项计划校验、普通聊天延迟回归 |

### 13.2 发布阻断标准

- 任一越权读取、越权分享或越权写入用例失败。
- 任一幂等用例产生重复业务副作用。
- 上下文失败时回答仍声称读取了当前页面。
- 简报把数据源失败解释为零风险。
- 非原子计划部分失败却显示全部成功。
- 旧计划版本或过期确认卡仍能执行。
- 普通聊天成功率或首字延迟出现不可接受回退。

## 十五、Definition of Done

一个里程碑只有同时满足以下条件才算完成：

- 产品流程、空态、加载、失败、过期、权限变化和恢复状态均已实现。
- 服务端权限与字段裁剪有自动化测试，前端隐藏入口不作为安全措施。
- 写操作具有确认、资源版本校验、幂等、明确执行策略和逐项回执。
- 关键状态刷新后可恢复，不依赖单次 SSE 或进程内内存。
- 来源、数据时间和操作结果对用户可解释。
- 关键埋点不记录正文或敏感业务字段。
- 灰度指标与安全护栏可在管理端观察。
- 回滚功能开关后，现有 MateChat 会话和单项确认卡继续正常工作。

## 附录 B：建议的首个演示脚本

1. 用户打开一条已临期研发任务，点击“问 MateChat”。
2. 输入“这个任务为什么可能延期，今天应该先做什么？”
3. MateChat 展示当前页面来源、最新进度、截止日、阻塞与三条建议。
4. 用户继续说：“把相关的 6 个任务按风险排序，前三个改到本周五，其中两个改派给李明。”
5. MateChat 生成行动方案，展示每项当前值、目标值、风险和执行策略。
6. 用户删除一项、修改一个截止日并点击检查。
7. 系统校验后生成不可变确认卡；用户确认。
8. 执行器逐项回执，并刷新任务页与今日作战台。
9. 次日简报不再重复提示已解决事项，只提示新出现或升级的风险。
