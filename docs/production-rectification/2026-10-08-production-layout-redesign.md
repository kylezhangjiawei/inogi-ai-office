# 生产模块页面布局重构专项方案

> 2026-10-09 更新：用户否定了本文此前采用的驾驶舱工作台布局。驾驶舱部分已由 [P00 对照整改](2026-10-09-cockpit-correction.md) 替代；其他页面与未闭环事项保持。

日期：2026-10-08｜对应主方案：V1.1｜状态：推荐布局方案，未实施页面代码

后续状态：第一批页面已按此方向实施，实际完成范围与尚未闭环项见 [实施记录](2026-10-08-production-implementation.md)。下文保留布局决策时的规划口径，不代表全部页面已开发完成。

## 1. 本次调整的决定

用户明确允许推翻生产页面的原有布局、静态内容及驾驶舱结构。本次是布局重构范围的补充，不再将工作限制为修间距、换颜色或给旧页面增加卡片。

必须保留的是业务事实、已有数据、权限、流程约束和用户能完成的操作。原卡片排列、页面分栏、表格位置、横向标签、装饰、示例图表、重复提示和静态文案都可以重新组织。移除静态内容前须确认其是否承载真实说明或操作入口，业务含义需要保留的改到恰当位置。

原型用于核对功能和信息，不要求像素复刻。默认保持 INOGI 品牌识别及全站基础控件的一致性，生产模块内部可以重新设计页面结构和内容密度；此次不扩大为全站品牌改造。

设计目的：主管能判断交付风险，计划员能安排生产，现场能快速录入，质检员能找到下一项检验，相关人员能追溯问题。具体首页默认受众已发起确认；未收到答案时，推荐以主管/计划员为驾驶舱默认受众，现场任务使用独立入口。

## 2. 现有结构为什么需要重做

以下来自当前组件代码与用户所附原型，不等同于新一轮全页面浏览器测量：

| 已核查的结构 | 对使用的影响 | 重构方向 |
| --- | --- | --- |
| 驾驶舱依次放月度指标、风险区、默认折叠的现场列表及发货记录；风险区又有独立筛选和刷新 | 月度结果、当前风险、现场工作处于不同范围，用户需要反复辨别筛选作用域 | 月度概览与当前待办明确分区；核心风险默认可见，历史明细下钻 |
| 生产工作区把批次、日程、现场、检验、质量、齐套、转产、发货、档案、历史共十类内容放在同一组标签 | 一个页面承担多种角色，用户先选择技术分区才能找到工作 | 稳定业务导航加角色工作台；生产单详情中只保留关联信息分区 |
| 原型多数页面重复放月份、出货目标、已出货、待出货和流程条 | 在录入与质检页面占据空间，却不帮助当前动作 | 管理总览保留汇总；工作页只展示当前对象和办理条件 |
| P02 原型将报工和不良登记两个大表单并排 | 操作焦点不明确，小屏输入区域容易拥挤 | 先选任务，再执行报工或不良登记；共享任务信息，不重复填 |
| P04/P08/S16 使用相近的问题详情，但布局和操作位置不同 | 同一异常换页面后需要重新找信息和按钮 | 一个异常工作台，按来源显示差异字段，操作位置一致 |

## 3. 推荐信息架构

建议用户按工作目的进入，而不是把十四张原型逐一变成十四个并列菜单。

| 一级业务入口 | 主要内容 | 对应原型 |
| --- | --- | --- |
| 生产驾驶舱 | 交付概况、阻断风险、今日生产和待办 | P00 |
| 生产计划 | 生产单列表、排程、工序派工、用料与到货 | P01、P07 |
| 现场工作台 | 我的任务、领料、报工、不良快捷登记 | P02 |
| 检验工作台 | 来料、过程、性能、最终闸门、复验及待放行入口 | P03、S10 的检验视图 |
| 不良与协同 | 异常列表、初判、接收、协同、处置与验证 | P04、P08、S16；S06 为分析视图 |
| 转产与追溯 | 转产、ECN、生产单档案及跨链查询 | P05、P10 |

“全部任务”P06 作为统一待办入口，贯穿上述业务，可放在生产导航顶部或页头固定入口。S10 收货操作和 S11 退料接收仍从仓库工作台进入，同一个收货/退料对象可按权限从生产关联查看，不复制台账。

生产单详情作为共同上下文，包含“概况、工序执行、用料、质量、资料与追溯”等有限分区。部门用户直接到自己的工作台，不强迫先进入某个月度计划、再逐层找标签。

## 4. 驾驶舱：围绕交付与待处理问题重新设计

### 4.1 桌面推荐结构

```text
生产驾驶舱    型号 / 产线范围                         数据更新时间 · 刷新
─────────────────────────────────────────────────────────────
月度概览 [月份]
本月实际完工       本月计划完成率       实际净发货
─────────────────────────────────────────────────────────────
当前运营 [今日]                         包含跨月未完成事项
优先处理的阻断与逾期（主区域）           我的待办（辅助区域）
影响生产单 · 原因 · 经办 · 时限 · 办理   到货审批 / 接收 / 确认
─────────────────────────────────────────────────────────────
今日生产与工序进度（主区域）             到料与检验（辅助区域）
生产单 / 产线 / 工序 / 进度 / 偏差       已到待审批 / 待检 / 待入库
─────────────────────────────────────────────────────────────
月度趋势 [随月份切换]                    质量关注 [所选期间]
计划与实际，口径可查看                   主要问题与关联异常
```

这是一种信息层级示意，不是已锁定的视觉稿。主工作区占更大空间，侧区用于可办理待办；当有效内容宽度不足时顺序纵向排列，不保留挤窄的左右栏。

### 4.2 首屏规则

1. 月度指标集中成一条紧凑摘要，三个核心数值够用；生产目标作为计划完成率的分母/说明，减少同义指标占位。待 QA、待包装等过程数量放在对应交付明细中。
2. 核心风险默认展开，优先显示阻断生产、逾期、高优先级；每条都说明影响、负责人及可执行的下一步。超过首屏容量提供“查看全部”，不无限拉长。
3. 今日生产展示真实任务与工序，不用装饰性的产线图片替代进度。筛选作用域标在区域标题旁；月度切换不能悄悄隐藏当前跨月待办。
4. 图表只保留能帮助判断进度偏差和质量变化的内容。无真实数据时展示未接入/暂无记录，不用示例数字撑满驾驶舱。
5. 用户看到的是其权限范围；无权查看全厂数据时标明范围，隐藏不可办按钮。是否按角色调整首页重点作为推荐增强，不自动扩展业务权限。

## 5. 各类工作页面的布局

| 页面类型 | 推荐布局 | 默认可见的关键内容 | 下钻/展开内容 |
| --- | --- | --- | --- |
| **生产计划 P01/P07** | 全宽生产单列表与排程视图切换；选中生产单打开详情。排程编辑使用独立大工作区 | 型号/日期/产线筛选、生产单、工序安排、数量、齐套阻断、派工动作 | BOM 明细、采购分配、变更历史；不把长排程压在窄卡片里 |
| **现场工作台 P02** | 今日任务列表 → 当前任务 → 单一录入任务；报工和不良为两个明确动作 | 生产单/派工/工序、目标与剩余、需填数量、主提交动作 | SOP/SIP/ECN、领料明细及历史记录；打开后保留当前任务上下文 |
| **检验工作台 P03/S10** | 待检队列与选中任务详情；较窄屏幕列表和详情逐级进入 | 优先级、需求日期、来源、物料/型号、关联单据、数量和本次检验表单 | 检验依据、历史、采购原单；照片/视频在录入旁可查看，不放到页面最底部 |
| **异常工作台 P04/P08/S16** | 问题队列 → 问题详情；详情主区处理证据和结论，侧区显示责任与时限 | 来源/生产单、影响数量、状态、主经办、协同人、接收状态、当前可办动作 | 完整时间线、历史复验、库存影响；处理阶段相关信息优先展开 |
| **质量分析 S06** | 分析筛选 → 数量/质量口径 → 原因与供应商对比 → 对应异常列表 | 同期间同类物料口径、待确认根因、可下钻数据 | 个案处置在共享异常详情办理，不在图表页塞完整表单 |
| **全部任务 P06** | 全宽任务列表，按业务/经办/状态筛选；详情适度侧开或独立页 | 任务类型、关联生产单、经办、截止日、风险及下一步 | 复杂报工/检验进入专用工作区；侧栏不承载所有大表单 |
| **转产与档案 P05** | 转产办理和档案查询为不同视图；档案先搜索，再进入关系清晰的详情 | 转产条件、未闭环阻断、受控资料；档案身份和追溯节点 | 文档版本、软硬件区间、领退料/质量/发货历史按节点展开 |
| **ECN P10** | 变更摘要 → 影响范围 → 新旧对比 → 本人动作 → 执行记录 | 改了什么、影响哪些生产单、何时生效、本人是否需确认/验证 | 大图或 PDF 打开独立对比查看，表单不强行与大图挤在一行 |
| **退料 S11** | 待接收列表 → 当前退料核对；核对内容与库存影响相邻 | 生产单/领料 LOT、申请/实收数量、质量去向、确认按钮 | 原异常、照片视频、历史记录；确认前可读见库存变化 |

## 6. 允许删除、合并和替换的旧内容

| 旧内容 | 新处理方式 |
| --- | --- |
| 每页重复的出货目标/月度横条 | 集中到驾驶舱；工作页只保留相关对象摘要 |
| 静态演示图表、无来源数字、占空间的产品装饰图 | 从正式业务布局移除；所需真实能力具备后再接入对应区域 |
| 不随业务变化的流程步骤条 | 无导航/状态意义时删除；真实流程改用当前节点、待办和下一步说明 |
| 多层卡片套卡片 | 按列表、编辑、详情、辅助依据分区，减少边框和背景层级 |
| 重复标题、重复筛选、满页相同样式按钮 | 一个明确页级上下文；区域筛选标作用范围；按当前动作设置主次按钮 |
| 长期折叠的核心任务、必须展开多次才能操作的内容 | 主任务默认可见；历史、依据和低频内容按需展开 |
| 原型中的“示例人员、日期、型号” | 设计稿可明确标为示例；正式页面必须来自实际记录 |

重构不删除原有有效功能，也不以“看起来简洁”为由把所有重要信息藏到二级页面。每项隐藏必须能解释其查看频率和到达路径。

## 7. 视觉与响应式要求

默认方向为适合日常业务操作的清晰界面：信息层级明显、内容紧凑但可读、重要状态有充分对比。品牌色用于选中和主要操作，红黄绿表达业务状态并配文字；不以大面积渐变、巨大数字卡或装饰图表制造驾驶舱感。

| 屏幕/场景 | 要求 |
| --- | --- |
| 桌面 1440 宽 | 驾驶舱呈现概况、核心风险和待办；计划排程有足够横向空间；主区/侧区有明确比例 |
| 常见笔记本 1366×768 | 主任务标题、关键状态和操作可快速找到，页头和摘要不占据大半屏 |
| 平板 1024 宽 | 根据实际内容宽度决定是否保留双栏；表格/日程允许内部滚动，页面主体不横向溢出 |
| 手机 390 宽 | 现场报工、媒体登记、待办处理采用单列；列表进入详情，不把三栏缩成三条窄栏 |
| 长文本/大量记录 | 中文长名称、多个协同人、长单号、多附件不撑破布局；分页/查询范围可见 |

工具提示支持鼠标、键盘和触摸；库存值旁可看来源、更新时间和扣减项。只读文本和可编辑字段要能区分。加载、空、出错、无权限、历史缺失、保存失败及离开未保存状态必须设计，不能只交付有完整数据的一张截图。

## 8. 实施与验收方式

1. **先设计四类代表页面：**生产驾驶舱、生产计划排程、现场登记、检验工作台。使用实际字段与典型长内容，明确首屏、主操作及详情路径；布局结果可评审后再扩展。
2. **随功能整条交付：**来料闭环采用新的检验工作台；现场异常采用新的现场/异常布局。新旧入口切换保留权限、深链和必要跳转，不另造一份业务数据。
3. **检查完整任务：**从驾驶舱风险能到原单；从到货能到审批/检验；从派工能到报工/不良；从异常能到接收/复验；返回列表保留上下文。
4. **检查真实渲染：**对上述屏幕尺寸、角色和关键状态完成截图与操作验证，再做一轮集中修正。不能用“已用设计技能”或只通过构建代替视觉验收。
5. **统一其余页面：**验证后的列表、工作区、详情及档案模式覆盖全部 14 张原型对应业务。交付新旧对比截图、任务验证记录和仍受数据限制的项目。

验收重点：驾驶舱能找到最紧急问题及责任人；计划员能定位缺料和受影响工序；现场人员无需重复填生产身份；质检员能看懂检验优先级并完成记录；同一异常在不同入口布局与状态一致。

本轮仅修订需求与推荐布局方案，未生成最终高保真设计稿、未修改业务页面、未进行新的浏览器验收。实际采用 ui-skills-root 选择设计方法、Impeccable 的规划方法组织信息架构，并沿用 ponytail 的业务复用原则和 i-have-adhd 的沟通方式。
