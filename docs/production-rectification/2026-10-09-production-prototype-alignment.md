# 生产页面按原型对齐：本轮实施与取舍

日期：2026-10-09。状态：本地实现，未部署。此轮覆盖 P01、P02、P03、P04、P05、P06、P07、P08、P10 九张生产原型；P00 驾驶舱已在前轮对齐。未提供 P09，本轮也未重构 S06、S10、S11、S16 四张供应链页面。

用户明确要求剩余布局回到原型，允许移除原型外、缺乏真实数据或当前无法闭环的内容，并依据会议文本调整功能。因此，本说明替代 [10 月 8 日布局方案](2026-10-08-production-layout-redesign.md) 中自由重组“工作台”的页面组织建议；原有业务整改事项和未闭环事实继续保留。

## 1. 页面怎么找

可见模块入口由“生产工作台”改为“生产管理”，页面标题显示原型名称和 P 编号。地址及权限键继续兼容原系统，不另造业务台账。

[P00 驾驶舱前轮整改及指标边界](2026-10-09-cockpit-correction.md) 继续有效；本轮没有再次用任务工作台替代驾驶舱。

## 2. 原型和会议文本冲突时的处理

1. **业务以会议确认口径为准。** 整机完工需要性能与最终闸门通过；QA 放行单独记录。月度完工按闸门通过日期，月计划完成率按计划归属，两者不能混用。本轮普通终检合格、报工良品都没有改名成闸门完工。
2. **现场登记按简化要求。** 不增加原型中的常规尺寸必填项；使用现象选项、照片/视频及必要说明。生产单自动继承派工，数量继承原报工，已登记问题继续补在原异常。目前仍需先有包含不良数量的报工，再登记现场不良。
3. **协同范围不限研发。** P04 改为“生产问题协同”，使用原权限允许的协同人员。当前具备指定协同、回复、处置、复验；并未新增跨部门独立接单/拒收审批节点。
4. **布局沿原型、数据沿原单。** 保留原型可识别的左右分栏和核心内容；删除静态演示量、装饰图和与当前操作无关的重复摘要。SOP 日期展示真实版本登记日期，缺失时明确“历史未记录”。

核心生产上下文使用“生产单号”，内部仍以原生产批次和派工任务 ID 关联。原物料 LOT、采购批次、生产单和检验记录不会因统一显示名称而被合并为同一个编号；供应链明细的字段口径后续仍需统筹。

## 3. 仍然不能宣称闭环的地方

| 缺口 | 当前真实状态 | 后续需要补足 |
| --- | --- | --- |
| 来料“仓库 → 计划 → 质检 → 采购/生产计划” | S10 仍是现有收货检验原单；P03 尚无统一来料待检入口 | 仓库到货通知、计划确认用途/需求日/检验优先级、QC 队列、结果回流及缺口更新。计划确认不承担质量合格判定 |
| 最终闸门与月度完工 | 普通终检、报工、QA 已区分；闸门完工统计仍待接入 | 性能与闸门对象、数量/生产单归属、通过日期、重复检验与跨月统计规则 |
| 协同接收与优先级 | 可指定协同人、回复、处置并验证；已有状态和协同期限 | 独立接单/拒收、现场负责人初判、明确红黄优先级字段及可追踪流转 |
| 工序流转 | 可拆任务派到各产线、按日排程、报工和留存调整记录 | 前后工序约束、交接接收、可流转数量及必要投入产出校验 |
| 跨链追溯完整性 | P05 可查询已有批次关联的版本、作业、检验、领退料、复验与发货 | 历史数据补齐、未关联来料/采购到生产单的链路、体系要求的完整覆盖验证 |
| 四张供应链原型 | S06 来料分析、S10 收货检验、S11 退料、S16 异常详情沿用现有供应链页面与原单 | 后续按角色进入同一原单并重构布局；本轮没有完成这四张页面改造，也没有复制第二套库存/质量台账 |

这些是数据和状态流程缺口，不能通过补卡片、填演示数据或绘制流程条解决。本轮优先恢复页面对应关系和已具备能力的可操作布局，未把十四张附件全部标记完成。

## 4. 实现范围和数据保护

入口、名称和上下文由 [ProductionWorkspace.tsx](../../src/app/production/execution/ProductionWorkspace.tsx) 统一维护；P01 使用 `ProductionPlanningPage`，P02 使用 `ProductionTaskDetail`，P03 使用 `ProductionInspectionOverview`，P04/P08 使用 `ProductionQualityPage`，P06 使用 `ProductionAllTasks`，P07 使用原 `ProductionSchedule` 的原型布局，P05/P10 使用 `LifecyclePanel`。

生产局部采用原型蓝白配色、明确标题和 P 编号；共享控件、全局导航和其他模块的设计约定不重定义。响应式下双栏顺序变单列，宽表内部滚动。全局型号/计划切换清理失效的局部生产单选择；检验和全部任务进入原任务后可以返回原范围。

写入继续复用已有后端命令、权限判断、版本校验和幂等请求；不重写提交后端。无数据库迁移、无真实业务写入、无 ERP 写入、未部署。现场不良提交失败时草稿保留，重试复用原请求；质量和检验关联沿原记录，找不到指定对象时展示不可用状态，不偷偷切到第一条记录。

## 5. 本地验证与截图

类型检查已通过。前端全量回归执行 2693 项：2690 通过、2 跳过，1 项共享控件规范检查发现转产选择器使用原生 select。已改用项目 NativeSelect，相关 24 项复测全部通过；未重复执行其余已通过的长耗时检查。最终移动端样式已纳入正式构建验收。

本地 Chrome 使用隔离虚拟数据，结果记录为 **15 项交互检查通过、32 条尺寸/截图记录、0 个页面运行错误**。尺寸覆盖各原型桌面 1440 与手机 390，以及代表页面 1366、1024；并非每个页面都在四种尺寸逐一验证。主要交互包括派工与报工原弹窗、现场不良提交失败草稿和幂等重试、原检验/异常跳转与返回、协同回复、转产资料、ECN 阅读确认、未知原单、只读人员和读取失败重试。

证据：[浏览器验收结果](2026-10-09-prototype-evidence/browser-results.json)、[控件复测](2026-10-09-prototype-evidence/control-recheck.json)、[移动端已选文字复测](2026-10-09-prototype-evidence/mobile-label-recheck.json)。后两组另覆盖 6 项控件/定位检查及 2 项已选文字可见检查。截图全部为虚拟数据，不代表真实业务数量。

独立视觉复核对照九张原型和 32 张桌面/移动/代表尺寸截图；补查共享控件及移动中段后，发现移动选择器样式误伤已选文字，已修复并经两张重拍确认。最终结论为 ship，范围限本轮布局和截图可见状态，不代表所有后端链路已闭环。宽表与流程条采用局部横向滚动，页面整体未横向溢出。
