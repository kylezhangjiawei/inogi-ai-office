# 生产与质量：原型对照整改落地记录

日期：2026-10-09。范围：当前工作区，14 张原型及 4 张批注图。状态：本地代码已更新，已做隔离浏览器与受影响测试验证；未部署，未写真实数据库或 ERP。

## 一、结论

页面继续以原型的分区、主次层级和办理顺序为基础，会议纪要与用户批注优先于原图。此次没有再另起一套“生产工作台”设计。

四张批注全部落地：P01 删除近 10 天时间安排卡；P02 增加协同部门与接收人选择；S10 删除发货单号及关联异常的表单字段；P07 显示工序名称、数量和实际单位。并补齐了原料检验入口、档案遗漏、待办关联、附件视频和手机布局。

**页面可以逐项对应原型，但整条生产业务仍未全部闭环。** 来料计划确认、性能及最终闸门、返工转良入库等后端问题仍需单独补齐，不能因为页面入口已存在就判定完成。

## 三、补齐的数据与操作细节

1. 切换月份、型号、计划时，一并清空旧生产单、队列和排程选择。旧链接指定的生产单已不在范围时，可直接恢复全部生产单。修复原审计 A13。
2. 批次档案纳入“只有现场提报、尚未初检”的异常；与检验关联的同一异常只列一次。历史增加现场提报、版本范围与授权计划事件。修复原审计 A10。
3. S10 复用平台附件能力：图片 20 MB、MP4/MOV/WebM 视频 200 MB、PDF 50 MB，每批最多 20 个；保留归属、类型、大小和权限校验。旧附件失效不会阻止添加新检验照片，旧快照仍保留。
4. 现场提报更换协同部门会清空旧接收人；接收人必须匹配部门及办理权限。建议协同不会悄悄变为正式分派。
5. P03 检验弹窗独立滚动表单与错误区，底部按钮不再遮挡必填内容；P04/P08 手机流程条完整换行；S11 手机不再将退料类型和状态藏在宽表格外；P10 文档按钮保持单行，长文件名自行换行。

## 四、仍未闭环，不能按“已实现”验收

以下沿用[上一轮闭环审计](E:/workCoding/inogi-ai-office/docs/production-rectification/2026-10-09-production-closure-audit.md)的编号。本轮没有用样式调整掩盖这些问题。

| 问题 | 本轮后的实际状态 / 必要后续 |
|---|---|
| A01 完工与 QA 口径 | 页面不冒充闸门完工，但后台仍以普通终检计算部分完工/QA 条件。需建立性能与最终闸门记录、通过日期，QA 独立记录 |
| A02 必要工序与前置关系 | 当前只是按工序派工显示，尚无必做/可选及前置工序校验；需防止工序未完成就放行 |
| A03 报废后的补产/短结 | 保留原数量保护，仍缺经批准补产或取消剩余量路径 |
| A04 跨检验重复不良 | 本轮修复档案展示去重，不等于解决同一实物跨过程检/终检重复建异常；需原异常沿用机制 |
| A05 来料复验转良 | 异常验证通过尚未自动恢复采购合格可入库量；需联动履约与入库 |
| A06 后续检验新增不良 | 原批次已有处置时，新增不良仍可能受原记录约束；需按新增量独立衔接 |
| A07 已确认退料后新增不良 | 原退料完成后缺后续差额退料路径 |
| A08 ECN 与放行/发货 | 未完成的 ECN 执行问题尚未完整约束旧 QA 放行及发货 |
| A09 ECN 改派 | 负责人调整后的责任与确认恢复仍需补齐 |
| A11 无实体用料工序 | 软件/测试等无物料工序仍可能被创建校验阻挡 |
| A12 改产线后的历史 | 历史报工的产线归属快照仍待修复，避免调整后改写历史归属 |

另外，会议提出的“仓库到货通知 → 计划员确认用途/日期/优先级 → QC”尚未建立完整审批数据链；单机 SN、整批包装进度、报工前独立不良提报及部门接收/拒收也没有在本轮冒充完成。

建议下一轮先补 A01/A02、来料计划确认、A05–A07，再做补产短结及其余历史/变更恢复；不需要先扩展自动排产或 AI 根因能力。
