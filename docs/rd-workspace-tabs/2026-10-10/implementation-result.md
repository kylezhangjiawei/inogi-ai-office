# 研发工作台入口与任务操作调整验收

日期：2026-10-10。状态：本地完成，未部署。

## 本次范围

按已确认方案，取消研发工作台任务抽屉重复的五个页签，保留主责/协助筛选。详情与讨论交由现有任务详情页面承接，进度、协作、完成使用独立操作抽屉，不重写后端业务流程。

| 原入口 | 调整后的入口与承接 |
| --- | --- |
| 点击卡片 / 查看任务 / 任务详情 Tab | 直接进入正式任务详情页 |
| 任务讨论 Tab | 卡片“讨论”，直达正式详情的讨论区 |
| 更新进度 Tab | 卡片“更新进度”，独立表单 |
| 移交协作 Tab | 卡片“移交协作”，独立表单 |
| 标记完成 Tab | 卡片“标记完成”，沿用原校验和提交逻辑 |
| 原详情中的专有维护操作 | 更多操作→任务设置，保留截止日期、进展附件维护、子任务关系、历史申请应用 |

主责/协助、关键字、优先级、状态和时间筛选写入研发工作台 URL，从详情返回与浏览器后退均可恢复。通知的普通查看入口统一分派；提及通知仍保留专用讨论链接和锚点。

## 保留的业务边界

- 完成任务隐藏进度、协作和完成快捷按钮；历史待审变更仍可从任务设置处理。
- 转采购、申请放弃保留原门控及表单，普通参与人的原有操作权限不改成管理权限。
- 跨工作区任务沿用各自的详情路径。中美协同与生产共享组件保留原操作方式，工作项仍仅在中美协同开启。
- 样品测试保持原独立流程；手机样品测试专用页优先级不变。
- 手机研发工作台使用已有响应式布局；详情继续通过实际移动详情组件承接，跳转保留来源与筛选。

## 验证结果

1. 研发入口、详情返回、筛选、采购入口、直接变更、评论与样品等合并回归 81/81 通过，见 [tests-final.log](./tests-final.log)。
2. 手机路由与工作区相关检查 37/37 通过（与上一组有重叠，不相加）。包含真实 ProtectedLayout 条件执行、样品优先、自定义路径、相似路径和协同隔离。
3. 隔离 Chrome：27 项组件交互、7 项设置操作保留检查、4 项按实际路由进行的手机详情/讨论/返回检查通过。已人工查看桌面与 390px 截图，见 [浏览器验收汇总](./after/QA-summary.md)。
4. `npm run typecheck`、`npm run build` 通过；本轮修改文件 `git diff --check` 通过。

浏览器使用实际产品组件与虚拟接口，所有业务写请求被阻断；验证的是入口、表单、权限呈现、路由和既有业务处理函数，不代表真实后端端到端写入验收或上线成功。没有修改数据库、ERP 或部署环境。

早期隔离预览在 390px 直接渲染桌面详情，曾观察到讨论区不在首屏；按实际 App 规则改为移动详情承接后复验正常，已撤销此发现，没有为错误预览新增产品滚动行为。

- `src/app/RDMyWorkspacePage.tsx`：卡片入口、独立操作抽屉、任务设置、筛选与通知分派。
