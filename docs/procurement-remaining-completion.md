## S02 草稿

草稿用本设备浏览器的 IndexedDB 存储，键含任务、账号和工作区；新增附件保存 File 内容，研发附件只保存选择标识，恢复时重新检查当前可见版本，不保存临时签名地址。新增附件总计上限 50 MB；不支持或存储失败会明确报错，不把请求成功当作事务已经提交。

草稿保存/清理按范围串行。主提交和显式草稿保存共用即时互斥，避免保存完成时关闭正在提交的窗口；自动保存先前排队的写入不能让成功提交或明确放弃的旧草稿复活。未知/损坏旧稿加载失败时禁止自动覆盖，用户可明确清除后重新填写。恢复既有稿需要确认覆盖当前填写。账号、工作区或任务变化会重挂整个表单，旧异步回调不能更新新范围。

草稿属于本设备，不跨浏览器/设备同步；浏览器清理站点数据也会清除草稿。

## S07 分派和数量

分派记录使用既有 RuntimeState，原订单行/收货 ID 为业务来源，包含稳定人员 ID、截止日、原因、版本、操作人、时间及完整交接历史；原收货/检验登记人不是任务负责人。候选人必须为启用且具备对应岗位操作权限的账号，同名人员按 ID 区分。

团队查看要求采购管理与订单详情权限，分派另需 `proc-operations:assign`；普通人员服务端强制查询本人，不能用 owner 参数请求其他人。本人页面仅展示自己的任务和分派记录。仓管待交数使用 S14 净履约数量；质量待判量只按当前收货批次的有效净判定计算，ERP 关单和其他批次异常不会抹掉本批真实待检量。无可靠依据显示待核对，不显示假零。

本人入口为供应链菜单的「我的仓管与质量任务」（`/proc-operational-tasks`），要求订单详情权限，同时具备收货、检验或采购驾驶舱权限之一；直接访问与导航使用相同组合条件。本人模式即使由管理人员打开，也按本人查询并隐藏团队分派和其他负责人选项；质量专岗默认进入质量待检验。团队管理入口仍保留原驾驶舱权限。手机菜单沿用共用导航筛选，岗位页保留原地址，不转到研发移动驾驶舱；固定入口不随订单详情的配置路径变化。新增入口与组合权限用例 6 项通过，连同手机样品及导航相邻回归共 16 项通过，记录在 `artifacts/qa/remaining-completion/s07-personal-entry-after.txt`。

原业务持续变化后刷新得到完成情况。按稳定 ID 连续分页，不以首 25 项冒充全部；跨月提醒独立于主列表完成状态，超过本页明确显示加号。

## 权限和部署

新增动作：`proc-operations:assign`、`proc-purchase-order:record-commitment`、`proc-purchase-order:adjust-fulfillment`、`proc-purchase-order:approve-fulfillment`。已注册目录和服务端守卫，未自动给任何真实账号扩大权限。本轮复用既有 RuntimeState 和 ProcTask.metadata，不新增数据库迁移。

交期和履约历史从实际保存/同步观察开始记录。系统过去没有保存的原承诺、轮次或实际时间不会补造。ERP 保持只读，本地台账不会擅自更新 ERP 库存/数量；ERP 与本地记录不确定是否重叠时要求覆盖确认，避免双计。

本轮没有部署、操作真实订单、修改真实角色或发送业务通知。上线仍需在目标环境发布接口/前端、配置角色，并对真实数据和跨模块流程做业务验收；生产及仓库演示页的数据接通属于此前明确区分的后续阶段。
