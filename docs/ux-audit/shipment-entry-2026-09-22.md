## 全量测试限制

本次 npm test 的前端脚本阶段 2455 项：2427 通过、28 失败；串联的全量 API 测试因此未执行。28 个失败名称与上一轮库存盘点任务留下的测试日志一致（不是干净基线对比），没有据此宣称项目全绿。未为清除此类失败扩大修改范围。

失败清单：

- 业务页面的基础交互控件统一经由项目 UI 库渲染
- failed frozen dependency installation blocks release instead of falling back
- real catalog groups control navigation order independently of cross-group entries and aggregate aliases
- 供应链导航保留独立权限与路径，所有角色均移除仓管质量任务入口
- 缺任一权限前提时菜单隐藏，既有知识库任一权限规则保留
- 个人工作台支持搜索、月份入口、任务列表和可恢复空态
- 采购驾驶舱保留研发式任务卡，个人工作台使用紧凑任务行与右侧详情
- 通用物料新建提交清理后的名称、编码和四位小数用量，不携带旧记录ID或版本
- 通用物料编辑保留来源原始用量与精确版本，不改写成齐套列表汇总数量
- 多来源汇总必须明确选择一个来源，只提交选中的原始用量、ID与版本
- 切换物料来源重新带入该来源字段，不把前一来源草稿写到另一条记录
- 删除多来源物料时只删除明确选中的叶子ID并携带它的版本
- 通用物料保存双击只有一个请求，等待期间阻止取消、Escape和点外部关闭
- 通用物料删除双击只有一次精确删除，等待期间不能切换被删来源
- 通用物料保存失败保留修改后的输入和来源版本，可重试且成功前不关闭
- 通用物料编辑器销毁后，保存或删除的迟到响应不再关闭页面或触发刷新
- 通用物料非法用量在提交位置报错，不发起保存请求
- 物料分类只读并按去空白后的编码延迟读取，不把 BOM 位置当成分类
- 更改编码立即移除旧分类，取消旧查询并忽略乱序返回
- 未匹配物料库明确提示，不回退到旧分类或 BOM 所属位置
- 分类读取失败显示原因并允许重试，同编码重试成功后仍保留编辑草稿
- 新建和编辑仅保存 BOM 位置 parentId，不把查询出的分类或单位写入 BOM
- 未选择来源和删除流程不查询分类，编辑器销毁取消延迟及在途分类查询
- 个人工作台右侧只绑定本人任务，回退和日志仍路由到同一详情抽屉
- procurement workspace keeps task arrivals as the only arrival entry
- 驾驶舱抽屉展开完整详情并返回后保留负责人、搜索与统计筛选
- S01 和采购驾驶舱各栏目在窄屏保留原页面，登录保护和其他工作区规则继续生效
- 真实移动守卫把自定义协同页转到协同移动页，恢复宽屏仍回配置后的驾驶舱
