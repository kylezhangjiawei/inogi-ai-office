# 关键物料首版闭环验收 · 2026-09-22

## 本轮范围

采用“先减法、每项可闭环”的首版：正式物料目录 → 按计划核对剩余需求及日期缺口 → 原单办理后手动刷新。
不新增采购下单、收货或质量处理流程；不做自动采购建议、风险评分、识别和自动派任务。不部署，不迁移数据库，不改业务记录。

## 实现与边界

1. **正式目录**：从现有物料库选择有正式编码的物料；可纳入、退出和恢复，必填依据。记录操作人、时间、版本及历史，并写审计。同一请求幂等，过期版本拒绝保存，失败保留草稿。
   - 复用现有 runtimeState/映射事务，正式范围使用独立的 `material:<materialId>` 标识，不创建物料主档。
   - 原会议映射及其历史保留在“资料核对”；未设置独立范围的旧条目沿用当前已核对映射。显式退出优先于旧映射，不因旧映射自动恢复。
   - 正式目录的当前纳入物料不因无本月需求或零库存消失；已退出单独筛选，恢复后重新参与月度跟踪。
   - 页面查看权限与物料审核权限均由后端校验。没有审核权限只读历史。
2. **月度跟踪**：复用正式生产计划的冻结 BOM 和 ProductionReadinessService，展示计划总需求、剩余需求、日期内采购及缺口，保留产品 ID、型号和日期范围。
   - 无正式计划为待核对；已有正式计划但本物料无匹配需求，不伪装为缺数据；未知数量不显示成零。
   - 各计划独立展示，不相加不同单位或计划的数量。同料多计划的共享采购沿用原分配台账。
   - 共享仓库余量未充分分配且会影响判断时不宣称覆盖；已有分配足够时可覆盖，仓库净可用已全部分配但仍不足时展示真实缺口。整月识别已分配给下属批次的库存，数量比较使用 Decimal。
   - 物料主档与 BOM 单位冲突、重复正式编码显示待核对。
3. **原单反馈**：保留原物料、订单行、采购任务和质量记录入口；原计划直接进入“齐套与占用”，携带原需求日期。原单业务权限与校验不变。
   - 页面说明办理后手动刷新，展示最近读取时间，刷新不丢月份/产品/筛选。
   - 订单分配释放、原单数量/日期/来源变更后，重新读取及核算；失效供给不继续算覆盖。
   - 质量关闭仅移出未闭环异常，不能把库存变成可用；质量重开后重新出现在异常列表。

## 验证结果

- 前端相关测试 44/44：正式范围/权限、筛选与来源保留、剩余需求、真实原单链接、刷新风险、保存失败草稿、幂等重试、版本重核，以及现有预览页和分配入口回归。
- 后端相关测试 35/35：纳入退出恢复/历史/权限/版本、共享库存边界、质量关闭及重开、原单供给分配、释放及来源变化。
- 新增看板与真实齐套服务联动测试：同一 60 件采购分给两个计划 40/20，看板分别计入；释放后归零；原单变化后旧分配失效。使用内存隔离数据，未调用业务数据库写入。
- `npm run typecheck`、前端生产构建、API 构建通过。
- 浏览器验证本地正式路由：物料库搜索、选择、最新范围/历史读取；目录/月度/详情；原计划新标签页实际进入同一计划和需求日；桌面与 390×844 窄屏。窄屏页面宽度与 scrollWidth 均为 390；弹窗可操作；控制台无错误。
- 本地浏览器现有数据标记为“演示”，本轮没有提交纳入、退出、库存或采购等业务变更。真实业务数据的写入验收、线上发布尚未执行。
- 本轮运行上述相关回归，未重新宣称全仓测试通过。

## 交付说明

采用 ponytail 复用已有接口与事务；baseline-ui 保持现有表格、标签和弹窗规范；i-have-adhd 用于沟通；浏览器用于真实渲染与只读交互验收。
首版操作入口为：供应链管理 → 全部关键物料 → 全量目录 / 月度跟踪 / 资料核对。
