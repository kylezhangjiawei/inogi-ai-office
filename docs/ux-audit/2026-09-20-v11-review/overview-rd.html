优先处理的偏差

OR01 · 高：G00 的实际职责与原型不同，缺公司交付风险总入口

需求依据：说明 L151、L153、L155、L157。原型要求部门交付风险、当前经办/期限、原任务跳转；同一异常跨部门只计一次，各指标保留单位和分母。

实际证据：dashboardApi.ts:10 限定数据源；L75 只按权限加载研发个人工作台、issue-ai、费用、订单，没有月份/产品条件和生产、齐套、质量数据。首页指标为今日待办、已闭环记录、模块加载数 Dashboard.tsx:526，业务状态图来自问题或订单 L368。这些是有效办公聚合，但不能作为 G00 交付总览已实现的证据。

影响：管理层不能在统一月份/产品范围回答“哪个原问题影响本月交付、现在由谁处理、何时到期”；同号质量异常与跨部门协同的去重汇总也没有在这里实现。不是已确认发生重复计数，而是缺该汇总及其去重链路。

建议验收：保留现有个人聚合的价值，在明确的管理入口按月份/产品汇总正式来源。用一个跨部门原异常和两个不同单位的业务指标验证：异常计一次；每个指标可追到来源和分母；点击进入原记录；切月保留跨月未闭环风险；无权限不泄露，无来源显示待接入/待确认。无需增加多份并行问题记录。

OR02 · 高：R01 缺“原生产问题 / 适用 ECN”的结构化关联与导航

需求依据：说明 L179“统一…生产协同的关联入口”、L183“查看生产转研发问题 P04；查看适用 ECN”。PNG 也直接展示原生产问题编号及关联操作。

实际证据：R01 操作区提供同步、转采购、生成问题；handleGenerateIssue 调用 issueService.create 后跳 /issue-ai?issue=… RDTaskDetailPage.tsx:1146，属于新建记录。同步数据是 source_task_id/root_source_task_id/read_only: true 镜像 production-task-sync.ts:6、L46。生产质量协同使用原 qualityId 保存经办与回复 production-execution.service.ts:170，ECN 使用 packageId/batchIds/effectiveDate production-lifecycle.service.ts:14、L109。以上结构未提供 R01 按研发任务解析原生产异常或适用 ECN 的关联字段/查询，R01 也没有读取它们。

影响：研发人员能接收一般任务与新建问题，但无法从该任务确认自己正在处理哪张生产原异常、哪批适用哪项 ECN；容易依赖手工文字查找，不能闭合原型的跨部门回路。

建议验收：在详情关联区复用原异常/ECN 的真实 ID 与权限范围，显示原编号、经办/截止、关联批次和状态，点击返回原记录。同一异常回复后保持原编号且不新增不良量；无关联是明确空态，不凭物料同名推测。ECN 应按实际关联批次/生效条件筛选，不把最新变更自动套到所有历史任务。对应生产 P04/P07 的缺口见 production-p00-p10.md。

OR03 · 中：R00 缺卡片级确认版本与关联采购/样品记录提示

需求依据：R00 PNG 的当前资料版本、关联业务提示；说明 L167 的资料与进度依据、L169 的采购需求入口。当前卡片的标题/状态、主责/期限、附件/摘要和进度都是真实实现，不能整体判为缺卡片信息。

实际证据：卡片附件来自普通附件预览 RDTaskManagementPage.tsx:7754；内容与操作结束于 L8142，没有技术资料当前版本标识或已关联采购/样品入口。更多菜单已有查看任务、全部附件、生产镜像同步、转派/删除。采购与样品能力在 R01 已接通，不应再次开发一套流程。

边界：新个人工作台 /rd-my-workspace 已有 RdProcurementProgressEntry RDMyWorkspacePage.tsx:4082 与原地采购进度弹窗 L5689。这是另一个正式入口，不能据此把 R00 任务驾驶舱的卡片关联缺口划为完成。

建议验收：批量读取卡片所需的确认版本和关联采购摘要，区分“未登记版本”“无关联”“读取失败”；按权限在卡片进入现有详情 Tab/只读进度弹窗。未转采购任务由现有流程显式提交；不拿最新附件名猜版本，不把生产镜像同步误称为生产执行状态。

OR04 · 中：G00 / R00 没有保留业务范围的“全部关键物件”入口

需求依据：说明 L155、L169 明确从两页进入 S18，并“沿用当前月份、产品与权限范围”。

实际证据：正式 S18 路由已存在，/proc-key-materials → KeyMaterialsPage App.tsx:583。但 G00 的快捷入口集合 Dashboard.tsx:98 与研发主卡片/工具入口未引用该页面；本次按路径、名称和组件查找未找到两页携带月份/产品上下文进入 S18 的动作。侧栏全局入口不等于上下文衔接。

影响及验收：用户需重新定位产品/月份才能判断关键物件对当前任务的影响。补充一处轻量关联动作即可；有产品/月条件时保留，当前页没有该条件时应明确默认值；沿用权限裁剪，目录中无当前需求的物件仍可通过全量视图查看。S18 自身的数据语义由供应链分报告评价。

已实现，不能因样例无数据而判缺

  1. R01 技术资料不是纯附件占位。 图纸/规格/BOM/验证/其他分类、选中原件预览、版本标识、变更原因、版本历史与历史原文件均已实现 TechnicalDocumentsPanel.tsx:260、L280。上传仅新增留痕附件，还要求用户确认类别/版本/说明 L210、L300，不会因上传自动完成任务。
  2. 后端有真实版本与并发保护。 读取按任务权限；确认按写权限和附件来源校验；保存新版本、前版本 ID 和变更原因，条件更新当前版本指针并写审计 rd-technical-documents.service.ts:83、L145。这不是只在 UI 上展示一个“版本”字段。
  3. 采购交付保留明确选择的研发版本。 后端按任务解析版本 ID rd-technical-documents.service.ts:178，采购端解析原版本并建立交付快照 procurement.service.ts:1155。详情说明并展示本次/历史交付文件与版本 rdInsertion.tsx:184，不能把研发后续换版覆盖旧交付的风险当成已确认缺陷。生产批次受控资料的缺口另见生产报告，不能外推为研发资料历史未做。
  4. 样品本人确认入口已接入。 详情采购 Tab 复用 ProcurementActivitySection，真实显示样品测试人、状态、备注、本人确认日期；指定测试人和相关权限决定“填写测试结论 / 查看样品记录”入口 rdInsertion.tsx:149、L177。不因用户在某条任务看不到按钮而直接判缺，应先核对样品关联和身份。
