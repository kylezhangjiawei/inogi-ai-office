# F03：采购决策与净新增需求

已在个人工作台所选任务的右侧详情，以及完整采购详情「采购与到货」页签中复用同一「净采购决策」组件。列表不为每个任务请求决策，也不增加重复的数据列。

## 页面与数据依据

首先选择正式计划、批次（可选整月）和需求日期，再显示四项：当前缺料、本任务未验收、按期可覆盖、建议新增采购。详细公式、计划版本、库存待回写扣减、其他计划占用和本任务订单验收情况默认收起。

候选严格来自任务正式产品 ID 与关联物料 T+ 编码共同匹配的生产计划；同名物料不混用，不自动选择第一个计划。没有物料码、没有匹配计划、日期缺失或来源异常时，数量保持「待核对」，不把任务需求量冒充当前缺料。

计算复用 ProductionReadinessService 的正式计划/批次结果：

- 当前缺料 = max(计划剩余物料需求 − 当前可用, 0)。
- 按期可覆盖 = min(当前缺料, 本范围按期有效采购覆盖)。
- 建议新增 = max(当前缺料 − 按期可覆盖, 0)。
- 本任务未验收 = 本任务关联真实订单净订购 − 已确认合格数量。它与计划级覆盖的范围不同，页面明确标注；收货 60、合格 56、不良 4 时，仍有 4 件未验收。

readiness 继续负责冻结库存、待回写出库、其他计划占用、共享订单分配、检验可用日期与最新供应商改期。订单数量从真实镜像行与履约状态计算；旧关联没有原始 ID/行号、重复镜像、单位冲突、ERP 与本地收货覆盖未确认时，不猜测未验收量。

## 权限与读取边界

先调用既有 `getTask(id, actor)` 验证任务访问范围，再读取匹配计划。客户端指定无关产品计划或其他计划批次会被拒绝。返回仅有当前物料的计划聚合、候选摘要和当前任务订单数量，不返回其他采购任务、价格、完整 BOM 或生产任务明细。读取使用可重复读事务，不写业务状态，不创建采购订单。

前端在账号、任务或选择范围切换时隐藏旧结果并取消旧请求；刷新失败保留错误与重试入口，旧金额不会继续作为有效结果显示。
