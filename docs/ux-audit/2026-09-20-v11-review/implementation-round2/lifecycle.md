# 第二轮：受控转产、ECN 执行反馈与批次版本范围

对应主报告 F08、F15。依据原开发说明 P05/P09/P10 及“附件存文件 ID 与版本引用”“批内不同版本按适用数量／范围记录”“已有 SN 关联”“已读不等于验证”规则实施。

## 已完成

- 新转量产资料从原样品采购任务已交付快照选择 SOP、SIP、图纸 / BOM 的真实受控版本。服务端交叉核对研发任务、documentId、versionId、attachmentId，客户端文件名、版本标签和 fileId 不能伪造覆盖。可找到 FileAsset 时补充真实 fileId；旧附件仍沿原 attachmentId/版本引用，不造新文件 ID。
- 独立验证及新发布均检查固定文件可用，已停用文件拒绝发布。原样品轮次、测试通过、结束／确认时间、非编制人独立验证等门禁保留。旧文字依据继续展示；旧未发布资料缺受控引用时须新建版本，不默认为已补齐。
- 派工快照包含受控文件引用；已冻结资料不随新版本覆盖。新增按计划和可见批次授权的文件预览接口，使用原 OSS 签名及内嵌受控文件预览能力，可续签，不能仅凭任意版本 ID 获取文件。
- ECN 详情展示原已冻结／生效资料及替代资料、阅读人员与时间。原资料没有真实记录时明确未知，不推断成最新版。
- “无法执行”沿原 ECN 保存问题、报告人、当前经办、处理期限及状态。当前经办或转产管理人员可处理、转交、重新打开，每次操作追加历史；不建立第二个不良数量。经办候选为可访问该生产计划的在职人员。未解决反馈阻止后续适用批次派工，已读不能消除阻碍。
- 批次档案新增“版本与 SN”：按段保存软件／硬件版本、适用数量／范围、已有 SN、登记人和依据。未知版本、未采集 SN 明确待补；版本登记数量合计不能超过批次数量，SN 数量不能超过本段数量，同计划有效范围内 SN 不得重复。更正追加新记录并保留旧记录，发布文件新版本不会改写历史实际范围。
- 批次目录可按已有 SN／版本检索；档案 JSON 导出保留范围与更正历史。原详情 URL、列表筛选、返回上下文和既有放行／发货动作继续保留。
- 与执行端新过程检模型衔接：过程检不计整机检验完成，不据此放行；终检和兼容历史检验按 `completionInspections` 口径统计。

## 边界与待现场验证

- 真实文件需要先在研发侧确认并交付到样品采购任务。本轮不会把旧自由文字自动转为“已验证文件”，也不会为缺附件演示资料伪造 ID。
- 本轮实现原 ECN 内的协同处理队列；未新增供应商外部通知、全站消息分发或跨菜单待办聚合。无生产计划读取权限的采购人员需先按现有权限配置授权，不能通过指派绕过权限。
- 已有 SN 为人工关联的真实已知标识；没有新增扫码、自动编号或接入未提供的企业 SN 主数据。自由文字范围由登记人确认，服务端校验适用数量与已知 SN，不宣称逐台追溯完整。
- 未解决反馈拦住新的派工／调整校验；不会偷偷改写或取消已执行作业的历史依据。
- 浏览器由主代理统一验证，本子任务未操作浏览器。真实 PostgreSQL 并发、实际 OSS 文件及普通现场账号仍需独立环境验证。

## F15 补充：单次实际发货与已有 SN 对应

已补齐审核中“发货 20 台关联已有 12 个号码，剩余 8 台待补”的独立验收项。批次拥有 SN 不再被当作某张发货单已经关联了这些实物。

- 每张发货单保存明确选择的 `serials` 子集，包括已有号码、原版本范围 ID、关联时的软件与硬件版本。接口分别返回 `linkedSerialQty`、`pendingSerialQty`；旧发货没有关联记录时全部为待补，不自动选取批次号码、不生成 SN。
- 登记实际发货可以填写已有 SN 子集；发货详情提供“补录实发 SN”弹窗，从本批次当前有效、尚未用于有效发货的已有 SN 中搜索选择，并填写实发清单依据。补录只能追加关联，不修改原实发数量、日期或凭证。错误关联须按原有凭证冲销流程处理。
- 服务端校验号码属于本批次有效版本范围，清单内不得重复，累计关联不得超过本单实发数量。大小写和全半角统一比较；对不同发货单及不同计划使用同一 SN 的情况，由独立 RuntimeState 占用记录阻止重复。唯一键、Serializable 事务和 CAS 将号码占用、原发货事实、历史、审计与幂等请求一起保存。
- 冲销仅释放原单持有的 SN 占用，保留原号码、版本快照和冲销依据；其他有效单据占用不受影响。实物退回且凭证冲销后，可以在后续真实发货中重新关联原号码。
- 批次版本可以更正并保留历史，但不能移除有效发货单正在使用的 SN。多次范围更正仍执行该限制；发货当时的版本快照不会被后续版本覆盖，后补号码保存补录时核对的版本。
- 发货详情按“原单实发数量 / 本单已关联 SN / 本单 SN 待补”展示，再单独列出 SN 和版本，关联历史收起展示。已冲销单明确标注原 SN 已随单冲销。发货目录可以检索 SN，详情返回继续保留原列表上下文。

新增文件：`production-shipment-serials.ts`、`LifecycleShipmentSerials.tsx`、`ShipmentSerialDialog.tsx`，扩展既有 lifecycle service / API / panel。沿现有生命周期命令增加 `bind-shipment-sns`，要求 `production:ship`；没有新增权限旁路或独立假数据页面，也不需要新的 provider 或数据库迁移。
