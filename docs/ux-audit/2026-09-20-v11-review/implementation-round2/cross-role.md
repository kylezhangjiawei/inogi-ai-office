# F09 同人跨岗位待办与原记录链路

新增首页“跨岗位待办”（?home=tasks）。原管理总览/我的办公默认行为不变，无生产权限用户仍默认我的办公。新视图不建立第二套任务，只读聚合本人原单：

- 现场派工/执行与跨月未完：复用 ProductionExecutionService.list，限定当前任务负责人。
- 原生产质量协同与回复返回后的待复验处理：读取 inspections + fieldIssues 上同一个 qualityId，按原协同当前 ownerId 归属，去重并展示 dueDate、requiredInfo、verificationPlan。
- 适用本人批次的未读 ECN 和当前经办的未解决执行反馈，使用原 ECN 编号、期限及反馈问题。
- 指定本人测试且未提交结论的样品，读取原 sampleTest 轮次。
- 本人仓管/来料检验：复用 OperationalTasksService，显式 owner=actor.id，并跟随其游标至结束，不截断25条。

列表有类型/关键词筛选、分页、读取时间和逐来源失败提示。切用户或权限立即隔离旧数据，取消旧请求，晚到响应不能覆盖新范围。

待办列表显示可读业务信息：样品显示“当前样品测试轮次”，不展示内部轮次 UUID；质量项使用关联生产批次的真实 code，缺批次资料时使用原作业名称。具体异常编号仍在原详情保留。

研发采购进度增加相关原采购、ECN、生产质量记录链接：先调用原 requireTaskReadAccess，再沿采购任务ID→已确认转产包→实际生产依据/ECN找到真实原单。原采购链接必须有全量或本人采购读权限；生产沿原 lifecycle.read 可见范围；质量再次沿 assertQualityRead 校验。普通研发不因为此入口获得生产/报价权限。未知或无关联不猜ID。

生产代理已支持 quality=原质量ID 深链：仅打开当前records内实际记录，关闭只删除quality参数，保留计划、月份、视图。ECN反馈参与范围亦与原生命周期读取范围对齐。
