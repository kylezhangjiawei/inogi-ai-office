### F01 · 共享采购供给分配

**已实现：** 按真实订单行与计划 / 批次保存分配和释放，其他范围分配不再重复计入；同料多计划必须明确分配。仅单一正式计划、未建立分配台账时保留旧兼容口径。部分收货、订单数量 / 日期、来源或计划依据变化会使原确认失效，需重新核对；允许释放失效分配，保留版本、幂等和历史快照。

**入口：** 生产计划详情 → 齐套与占用 → 物料“查看依据” → 分配 / 释放采购；`/production-execution?plan=<计划ID>&view=readiness`。

**证据：** `readiness-purchase-allocation.spec.ts` 覆盖唯一 60 分给两计划 40 / 20、上限、释放、重复提交、单计划转多计划、收货后净剩余、来源改变与冲突；与交期 / 决策 / 规划的[独立复核](planning-independent-review.md)共 59 项通过。

**待验证：** 真实 PostgreSQL 双连接竞争与事务回滚未执行；真实收货转现货、ERP 来源更换的完整业务链仍需隔离数据验收。没有新增自动最优分配算法。

### F02 · 管理总览与交付风险

**已实现：** 首页保留“我的办公”，生产全量岗位默认管理视图；授权供应链 / 质量岗位可切管理视图且办公仍为默认。正式生产目标、发货与完成逐产品呈现。风险队列除原生产质量、ECN、齐套和作业逾期外，已纳入独立逾期采购、有效未收逾期订单及四来源未闭环质量，按真实原单去重；各来源独立鉴权，不把所有未完成事项当风险。无生产权限不显示生产数字，读取失败不变成零风险。

**入口：** `/?home=management&month=2026-09` 或生产总览 `/production-dashboard` → 交付风险与齐套；产品参数 `riskProduct` 只控制该区域，月度指标与计划列表的范围另行标明。

**证据：** 风险服务新增 10 项、UI 新增 3 项；与规划 / 交期 / 质量联合后端 69 项、前端 28 项通过。覆盖源级权限、精确原行去重、承诺撤销、无归属订单、跨月、产品 ID、原质量弹窗及请求竞态。[风险来源说明](planning.md)

**仍有限定：** 生产指标仍只计正式生产；风险是授权的已接入原单范围，并非全公司所有潜在风险。独立订单没有可信产品归属时仅列在“全部产品”；无约定期限 / 无已登记异常不能推断为风险。历史月份展示对应日期范围内当前仍未闭环事项，不恢复历史状态快照；外部工单实时状态与在岗指标没有伪填。

### F03 · 净采购决策

**已实现：** 选定真实计划、批次和需求日期后，显示当前缺料、本任务未验收、按期可覆盖和建议新增采购；下方可展开计算依据。候选同时匹配正式产品 ID 与物料编码，不自动选择第一个计划；未知来源保持待核对。收货 60、合格 56、不良 4 时，本任务未验收仍为 4。

**入口：** 个人工作台 → 选中任务 → 右侧“净采购决策”；采购完整详情 → 采购与到货 → 同一组件。

**证据：** 决策服务 11 项、实际组件处理器 6 项通过，包含缺 60 / 按期覆盖 60 → 新增 0，20 晚到 → 新增 20，以及单位、权限、来源和请求竞态。[详细说明](decision.md)

**范围：** 决策集中在详情按需读取，未给任务表逐行增加实时净缺料列，也未自动生成采购单。真实 ERP 验收覆盖仍需人工核对。

### F04 · 正式质量分析与四来源闭环

**已实现：** 沿唯一原异常增加主因待分析 / 授权确认、独立责任认定、现象次数、证据和采购 / 生产 / 仓库 / 售后来源引用。6 件不良与 8 次现象分开；未知主因独列。列表可筛选、分页、看高频现象和同物料同单位的供应商记录比较；原处置与独立复验保留。

**入口：** 供应链子系统 → 生产与质量 → 质量异常；生产计划 → 质量闭环；`/production-execution?plan=<计划ID>&view=quality&quality=<原异常ID>`。

**证据：** [质量模块记录](quality.md)列出后端 71 项、前端 38 项联合回归，覆盖 6 件 / 8 次、授权确认、真实附件、双版本冲突、同号复验与四来源。

**边界：** 四来源文字引用不冒充外部系统已验证链接；供应商比较只覆盖已登记检验记录，不等于全部交付合格率。真实文件存储、普通角色和跨部门处理仍需现场联调。

### F05 · 过程检、终检与首次终检口径

**已实现：** 新检验明确过程检 / 终检、工序和 SIP 依据；原派工版本优先冻结。旧记录标历史未分类，不能自动改成终检。过程检不计整机完成；首次终检不被复验改写。检验列表与详情支持日期、类型、搜索、分页和固定版本预览。

**入口：** 生产计划 → 生产检验；`?plan=<计划ID>&view=inspections`；作业详情 → 登记检验。

**证据：** 生产执行服务与页面测试覆盖 47 / 50 = 94%，复验后仍保持 94%；过程检容量、历史兼容和 SIP 防篡改。[生产说明](production.md)

**待验证：** 历史未分类记录仍单列兼容，不代表历史数据已由业务补分类。真实工序、SIP 文件和普通检验角色验收尚未完成。

### F06 · 原作业调整、日程与批次齐套

**已实现：** 原号调整日期、产线、负责人、数量，保留已发 / 已签 / 已报 / 检验与冻结依据；领料需求同事务更新并双版本核对。按日 / 产线矩阵支持负责人、产线、批次与日期范围筛选。齐套可选择整月或具体批次，批次库存及采购必须明确分配，历史快照按原范围读取。

**入口：** 生产计划 → 日程 → 作业详情 → 调整；齐套与占用 → 计算范围。URL 使用 `view=schedule` / `view=readiness` 与 `readinessBatch=<批次ID>`。

**证据：** 生产页面 27 项与执行 / 仓库联合行为测试；采购分配测试覆盖月度 / 兄弟批次不双占、历史快照范围拒绝。[生产](production.md)、[规划复核](planning-independent-review.md)

**范围：** 调整日期限计划月初至原批次交期；跨月延期的批次承诺调整、自动产能优化和拖拽排程不在本轮。真实并发与跨角色办理待验。

### F07 · 现场不良与实领批次

**已实现：** 从原作业 / 报工登记现场不良、现象、证据及实际签收批次；缺码为待补。QC 必须接同一报工的原异常，不能再新增一份相同不良；分析可补实领批号并留历史。退料可关联该作业原质量编号。

**入口：** 作业详情 → 登记现场不良 → 原质量异常；仓储 → 原领料 / 退料。

**边界：** 不用生产批次或送货号冒充库存批号；没有自动补造历史批号，也没有新增跨报工实物分拆 / 合并流程。真实批次与退料需要岗位验收。

**入口：** `/inventory-management` → 物料详情 → 库存依据 / 事件；`/warehouse-flow` → 领料与签收、仓库台账 / 原记录。

**证据：** 仓储批次与主账 20 项，生产 V1.1 / 库存服务 13 项，以及仓储与库存页面回归；覆盖重复事件、单位冲突、冻结 / 报废不双扣、后续快照覆盖、退料范围。[仓储说明](warehouse.md)

**重要限制：** 完整 ERP 库存批次、待检 / 不良 / 冻结分桶和机器可验证凭证接口仍未提供。本地台账不能称为完整 ERP 批次结存。**A06 合格入库 56、A08 不良退回 6、A09 可用 178 的真实业务及同步前后验收未执行**；真实 ERP 自动回写亦未实现。

### F15 · 批次版本范围与已有 SN

**已实现：** 批次档案按段登记软硬件版本、范围、数量与已有 SN；数量不超批次、SN 不超本段且有效范围不重复。每次实际发货另选已有 SN 子集，并保存关联时的版本快照；20 台实发、已关联 12 个 SN 时，本单显示 8 台待补。补录沿原单追加，跨有效发货单 / 计划拒绝重复，冲销只释放原单持有的号码并留历史。

**入口：** 生产计划 → 批次档案 → 版本与 SN；实际发货 / 发货详情 → 补录实发 SN。

**证据：** 生命周期与单次发货服务联合 20 项、前端行为 14 项通过（含共享控件检查合计 23 项）。覆盖 20 / 12 / 8、跨计划重复、版本快照、更正保护、幂等与模拟冲突整次回滚。[生命周期说明](lifecycle.md)

**边界：** 仅关联已存在且人工核实的号码；旧发货全部保留待补，不自动选取批次所有号码。未新增自动编号、扫码或外部 SN 主数据接入，真实 PostgreSQL 跨计划占用竞争尚需独立验证。

### F16 · 研发正式转采购完整性

**已实现：** 正式提交要求有效需求日期、数量 / 单位及规格或服务端确认的图纸 / 规格版本；不适用需留原因。草稿保持宽松。旧任务继续 / 审核入口同样补齐后沿原采购编号提交，需求与依据冻结进交付快照。

**入口：** 研发任务详情 → 转采购 / 继续采购提交表单；采购详情 → 交付资料快照。

**证据：** [样品 / 研发联合回归](sample-rd.md)覆盖缺字段拒绝、不适用说明、旧入口不可绕过、原编号、版本、重复提交和消息事务。

**待验证：** 技术资料变更后的真实通知接收与采购重新确认，需要普通研发 / 采购账号专项联调；内存测试通过不等于通知已送达生产用户。

### F17 · 无正式目标的草稿情景试算

**已实现：** 无正式计划时可选择 BOM 型号、草稿整机目标和需求日试算；未下单方案量与检验可用日显式填写，晚到方案不计覆盖。未占用供给与正式计划分配隔离；不生成正式计划、采购、占用或正式历史。改条件标记上次结果，换 BOM / 月 / 账号清理旧请求。

**入口：** 生产计划与执行 → 草稿情景试算；从正式列表进入后可返回正式计划。

**证据：** `planning-round2.spec.ts`、采购分配情景用例与 `planning-round2-ui.test.mjs`；覆盖空 / 非法 BOM、晚到方案、无写入、显式请求、分页及竞态。

**边界：** 方案是比较假设，不是正式在途；真实供给来源缺失仍为待核对，不输出假零。真实下月数据与岗位体验由集成验收补充。

### F18 · 独立物料 × 供应商供货资格

**已实现：** 资格与报价独立：待审核、可供货、暂停、撤销，绑定真实物料 / 供应商 ID，记录适用产品、生效 / 失效时间、原因与真实审核证据。登记和审核权限区分；失效、停用或证据缺失不冒充可供货。列表 / 详情有搜索、状态筛选、分页和版本历史。

**入口：** 报价库 → 供货资格；物料详情按需展开；关键物料 → 供应商资质。精确参数为 `view=qualifications&materialId=<物料ID>&supplierId=<供应商ID>`，没有真实供应商 ID 时仅限定物料。

**证据：** 服务 8 项、UI 5 项；覆盖真实主数据、证据所有权、审核边界、生效期、撤销、幂等与版本冲突。[供货资格说明](qualified-materials.md)

**边界：** 不把历史报价、供应商启用或单次样品通过自动变成合格供货关系；未改变 ERP 下单审批。真实供应商审核、文件与岗位联调未完成。

## 5. 仍需独立环境验证的事项

1. **真实数据库竞争。** PostgreSQL 多连接并发分配、双版本提交、重试和事务回滚；本轮覆盖的是内存服务规则及冲突映射。
2. **真实角色与文件。** 普通研发、采购、仓管、质检、计划员分别验证查看 / 修改范围；OSS 历史版本、停用文件、续签及上传归属真实联调。
3. **ERP 与完整业务用例。** A06 / A08 / A09 同步前后主账一致性、到货 / 合格 / 不良 / 待补分开、重复凭证与来源覆盖，均需隔离业务数据操作。未提供的完整库存批次 / 分桶接口不能由本地推导代替。
4. **范围仍需辨明。** F02 只覆盖已接入且获授权的真实来源；F11 反查明确分配关系，不猜潜在需求；F15 只关联已有 SN。作业跨月批次承诺调整、自动产能优化和逐台扫码未在本轮实现。
5. **真实全链路。** 从研发交付、样品、转产、分配、收检、派工、现场不良、原异常复验、放行到发货，按原编号和普通角色验收；当前自动化结果不能替代这一轮业务确认。
