# F02：管理风险补齐独立供应链原单

依据原开发说明 G00 / S00：需要计划、缺料、到货和来料不良的原记录入口；管理指标口径明确“未关闭且超约定期限／指定业务状态”，同一跨部门异常只计一次。本次补充原来只随正式生产计划出现的风险来源，未把所有未完成事项当风险。

## 实现范围

- **采购逾期**：有明确已过日期且未完结的原采购任务；询价等前置状态沿用任务截止／需求日，在途和部分到货沿用任务预计到货日。已取消、已完成、业务完结、已到齐或没有对应日期不判为逾期。
- **订单逾期**：有效真实 ERP 订单行存在未收余额，且最新有效供应商承诺（无承诺记录时明确标注 ERP 预计到货）已过期。撤销承诺、来源变更和无日期不会回退旧 ERP 日期。数量标明 ERP 同步未收口径及同步日，不把它伪装为现场实物数量。
- **未闭环质量**：正式采购、生产、仓库、售后原异常，包含未关联生产计划及跨月未关闭的记录。与生产作业中同一 qualityId 合并，保留真实单位和批次；质量协同经办及其期限仅来自已有协同记录，未登记显示待确认，不把创建人、审核人或责任认定人推作当前经办。
- **关键物料上下文**：只有拥有关键物料页面权限、已确认纳入且映射真实 materialId 的风险记录才显示关键物料入口。未映射会议线索、尚无需求的物料不被凭空标为缺料，也不复制一份原异常。

ERP 订单行只生成一条风险；同物料且精确关联原订单号／行号的采购到货风险合并到该行，独立的前置办理期限仍保留。相同名称而不同物料、产品或订单行不能互相合并。现有生产批次齐套风险保留其批次需求口径，不把一个订单的未分配数量重复计入多个批次。

## 权限、时间与链接

`managementRiskScopes` 按原来源分别裁剪。采购风险需要采购驾驶舱全量读取权限；订单行使用已有采购订单列表／详情读取权限；质量使用既有原质量读取范围；生产仍要求生产页面加计划／查看全部权限。API 和 Panel 不因能查看一种来源而放开另一来源。

无生产全量权限时 `completed/remaining/firstFinal` 为 `null`，生产批次为空；Panel 省略生产数字和批次页签。管理首页外层入口由对应代理衔接，共用 `canReadManagementRisks`，供应链和质量账号保留办公页默认，仅增加可见管理页签。

产品过滤使用实际 productId；产品名称只读取授权原记录对应的产品目录条目或已有生产快照，不按同名／型号猜归属。没有精确任务关联的独立订单仅在“全部产品”出现，并标明归属待确认。本月与跨月风险可单独筛选；历史月是业务日期范围内**当前仍未闭环**的风险，不声称恢复历史状态快照。

- 采购打开原 `task` 独立详情，保留 `detail=1`。
- 订单链接复用原订单号及镜像行 `lineId` 的标准链接工具。
- 独立质量在当前页面以 `riskQuality` 打开原 `QualityAnalysisDialog`；ID 必须出现在本次授权风险响应内，服务端再次检查原记录权限，关闭保留原有页面参数。
- 已有生产作业、ECN 和批次链接保持原参数。
- 关键物料入口带真实物料 ID 和月份；没有正式生产计划产品映射时不伪造产品需求范围。

## 验证与边界

`management-supply-risks.spec.ts` 新增 10 个真实服务行为用例，覆盖源级权限、缺失／撤销／失效日期、有效在途、精确原行去重、同名不同 ID、质量单位与经办、跨月、受限产品目录、关键物料权限及损坏记录显式失败。UI 新增 3 个行为用例验证供应链账号隐藏生产指标、原单 ID 链接、原质量弹窗范围和跨月筛选；旧分页、切产品、换账号、过期响应与原生产下钻继续验证。

相关后端联合 69 / 69 通过（管理风险、规划、订单交期、质量操作）；前端联合 28 / 28 通过（规划风险、管理首页、共享 UI 规范）。前后端 TypeScript 检查通过。日志为 `management-supply-risk-api.log`、`management-supply-risk-ui.log`。

没有新增 provider、数据写入、迁移或外部系统同步。未执行浏览器验收。当前未覆盖没有明确日期且未登记异常的潜在风险、自动推断责任人／采购人、外部售后工单实时状态或历史关闭状态重建；这些没有可靠现成来源，保持待确认。
