# F11 补充：原订单行反查影响计划与批次

交期日期口径和齐套核对之外，现已从原订单详情增加按需展开的“影响计划与批次”。它查询当前真实分配台账，不把同名物料、历史零分配或单一计划的隐式兼容数量编造成已分配关系。

## 已实现

- `GET /api/procurement/delivery/lines/:lineId/impacts?orderNo=<原单号>&page=1` 同时要求采购订单读取和正式生产齐套读取权限。校验行 ID 与原单号匹配后，才读计划；只有本人作业权限不能越权查询全部计划。
- 仅真实正数未释放分配建立关系。计划和批次以存储的实际 ID 精确匹配；被删除或找不到的关系只提示待核对项数，不猜链接。没有分配记录不等于没有潜在需求。
- 每页 10 项，在同一 RepeatableRead 读取事务中调用现有正式齐套计算。展示原登记数量、当前有效分配、批次需求日、检验后可用日、按期数量与延期天数。失效来源、未知日期或计算失败显示待核对，不伪填零。
- 整月分配没有唯一需求日，因此按期覆盖保持未知；用户可进入真实计划选择批次继续核对。月级本级分配与下级批次分配分别展示，不把月级汇总再次算入本表数量。
- 采购订单详情及原交期抽屉复用同一折叠区域；默认不发请求。展开后可分页、刷新和重试，订单 / 来源 / 账号 / 权限变化会隐藏旧数据并取消旧请求。
- “查看齐套”携带原计划的 `month`、`plan` 和真实 `readinessBatch`，新标签打开，以保留当前交期表单草稿；月级记录不附加虚构批次 ID。
- 保存承诺或成功重读交期后更新影响范围。折叠组件不改变供应商承诺、ERP 镜像和采购分配写权限。

## 范围限制

本接口不是全公司潜在需求反推；没有明确分配的订单不会按编码推测受影响计划。没有新增写命令、数据迁移或 provider。测试使用纯内存读取模拟，未写真实数据库；真实 PostgreSQL 快照性能、普通角色和供应商改期后的 ERP / 齐套联动仍需隔离环境验证。
