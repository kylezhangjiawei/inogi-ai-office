# F14 仓储主账、实际批次与 ERP 覆盖

本轮补齐真实库存镜像旁的本地限制与事件台账，未写入真实数据库或 ERP。

- ERP 存货编码×仓库仍是唯一库存基数。主账可用扣除未覆盖发料、已复核盘亏、本地冻结和报废；本地合格收货/退料只显示待覆盖，绝不加到 ERP 数字。
- 独立 helper warehouseStockExposure 返回冻结与未覆盖报废、单独的盘亏、合格/不良/待检待覆盖及单位/重复数据问题；readiness 由主代理接相同 helper，避免重复扣盘亏。
- 仓库台账可登记冻结，具 warehouse:adjust 的仓管可解除或将同一原记录转报废（不新建第二笔扣减）。所有动作有原版本、请求幂等、串行事务、历史及审计；转报废后仍需 ERP 凭证核对和严格晚于核对时间的库存快照才能解除限制。
- 发料逐行保留真实 batches 与 batchPendingQty，签收只能使用已发未签的实际批次或对应待补部分。派工单的生产批次、采购送货号不会冒充库存批号。行上持久化 signedBatches/signedBatchPendingQty 供质量取原批号。
- 收货/退料新增真实 stockBatchNo，可缺失待补。退料输入批号必须属于实领签收并有剩余；发起与确认都检查。原质量编号可关联，但必须属于原作业，已有明确物料/批号时逐项核对。
- 库存详情使用系统 Table 展示 ERP 基数、各限制及待覆盖状态，真实事件支持状态/关键字筛选与分页，仓管可回到原台账/领料单。同步失败与请求竞态处理保留。

- warehouse-stock-ledger + warehouse-flow 20 条通过：真实批次守恒、禁止虚构批号、待补/旧数据兼容、签收上限、冻结权限/额度/版本/幂等、转报废不双扣、严格后续同步、单位冲突、重复记录、真实事件来源。
- production-v11 + tplus-operations 13 条通过，包含 A08 不良退料、A09 盘亏至可用 178、采购镜像只读口径。
- warehouse-workspace + warehouse-reconciliation 9 条通过；库存页面现有 7 条通过；前端类型检查通过。
- 前后端整库类型检查均通过（并行编辑期间的临时类型错误已修复）。

## 明确边界

ERP 同步目前没有提供真实库存批次、完整待检/不良/冻结分桶或机器可验证的入出库凭证接口。本轮不会推导虚构这些事实：页面明确本地记录只是可证的状态，不能当作完整 ERP 批次结存；ERP 凭证核对仍是独立权限人员填写的证据。实际批号允许待补，旧记录保留旧来源号而不改成假批号。未部署、未执行真实发料/冻结/报废或 ERP 同步。
