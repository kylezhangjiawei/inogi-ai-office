# 第二轮：样品验证与研发采购提交（F13 / F16）

## 已实现

### F13 样品验证类型与适用依据

- 样品详情增加独立「验证依据」页签，资料预览、结论、登记和历史继续分区展示，避免在结论栏堆叠长表单。
- 当前指定测试人员明确选择「研发探索」或「转产验证」，核对图纸 / 规格、SIP、SOP、治具和试装 / 小批五项。
- 探索型可填写逐项不适用原因；转产型的图纸、SIP、SOP 必须使用交付快照中的固定技术版本，适用治具同样需要固定版本。治具不适用需说明原因。试装 / 小批需要真实文件依据、通过结果及说明。
- 普通任务附件不能充当转产受控版本，传入虚构、其他任务或已变更交付的引用会被服务端拒绝。文件名称、版本与来源从服务器已有交付记录取得，不接受客户端自填版本。
- 新增本轮证据上传：仅当前指定测试人员可写，校验当前轮次、任务状态、更新时间及文件存储范围；旧处理器、被改派人员和已结束轮次不能写入。普通证据不会自动成为受控版本。
- 通过结论必须经过服务端核验。失败结论仍可按已有重新送样 / 重新询价分支处理，继续通知真实采购负责人。
- 确认时冻结适用清单、依据版本、确认人和时间；重送样与改派保留旧轮次，历史页可查看每轮依据。
- 旧数据明确显示「历史未分类」，不自动补造探索类型或转产合格。报价附件不会出现在研发的验证依据选项中。

### F16 正式转采购完整性

- 正式提交要求有效需求日期、数量与单位，并要求规格或服务器确认的图纸 / 规格版本。日期或规格确实不适用时，必须说明原因。
- 草稿可保留不完整字段；不适用原因随本次不可变交付快照保存，并在采购交付详情显示。
- 待继续的旧研发采购任务也不能通过旧继续 / 审核入口绕过门槛。研发入口打开同一提交表单，补齐后沿用原采购编号并追加交付快照。
- 并发重提仍由原任务状态与更新时间约束；原日志、附件历史、采购分配及待办处理链保留。

## 边界

- 本轮复用既有研发受控交付版本与真实附件，不自动创建 SIP / SOP / 治具文件，也不把文档登记等同业务验收。
- 样品通过不会代替生产端的独立转产验证和放行流程。
- 服务测试使用内存事务夹具，不写真实数据库或上传真实业务证据；浏览器与真实岗位联调由主任务统一验收。
