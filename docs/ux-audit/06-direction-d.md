# Direction D · 供应链任务执行驾驶舱

## 方向定位

Direction D 将产品定位为**供应链任务执行驾驶舱**，服务采购负责人、供应链经理和项目负责人每天处理真实工作：确认任务、追问责任人、处理延期、解除阻塞、跟进供应商和推进下一节点。

它不以 KPI 看板为首页，也不把任务拆成一组互相平行的卡片。首页的主对象是“现在需要谁做什么”，状态是任务的时间线，异常是需要介入的工作，供应商风险是任务上下文的一部分。

设计签名是 **Next Action Rail（下一动作轨）**：任务在列表、详情和状态流中都持续显示同一组信息：

> 当前状态 → 阻塞原因 → 责任人 → 截止/承诺时间 → 下一动作

这样用户不需要打开多个页面来回答“下一步是谁做什么”。

## 真实业务边界

Direction D 使用现有采购驾驶舱的业务对象和术语：

- 采购任务、样品协同、备货计划
- 任务编号、物料名称、规格、数量/单位、业务线、需求月份
- 采购负责人、供应商、关联 T+ 采购订单、预计到货与实际到货
- 待继续转采购、待处理、待询价、询价中、待到样、测试中、已定价、待购买、已下单/在途、部分到货、已完成、已取消
- 确认提交、选择报价、完成询价、样品已到、安排研发测试、标记已下单、打开链接下单、登记到货
- 转派、回退、取消任务、操作记录、打开完整详情

页面可以把这些对象重新组织成执行队列，但不能把“已下单”“已到货”“检验合格”“已完成”合并成一个完成状态，也不能把采购负责人、研发测试人、仓管或质量责任人当成同一个角色。

## 1. 首页布局

首页是**我的执行队列 + 全局异常上下文**，不是指标总览。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 供应链管理 / 执行驾驶舱                 范围：我的任务 · 全部供应链   王工     │
├──────────────────────────────────────────────────────────────────────────────┤
│ 今天要清空的工作                                                               │
│ [待我处理  8] [今天到期  3] [已阻塞  2] [等待他人  4]                         │
│ 这些是可进入任务的队列入口，不是装饰性 KPI 卡片。                              │
├───────────────────────────────┬───────────────────────────┬──────────────────┤
│ 待我处理                       │ 阻塞与延期                │ 供应商风险       │
│                               │                           │                  │
│ 1  主板传感器                  │ 延期  PROC-…               │ 上海瑞医         │
│    询价中 · 完成询价           │ 原因：报价未齐             │ 2 个任务逾期     │
│    截止 今天 17:00             │ 责任：王工                 │ 最近承诺：09-18   │
│    [完成询价]                  │ [查看任务] [转派]          │ [查看供应商任务] │
│                               │                           │                  │
│ 2  Q5 装配物料                 │ 阻塞  PROC-…               │ 苏州精工         │
│    待到样 · 样品已到           │ 原因：等待研发测试确认     │ 到货 1/3         │
│    截止 明天                   │ 责任：韩琦 → 研发测试人    │ [查看履约]       │
│    [样品已到]                  │ [查看任务]                 │                  │
├───────────────────────────────┴───────────────────────────┴──────────────────┤
│ 全部任务                                                                       │
│ 搜索单号 / 物料 / 人员  业务线 负责人 状态 供应商 风险 需求月份   [新建需求]     │
│ 任务执行列表（默认按需要介入的紧急程度排序）                                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

首页层级：

1. **范围与身份**：明确当前是“我的任务”还是“全部供应链”，避免个人队列和主管视图混淆。
2. **可执行队列入口**：待我处理、今天到期、已阻塞、等待他人。数字只作为队列数量，不承担业务成就感或趋势表达。
3. **三条工作流**：待我处理是主列；阻塞与延期用于介入；供应商风险用于横向判断。三者都是任务列表的不同切片，不是三种独立数据模型。
4. **全部任务**：作为检索和跨任务比较的底层列表，保留筛选、批量转派、批量归类、单据匹配和导出当前列表。

首页不放无明确行动的趋势图、环形图、装饰性 KPI 卡片，也不把每一个区块做成浮动 Card。使用连续工作面、列分隔线和紧凑行高，让用户感觉是在处理队列，而不是浏览报告。

## 2. 任务列表布局

### 默认排序与分组

默认按“需要介入的紧急程度”排序：

1. 已逾期且仍可推进的任务
2. 今天到期或承诺时间临近的任务
3. 已阻塞、等待他人或供应商未响应的任务
4. 当前用户下一步明确的任务
5. 仅供观察的进行中任务

用户可以切换到“最近更新”“需求月份”“负责人”排序，但系统不以数据库顺序或状态字母顺序作为默认。

### 列结构

```text
[选择] 任务 / 物料       状态节点        阻塞 / 风险        负责人       供应商
       PROC-…            询价中          报价未齐            王工         上海瑞医
       主板传感器        完成询价        截止 今天 17:00     最后更新 2h

       关联订单 / 到货   需求月份        下一动作                         操作
       PO-… / 0 / 24     2026-09         [完成询价]  [查看详情]  ···
```

关键取舍：

- **状态节点**和**下一动作**相邻，避免用户看完状态后还要在详情页寻找能做什么。
- **阻塞/风险**是独立列，不能只通过红色状态推断延期原因。无阻塞时显示“无”或明确的等待状态。
- **负责人**同时展示当前责任人和最后更新时间；转派后保留历史责任人到操作记录。
- **供应商**显示供应商名称与任务级风险摘要，供应商风险本身可以打开供应商任务切片，但不在任务列表里伪造一个供应商评分。
- **关联订单/到货**显示已知事实，例如 T+ 订单号、已到/总量、承诺日期；不把“已下单/在途”直接解释成“已到货”。
- 长物料名、规格和供应商名单行省略，悬停或详情中完整显示；不允许整行被长文本撑开。

### 列表内操作

- 主操作只有一个：当前状态对应的下一动作。
- 次操作：查看详情。
- 更多操作：操作记录、回退、转派、取消任务；取消保留留痕，不执行物理删除。
- 批量操作只在勾选后出现，包含批量转派、批量归类和单据匹配；不会把状态推进这种需要逐条核对的动作伪装成无确认的批量按钮。

### 筛选与检索

筛选栏围绕执行决策组织：业务线、负责人、状态、供应商、风险、需求月份、是否逾期。搜索保留真实占位词“搜索单号 / 物料 / 人员”。筛选条件显示在列表标题旁，清除筛选后回到用户默认队列，不回到无意义的全量空白页。

## 3. 详情页布局

详情是**独立任务页面**，因为它需要同时核对物料、订单、样品/测试、供应商、交期和操作留痕。列表仍可用 Drawer 做快速预览，但完整推进和跨角色交接不塞进窄抽屉。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ← 返回任务队列   采购任务 / PROC-2026-0415-01                    [更多操作] │
│ 主板传感器   询价中   当前责任人：王工   需求月份：2026-09                  │
│ 阻塞：报价未齐 · 截止今天 17:00 · 最后更新 2 小时前                         │
│ [完成询价]  [转派]  [回退]  [取消任务]                                      │
├──────────────────────┬────────────────────────────────┬──────────────────────┤
│ 状态流                │ 任务与履约事实                  │ 当前协作与留痕       │
│                      │                                │                      │
│ ● 待处理              │ 物料名称   主板传感器           │ 当前责任人 王工       │
│ │ 确认提交            │ 规格       R-214 / 电子系统    │ 研发测试人 —         │
│ ● 待询价              │ 数量       24 件               │ 采购方式 询价采购    │
│ │ 选择报价            │ 业务线     普通采购             │ 供应商   上海瑞医    │
│ ● 询价中  ← 当前     │ 需求月份   2026-09             │                      │
│ │ 完成询价            │ T+ 订单    —                  │ 最近动作             │
│ ○ 已定价              │ 承诺日期   2026-09-18         │ 09:30 王工 发起询价  │
│ ○ 待购买              │ 到货       0 / 24              │ 昨日 系统 状态更新   │
│ ○ 已下单/在途         │ 风险       报价未齐             │ [查看全部操作记录]   │
│ ○ 部分到货            │                                │                      │
│ ○ 已完成              │ 关联资料 / 报价快照 / 订单行   │                      │
├──────────────────────┴────────────────────────────────┴──────────────────────┤
│ 下一动作说明：完成询价后，任务将进入“已定价”或“待到样”。                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

详情页分三块：

- **左侧状态流**：状态、进入条件、完成动作和当前节点；状态流本身不等于装饰性时间线。
- **中间履约事实**：任务字段、供应商、T+ 订单、承诺日期、到货数量、报价或样品关联；只呈现已确认事实。
- **右侧协作与留痕**：责任人、研发测试人、最近动作、操作记录和风险原因；让项目负责人能判断“谁在等谁”。

需要填写信息时，使用与当前节点对应的上下文表单：

- “待处理”打开确认接收/确认提交表单。
- “待询价”打开报价选择表单。
- “询价中”打开完成询价表单，并明确是否进入已定价或待到样。
- “待到样”打开样品已到和研发测试人指定表单。
- “已定价 / 待购买”打开 T+ 采购单号或直购链接表单。
- “已下单 / 部分到货”打开登记到货表单。

这些表单可以用右侧上下文 Drawer 或轻量 Dialog 承载，但不把整个任务详情放进 Modal；离开当前任务时必须保留未提交提醒。

## 4. 状态流设计

### 主状态流

```text
待继续转采购
      ↓ 研发确认需求并转采购
待处理 ──确认提交──→ 待询价 ──选择报价──→ 询价中
                                           ├─完成询价（无需样品）→ 已定价
                                           └─完成询价（需要样品）→ 待到样
                                                                       ↓ 样品已到
                                                                    测试中
                                                                       ↓ 安排研发测试 / 确认结论
                                                                  已定价
                                                                       ↓ 标记已下单
                                                                  待购买
                                                                       ↓ 打开链接下单 / 录入 T+
                                                                已下单/在途
                                                                       ↓ 登记到货
                                                                  部分到货 ──继续登记到货──→ 已完成
```

`已取消`是履约中任意节点的可留痕终止分支，不从视觉上伪装成正常完成；`已完成`只在任务履约事实满足后出现。

### 每个状态必须展示的五个字段

| 维度 | 例子 | 设计要求 |
| --- | --- | --- |
| 当前状态 | 询价中 | 用文字、节点位置和状态标记同时表达，不能只依靠颜色 |
| 阻塞原因 | 报价未齐 | 必须能定位原因，空值显示“无阻塞”而非留白 |
| 当前责任人 | 王工 | 显示谁可以执行下一步；等待研发时明确显示等待对象 |
| 时间风险 | 今天 17:00 / 已逾期 | 同时显示承诺日期和最后更新，避免只显示相对时间 |
| 下一动作 | 完成询价 | 只给当前角色可执行的动作，完成后解释下一状态 |

### 异常与等待

- **延期**：基于承诺日期和当前状态计算，显示“逾期 X 天”，不把所有旧任务统称异常。
- **等待他人**：状态仍保持业务真实状态，例如“测试中”，但责任区显示“等待研发测试人确认”。
- **供应商风险**：显示来自任务履约事实的风险，例如报价未齐、承诺日期变化、部分到货；不生成没有数据依据的供应商分数。
- **部分到货**：显示已到/总量、剩余数量和下一次登记到货动作，不能显示成完成。
- **状态修正**：只在详情的更多操作中进入，并要求理由；历史登记和操作记录保留。

## 页面承载决策

| 内容 | 承载方式 | 原因 |
| --- | --- | --- |
| 我的执行队列、延期、阻塞 | 首页连续工作区 | 每天高频扫描，需要同时比较多个任务 |
| 全部任务与筛选 | 首页下方任务列表 | 保持队列和检索在同一个工作上下文 |
| 任务完整事实、状态流、履约 | 独立详情页 | 信息量和跨角色责任超过 Drawer 的安全宽度 |
| 列表快速查看 | Drawer | 不离开队列即可确认少量字段 |
| 当前状态对应的字段输入 | 上下文 Drawer / Dialog | 表单是动作的一部分，避免导航跳失 |
| 回退、取消、删除等高影响操作 | Confirm Dialog | 明确后果、理由和留痕规则 |

## 任务完成路径

采购负责人打开首页后，目标路径是：

1. 进入“待我处理”队列。
2. 从第一条任务直接看到当前状态、阻塞、截止时间和下一动作。
3. 执行下一动作并完成节点所需表单。
4. 返回队列，任务移动到下一责任人或下一等待状态。
5. 对逾期、阻塞和供应商风险任务单独介入，而不是通过多个 KPI 卡片猜测问题。

这个方向的成功标准不是首页展示了多少数字，而是用户能否在一个工作区内快速回答：**我现在要处理什么、为什么没有推进、谁负责、下一步是什么、何时会影响交付。**
