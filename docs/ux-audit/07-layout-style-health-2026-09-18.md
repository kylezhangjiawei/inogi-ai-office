# 布局与样式健康检查

日期：2026-09-18。只读审查；本次仅新增报告，没有修改应用代码或业务数据。

## 结论与范围

**产品专属结构通过，一致性检查未通过。** 采购任务、业务来源、订单镜像、日期待确认、权限与同步状态都对应真实业务，未发现为了展示而虚构的数据模块。但页面级样式正在改变全局框架尺寸，重复标题、嵌套滚动和自动提醒削弱了连续工作的体验。

建议保留原有浅蓝白背景、白色侧栏和紫色主色。优先统一框架、任务区域与滚动规则，无需更换视觉主题。

本次实页抽查采购工作台、采购订单、用户管理，覆盖 1440×900 桌面和 390×844 窄屏；同时检查全局主题、公共控件和相关页面源码。采购工作台使用已有的全部进行中任务、展开 ERP 状态。抽查数据含演示记录，不代表生产数据规模。

**发现：P0 0 项，P1 0 项，P2 6 项，P3 1 项。** 未发现阻断操作的问题，仅指本次抽查范围。

## P2：建议下一轮处理

### 1. 页面级样式改变全局框架，切页发生位置跳动

- **类别：** 主题 / 实现一致性。
- **证据：** 同为 1440px，采购工作台侧栏实测 240px，顶部栏约 65px；采购订单侧栏 256px，顶部栏约 85px。采购工作台控件采用 6px 圆角，采购订单按钮实测为 10px。
- **位置：** [procurementWorkspace.css](../../src/app/procurement/procurementWorkspace.css#L72)，框架覆盖从第 72 行开始，控件圆角在第 91、93 行；全局控件半径在 [theme.css](../../src/styles/theme.css#L7)。
- **影响：** 相邻业务切换时，导航、内容起点和工具栏位置变化，削弱操作习惯与统一产品感。
- **建议：** 将侧栏宽度、顶部栏高度、页面边距和控件尺寸集中到共享框架；页面只决定内部列宽与信息密度。保留原配色。
- **建议命令：** `$impeccable layout`。

### 2. 任务入口仍被前置摘要挤出首屏

- **类别：** 响应式 / 信息层级。
- **证据：** 采购工作台主滚动位置为 0 时，桌面任务表起点约 y=597px；390×844 窄屏约 y=1115px。首屏依次展示标题、筛选、期限切换、说明、业务来源与 KPI，尚未进入任务行。
- **位置：** [ProcMyWorkspacePage.tsx](../../src/app/procurement/ProcMyWorkspacePage.tsx#L207)，筛选、聚合汇总、KPI、任务工作区排列在第 207—226 行附近。
- **影响：** 高频目标“找到任务并处理”需要先扫过多个口径和摘要，手机上尤其明显。
- **建议：** 保留全部字段与统计口径，将业务来源和说明压缩为可展开摘要；窄屏默认突出当前筛选及任务，其他筛选按需展开。不要用删除业务信息换取简洁。
- **建议命令：** `$impeccable layout`、`$impeccable adapt`。

### 3. 外层页面与任务列表同时滚动，列表高度未匹配实际剩余空间

- **类别：** 布局 / 响应式。
- **证据：** 1440×900 下主区域可视高度约 835px、内容高 2521px；任务表从 y≈597px 开始，自身可视高度约 515px、内容高 966px，因此表格底部已超出首屏，同时仍需在表内滚动。列表设置了 `overscroll-behavior: contain`，滚到边界不会自然继续滚动外层。ERP 订单列表另设 440px 高度上限。
- **位置：** [procurementWorkspace.css](../../src/app/procurement/procurementWorkspace.css#L32)，详情及 ERP 内部滚动规则在第 190、192 行。
- **影响：** 用户需要判断当前鼠标所在滚动区；持续浏览任务或接着查看 ERP 时容易停在内层边界。
- **建议：** 确定一个主要纵向滚动容器。若保留固定工作区，按其真实剩余高度安排列表与详情，并将 ERP 放在外层后续区段；不要仅用固定减去 24rem 估算空间。
- **建议命令：** `$impeccable layout`。

### 4. 日志快捷入口的焦点与滚动定位引用失效

- **类别：** 可访问性 / 实现完整性。
- **证据：** 打开“完整详情”后，浏览器记录 `Collapsible` 和 `CollapsibleTrigger` 不能接收 ref 的两条 React 警告。源码中二者是普通函数组件，未透传 ref；日志快捷入口却依赖这两个 ref 调用 focus 与 scrollIntoView。
- **位置：** [collapsible.tsx](../../src/app/components/ui/collapsible.tsx#L5)、[TaskDetailDrawer.tsx](../../src/app/procurement/components/TaskDetailDrawer.tsx#L171)，引用绑定在第 723、724 行。
- **影响：** 自动展开日志后的焦点转移与定位无法按预期执行。手动展开仍可用；不是整个详情抽屉失效。
- **建议：** 在公共折叠组件正确透传引用，随后验证“查看日志”入口把焦点和可视位置带到日志标题，并验证关闭后焦点恢复。
- **建议命令：** `$impeccable harden`。

### 5. 管理页面会被无关的使用提醒打断

- **类别：** 交互 / 实现一致性。
- **证据：** 用户管理实页检查时自动出现“今天还没用 MateChat 哦”模态框，遮罩覆盖当前任务并将焦点移到“立即去用”。源码在进入页面约 3 秒后检查提醒，仅为采购等部分路径设置豁免。
- **位置：** [MateChatReminderModal.tsx](../../src/app/components/matechat/MateChatReminderModal.tsx#L46)，定时检查在第 109 行附近；全局挂载在 Root。
- **影响：** 账号和权限维护属于专注操作，提醒要求额外关闭，且不同业务页面的免打扰规则不一致。
- **建议：** 保留现有提醒功能和助手入口，将工作页面提醒改为非模态呈现；编辑、审批、详情操作期间延后出现。不要仅继续增加单个路由的例外。
- **建议命令：** `$impeccable harden`。

### 6. 用户管理页重复展示两个一级标题

- **类别：** 信息层级 / 实现一致性。
- **证据：** 桌面和窄屏均能看到顶部栏“用户管理”和正文头部“用户管理”；DOM 中两个 h1 同时可见。正文另有英文分类、说明和账号摘要。
- **位置：** [header_1.tsx](../../src/app/components/header_1.tsx#L265)、[UserManagement.tsx](../../src/app/UserManagement.tsx#L607)。
- **影响：** 窄屏占用宝贵的首屏高度，重复强调页面身份，实际搜索入口被进一步下推。这里不把两个 h1 单独认定为无障碍违规。
- **建议：** 由共享页面框架明确标题归属：全局栏提供当前位置，正文保留页面标题与操作；对已经有正文标题的页面统一处理。
- **建议命令：** `$impeccable layout`。

## P3：维护性整理

### 7. 样式依赖大量强制覆盖，缺少单一权威来源

- **类别：** 主题 / 实现一致性。
- **证据：** 三个样式文件含 `!important` 的匹配行共 2791 行：theme.css 2539、公共 horizon.css 35、采购 horizon.css 217。这是匹配行数，不是独立缺陷数。采购工作台另以页面选择器覆盖共享框架与控件尺寸，实际漂移见问题 1。
- **位置：** [theme.css](../../src/styles/theme.css)、[horizon.css](../../src/styles/horizon.css)、[采购 horizon.css](../../src/app/procurement/horizon.css)、[procurementWorkspace.css](../../src/app/procurement/procurementWorkspace.css#L72)。
- **影响：** 后续修改共享控件时，效果可能被晚加载或高优先级规则抵消，修复容易再次变成追加覆盖。数量本身不能证明性能问题。
- **建议：** 先记录当前正确的色彩与尺寸 token，按共享框架、公共组件、业务变体整理样式归属；逐段移除已被替代的规则，避免一次性删除所有覆盖。
- **建议命令：** `$impeccable document`，整理后用 `$impeccable polish` 复核一致性。

## 应保留的优点与不应误报的项目

- **配色基础统一：** 浅色底、白色工作区、紫色交互强调清晰，不需要换主题解决上述问题。
- **业务信息真实完整：** 采购范围、日期待确认、ERP 同步时间和权限提示都存在；订单页明确提示 T+ 未授权并禁用同步按钮。
- **响应式已有基础：** 采购任务在窄屏转换为纵向字段布局；订单与用户宽表用内部滚动保留字段。表格 min-width 不是整页溢出的充分证据，本次三页均未发生整页横向溢出。
- **可访问性与加载基础存在：** 筛选有名称、任务和订单有区域语义、详情采用对话框语义，路由使用懒加载。不能因局部问题把这些已有能力推翻。

## 建议执行顺序

1. `$impeccable layout`：统一全局框架、消除重复标题，调整首屏及滚动规则。
2. `$impeccable harden`：修复日志定位，统一工作页面的提醒策略。
3. `$impeccable adapt`：验证窄屏任务入口、宽表及详情展开关系；补充真实触屏检查。
4. `$impeccable polish`：在原色调下收齐圆角、字阶、边距和状态样式。

可逐项、一起或按其他顺序执行；本次没有实施这些修复。完成后重新运行 `$impeccable audit` 复查。未测范围包括全部业务路由、暗色模式、浏览器缩放、完整键盘与读屏流程、生产性能和真实触控。
