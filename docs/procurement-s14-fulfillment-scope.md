# S14 订单详情数量与到货核对收尾

2026-09-14，延续“先补页面和交互”。在现有实际采购订单详情完成阅读与筛选收尾，没有改动服务端、ERP 同步、订单状态或业务写入。

原页面将所有订单行的订购和已到数量相加，再计算整单百分比。已用修改前实际表达式复现：两行各订 10，分别到 20 / 0，会显示 100%；1 套已到与 100 米未到会显示 1 / 101。这两个结果都掩盖逐行核对的边界。原始复现见 `artifacts/qa/s14-fulfillment/baseline/reproduction.txt`。

本次改为：

- 顶部展示已读取订单行、数量已收齐行、未收齐行及待核对行，不再计算跨物料/单位的整单到货百分比。超收行计入数量已达订购量的行数，同时单独标明超收。
- 数量按原单位分组，保留已到、订购、逐行未收差额及超收量。超收不抵其他行未收；不换算“件/套/米”等单位，不按 SKU 合并原行。
- 零订购量、负数、缺失/非有限数量与缺单位明确待核对；受影响的单位分组暂不合计，避免把未知凑为零。小数差额统一格式化显示，原计算值不被改写。
- 商品明细提供全部、未收齐、超收、待核对四种筛选；数量和金额汇总始终覆盖全部已读明细。筛选后保留原行号及日期历史、收货台账入口，关闭抽屉保留筛选并恢复入口焦点。
- 新导航或浏览器前进/后退恢复全部明细，确保精确目标行可见；普通抽屉开关不重置筛选。修复复核发现的旧历史位置恢复旧筛选问题，已保存修前失败与修后通过日志。
- 订单记录只呈现来源提供的审批、交付方式和 ERP 到货信息，不根据“已完成”状态推断审批通过、全部到货或入库；原仓库信息保留为“订单登记仓库”。

未收差额只是 `max(订购 − ERP 已到, 0)` 的逐行阅读值，未纳入批准取消、退货、冲销、检验和库存分配，不是供应商剩余交付义务、质检合格量或可用库存。分组相同单位仅用于数量阅读，不代表物料互相可替代。后端已规范化或丢失的信息不能由前端还原。
