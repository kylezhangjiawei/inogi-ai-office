2026-09-10。用户明确调整顺序为“先完善缺失页面和功能，再完善接口和业务逻辑”。本批完成收货处置前端流程，使用独立演示数据；不代表正式入库或退换业务已上线。

预览地址：http://127.0.0.1:5173/__preview/receipt-disposition

## 本批已完成

| 页面 / 操作 | 可验证的交互 |
| --- | --- |
| 收货处置工作区 | 左侧批次搜索与选择，上方采购订单、送货单、供应商及原始数量，右侧填写，左侧待处理量和记录；手机批次列表折叠，表单优先显示 |
| 收货纠错 | 填写纠正后实收量、日期及原因；展示前后差额；保留原始实收和每次纠正记录 |
| 合格入库 | 展示合格待入库量，选择演示仓库、联动库位，填写数量、关联单据和依据；保存后更新演示累计及记录 |
| 不良隔离 | 仅处理明确判为不良的数量，填写隔离仓库、库位、负责人和原因；待判定数量独立保留 |
| 退换补货 | 退货与换补分支、供应商只读、关联单号、负责人、原因；换补需预计日期；记录为“待办理”安排 |
| 共通交互 | 三位小数、数量范围、日期及必填校验；错误定位首个字段；保存前核对；防双击；取消或切换前保护草稿；失败保留内容并可重试 |
| 演示状态 | 暂无收货、读取失败及恢复、仅可查看、下次保存失败、批次搜索无结果、重置演示 |

演示内存模型保留 `receiptId`、版本、订单行/送货单身份、单位、数量前后值、关联单据和操作信息，供后续真实接口映射。组件与演示状态分文件管理，没有新增客户端 API 或持久化存储。

## 本批边界

- 所有新增记录只存在当前页面内存；刷新或重置恢复三条演示批次。界面持续显示演示说明，按钮使用“保存演示记录”。
- 不读取或改写正式收货、检验、ERP、采购任务、备货计划或库存数据，不新增数据库表、迁移或业务接口。
- 原正式订单行的“收货与检验”入口继续使用已完成的一期台账。新增预览没有混入正式菜单，也没有从正式记录进入假保存表单。
- 预览路由和懒加载仅在开发模式注册；生产构建中验证未包含该路由、演示批次标识和页面模块。
- 入库、隔离的累计只表示页面演示状态；退换安排不会冲减原实收、检验、入库或隔离数量，也不视为供应商已退收或补货已到货。
- 纠错不得低于已分类量、只隔离明确不良、先隔离后安排退换等限制是用于评审的临时规则。正式规则、权限及 ERP 记账归属后续确认，不将本批校验等同于业务验收。
- 仓库与库位是演示选项；关联单号由人工填写，不表示已生成或验证真实单据。

质检附件、受控检验规范版本、真实质量异常单、正式入库、冲销、退货执行、补货收货/复检、库存分配与按期齐套预测都未在本批完成。
