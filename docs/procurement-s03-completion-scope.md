# S03 实际时间、轮次历史与采购条件登记

2026-09-14。本轮开始补齐 S03 的持久化业务链路；取代 `procurement-s03-finishing-scope.md` 中“仅最后一轮记录、实际时间和结构化条件未实现”的旧边界。此文记录代码与隔离验证结果，不代表已对真实业务数据验收。

## 已实现

- 到样、开测、结束三个独立实际时间持久化到 `ProcTask.metadata.sampleTest`。不会用分派时间、结论时间、订单到货量或预计到货代填。
- 分派弹窗登记实际到样日期时间；新分派使用 `recordsVersion: 1`。已有旧客户端可以先分派、后登记实际到样，列表此时显示“实际到样待登记”。新轮次确认结论前必须保存完整、有效的实际到样、开测和结束时间。
- 实际时间必须带时区，公历有效，不晚于服务端当前时间；到样 ≤ 开测 ≤ 结束。允许补录已发生的时间，分派与录入操作时间单独保留，不强行把补录时间当作实际发生时间。已登记时间只能有效更正，不能清空；每次更正保存一份登记快照、经办人和登记时间。
- 改派、新一轮送样及回退/取消/重做报价造成的未确认轮次终止均保留历史。改派产生新的轮次 ID，新测试人不能继承旧开测、结束、结论或采购条件；已知同轮到样可以沿用，原来源仍在前轮历史中。再次送样不沿用上一轮到样。已确认旧结论继续保留，下一次分派前归档。
- 独立登记本轮任务级采购条件：计价单位、含税/未税口径、税率、付款条件、运费承担和交付条件、交期起算方式、约定起算日期、备注。数据保存在本轮 metadata 及更正/归档历史中。原采购报价的供应商、价格、物料 ID 和币种仍以原记录为准；不会按同名物料或已选报价自动填入本轮约定，不由交期天数推算 ETA。
- 样品详情增加登记表、真实时间卡、完整已保存轮次与登记更正历史。采购工作台、研发测试弹窗和手机深链复用同一组件。保存登记刷新样品详情；只有正式确认结论才触发原“已确认”回调和既有通知流程。

## 接口与权限

- `POST /procurement/tasks/:id/sample-test/assign` 新增可选 `arrivedAt`。保留 `testerUserId/fromStatus/baseUpdatedAt`，需要询价权限且具有该任务的采购读取范围；采购个人页按稳定 buyer ID 匹配，旧无 ID 负责人仅在启用人员中唯一匹配时可用。指定人员必须为启用且有研发个人工作台权限的真实账号。
- `PATCH /procurement/tasks/:id/sample-test/records`：`roundId`、`baseUpdatedAt` 必填，按修改内容提交 `arrivedAt/startedAt/finishedAt/commercial`。服务端事务锁定任务，校验轮次、当前状态和精确版本后写入，防止陈旧页面或并发操作覆盖。
- 到样与采购条件需要本任务采购读取范围和询价权限；开测和结束只能由当前指定测试人员本人登记。管理员不能代替指定人员登记测试时间或确认结论。已结束、已改派或已确认轮次不可更改。
- `GET /procurement/tasks/:id/sample-test` 增加 `history/historyIncomplete/canRecordArrival/canRecordTesting/canReadCommercial`。现有 `canConfirm` 继续表示本人当前轮次的结论权限；新轮次仍需满足实际时间门槛。
- 研发可读取本人当前任务的测试资料、时间、结论和轮次。当前采购条件、历史条件及每次更正里的条件全部脱敏。通用任务序列化也不输出新增商业条件，采购通过有权限的样品详情读取。
- 新登记接口不发送额外消息；分派、结论确认沿用原事务内消息逻辑。

## 草稿与并发交互

- 变更后取消、Esc、遮罩关闭提供继续填写/放弃确认。样品工作台的现有切换与导航保护同步纳入登记脏稿和提交状态。
- 保存失败保留草稿，允许重试或保留草稿重新读取。服务端版本变化时保留用户输入但禁止覆盖，需要明确放弃旧稿并载入最新记录。字段恢复原值后取消脏标记。
- 分派、登记和结论提交都有同步重复提交锁；处理中字段和关闭操作禁用。任务、轮次、账号或权限改变，或弹窗卸载后，旧请求结果不能回填、通知父组件或关闭新任务。忽略结果不等于撤销已经发给服务端的请求。
- 登记草稿未保存时不能确认结论；新协议实际结束未登记时显示原因并禁用确认。

## 兼容边界

- 旧系统没有存下的轮次和实际时间无法恢复，不生成虚构历史。旧协议、尚未完成的原有轮次允许继续原结论流程；一旦使用新登记接口则启用完整实际时间要求。新分派全部启用新协议。
- 历史格式不完整时保留原 metadata，明确提示存在无法完整展示的旧轮次；不会为了通过解析而删除原记录。
- 条件是本轮任务的独立约定，并非供应商报价表结构升级；多供应商、多物料报价仍逐条显示原有采购摘要，不能将任务级条件当成某条报价的已确认条款。
- 未增加浏览器刷新后恢复样品草稿的持久化机制。表单会话内的关闭、切换、保存失败和并发保护已实现；刷新/退出应用仍须重新读取已保存内容。
- 无 schema 修改，无 DB migration，无生产数据库写入或真实通知。实际生产账号权限、业务时区习惯与真实业务操作仍需部署后验收。
