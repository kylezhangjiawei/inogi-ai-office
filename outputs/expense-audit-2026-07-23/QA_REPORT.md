# 费用报销统计模块全流程审查报告

审查日期：2026-07-23  
审查目标：确认费用模块能否从空数据开始完成“上传 → OCR → 匹配 → 报销 → 企业微信审批 → 回调同步 → 归档 → 通知 → 统计/导出”的完整流程。  
审查方式：当前页面交互检查、源码静态审查、数据库与环境配置只读核对、前后端类型检查及生产构建。未上传测试文件、未创建或修改业务数据。

## 结论

当前模块**不能完整走通**。

主要阻断点：

1. 企业微信审批配置全部缺失，审批提交、回调与状态同步不能闭环。
2. 新建报销单接口失败时，前端会创建一个只存在于内存中的“本地审批单”，造成假成功。
3. 后端没有付款凭证列表接口；未匹配凭证刷新页面后会从界面消失，流程无法继续。
4. 归档分类、移动和删除均只修改前端状态，刷新后丢失。
5. 邮件通知只记录“已排队”，没有真实发送通道。
6. 后端未阻止同一发票重复进入多个报销单。

## 当前配置状态

| 配置项 | 当前状态 | 对流程的影响 |
| --- | --- | --- |

| 阿里云 OSS | 必填环境变量完整 | 已配置不等于已验证连通性；本次未上传真实文件 |

| 邮件/SMTP | 数据库存在 1 个启用邮箱账号，但没有 SMTP 配置，代码也没有真实发送实现 | 无法发送报销通知 |
| 权限目录 | `page:expense-center`、`expense:view-all` 已存在并启用 | 页面权限存在，但费用 API 没有绑定权限装饰器 |
| 用户部门 | 9 个启用用户中有 3 个未分配部门 | 普通用户会被后端禁止录入费用数据 |

| 自动化测试 | 无费用模块单元、接口或端到端测试 | 回归风险高，无法自动证明完整流程 |

另有一项需要排查的运行时不一致：数据库只读查询显示 1 个启用邮箱，但“新建报销单”弹窗显示没有可用邮箱。前端在邮箱接口失败时直接回退为空数组且不展示错误，因此当前无法在页面上区分“确实没有邮箱”和“接口/环境异常”。

## 完整流程健康度

1. **页面访问与部门隔离 — 部分通过**
   - 页面可访问，管理员可以选择部门。
   - 普通用户未分配部门时无法录入；当前 3 个启用用户受影响。
   - 后端数据作用域实现存在，但费用 Controller 未绑定 `page:expense-center` 或细分操作权限。

2. **配置预检 — 失败**
   - 页面没有调用已经存在的 `/api/expenses/integrations/requirements`。
   - 用户开始上传或创建报销单前，看不到 OCR、OSS、企微、回调、邮件是否可用。
   - 企微所有必填项当前缺失。

3. **发票/付款凭证上传 — 部分通过**
   - 前端支持文件选择、拖拽和粘贴，并限制单次最多 20 个文件。
   - 后端 Multer 接受 30 个文件，且没有文件大小和 MIME 类型限制。
   - `OssService.uploadBuffer` 未使用已经定义的费用文件 10MB/MIME 白名单常量。
   - OSS 上传失败时仍继续创建费用记录，页面不会明确告知原始文件未保存。

4. **OCR 识别 — 部分通过**
   - OCR 环境配置完整，代码支持自动/手动服务模式及官方错误留痕。
   - `enabled=false` 不会阻止调用；可用性判断只检查 SecretId/SecretKey。
   - 本次为保护第三方额度和真实数据，未发起实际 OCR 请求。

5. **AI/人工匹配 — 失败**
   - 自动匹配和人工改绑已有实现。
   - 后端没有 `GET /expenses/vouchers`；页面刷新只重新加载发票、报销单和看板。
   - 未匹配付款凭证只保留在当前 React 会话内，刷新、重新登录或换设备后不可见。
   - 发票与付款凭证的多条写入使用并行独立 upsert，不在事务内，部分写入失败时可能出现单边关联。

6. **新建报销单 — 失败**
   - 空数据时“确认创建”正确禁用。
   - 创建接口失败时，前端会调用 `createLocalApproval` 生成内存审批单并关闭弹窗，用户会误以为创建成功。
   - 企微提交失败被静默吞掉，未向用户展示缺失配置或官方错误。
   - 后端未校验发票是否已报销、是否已进入其他草稿/审批单、是否已经关联付款凭证，同一发票可以重复报销。
   - `applicant` 和 `wecom_creator_userid` 由客户端直接提交，未以认证用户身份覆盖，存在身份冒用风险。

7. **企业微信审批与回调 — 阻断**
   - 当前企微配置全部缺失。
   - 保存配置 DTO 不支持 5 个审批模板控件 ID；这些值只能依赖环境变量或手工写数据库。
   - 页面没有企微配置入口，也没有完整性提示。
   - `enabled` 未参与实际可用性判断；显式停用后仍可能调用企业微信。
   - 回调还需要可被企业微信访问的 HTTPS 地址，并在企业微信后台登记 `/api/expenses/wecom/callback`。

8. **归档分类 — 失败**
   - 分类新增、重命名、删除、凭证移动只修改 `useState`。
   - “删除归档凭证”明确是前端移除，没有后端接口。
   - 刷新后所有人工分类操作恢复；这会造成财务人员误判归档或删除已经完成。

9. **邮件通知 — 阻断**
   - 后端仅写入“邮件通知已排队（待发送通道接入）”活动记录。
   - 没有 SMTP/邮件发送任务、失败重试和送达状态。
   - 当前弹窗还与数据库的启用邮箱数量不一致，错误被静默回退为空。

10. **发票回购/统计/导出 — 部分通过**
    - 统计空态和 CSV 导出代码存在。
    - “本月”“上月”“Q2”及默认日期全部硬编码为 2026 年 4–6 月。
    - 当前系统日期为 2026/07/23，但“本月”显示 2026/05/01–05/31，可稳定复现。
    - 审批流页在无数据时只显示空白卡片，没有解释和下一步入口。

## 缺陷清单与建议

### P0 / 阻断

1. **创建报销失败后生成本地假审批单**
   - 位置：`src/modules/expense/pages/ExpenseModule.tsx:1182`
   - 建议：删除失败分支中的 `createLocalApproval`；保留弹窗并展示后端错误。只有后端返回持久化 ID 后才进入审批流页面。

2. **未匹配付款凭证刷新后丢失**
   - 位置：`apps/api/src/modules/expense/expense.controller.ts:79`、`src/modules/expense/pages/ExpenseModule.tsx:731`
   - 建议：增加带部门作用域、分页和筛选的 `GET /expenses/vouchers`，页面加载时与发票、报销单一并拉取。

3. **企业微信配置缺失且页面无预检**
   - 位置：`apps/api/src/modules/expense/expense.service.ts:687`、`src/modules/expense/services/expenseService.ts:588`
   - 建议：先补齐配置；页面加载 `integrations/requirements`，未就绪时禁用企微提交并展示缺失项和配置入口。

4. **同一发票可重复报销**
   - 位置：`apps/api/src/modules/expense/expense.service.ts:497`
   - 建议：服务端在事务内校验发票状态、匹配状态和其他报销单占用状态；数据库增加可追溯的关联表和唯一约束。

5. **归档操作不持久化**
   - 位置：`src/modules/expense/pages/ExpenseModule.tsx:688`、`:1302`、`:1355`、`:1374`
   - 建议：新增分类、移动、删除/作废 API；成功落库后再更新 UI。财务记录不建议物理删除，应采用作废状态和审计日志。

6. **邮件通知未实现**
   - 位置：`apps/api/src/modules/expense/expense.service.ts:600`
   - 建议：接入统一通知任务表/队列和 SMTP 或企业邮件服务，保存发送状态、重试次数与最终错误；页面不要显示“已排队”作为成功送达。

### P1 / 高风险

7. **费用 API 缺少权限绑定**
   - 位置：`apps/api/src/modules/expense/expense.controller.ts:46`
   - 建议：读接口至少绑定 `page:expense-center`；上传、编辑、匹配、组单、企微提交、改派、集成配置分别增加细粒度权限。集成配置只允许管理员。

8. **申请人和企微提单人可由客户端冒用**
   - 位置：`apps/api/src/modules/expense/expense.controller.ts:136`、`expense.service.ts:517`
   - 建议：Controller 将认证用户 ID/姓名传给 Service；普通用户不可覆盖申请人和 creator user ID，代提交需单独权限并留审计。

9. **上传接口缺少服务端大小/类型限制**
   - 位置：`apps/api/src/modules/expense/expense.controller.ts:69`、`:79`、`apps/api/src/modules/oss/oss.service.ts:85`
   - 建议：Multer 设置文件数、单文件 10MB 和总大小限制；服务端校验 MIME、扩展名和文件签名，统一前后端上限为 20。

10. **原始附件链接 30 天后失效**
    - 位置：`apps/api/src/modules/expense/expense.service.ts:824`、`:912`
    - 建议：持久化 `object_key`，读取时通过受权限保护的接口即时生成短期签名 URL；不要把 30 天签名 URL 当作永久文件地址。

11. **接口异常被伪装为空数据**
    - 位置：`src/modules/expense/services/expenseService.ts:432`、`:449`、`:499`、`:511`
    - 建议：费用主页面使用 strict 请求；区分加载中、空数据、无权限、服务异常，并提供重试。邮箱加载失败也应展示错误。

12. **匹配、审批状态更新缺少事务**
    - 位置：`apps/api/src/modules/expense/expense.service.ts:355`、`:1030`、`:1270`
    - 建议：改用规范化数据表和 Prisma transaction；发票、付款凭证、报销单、事件同时提交或同时回滚。

### P2 / 一般问题

13. **发票回购日期硬编码**
    - 位置：`src/modules/expense/pages/ExpenseModule.tsx:677`、`:3124`
    - 建议：按当前日期动态计算本月、上月和当前季度；校验开始日期不得晚于结束日期。

14. **状态、分类、日期和金额校验不足**
    - 位置：`apps/api/src/modules/expense/dto/update-expense-invoice.dto.ts`
    - 建议：状态/分类改用枚举；日期使用 ISO 日期校验；金额、税额限制为非负并设置合理上限。

15. **配置 DTO 无法保存企微控件 ID**
    - 位置：`apps/api/src/modules/expense/dto/save-expense-integration-config.dto.ts:29`、`expense.service.ts:751`
    - 建议：DTO 增加 `approval_control_ids`，保存时校验五项完整性；提供管理员配置页和连接/模板校验按钮。

16. **审批流无数据空态不完整**
    - 证据：`04-approval-empty.png`
    - 建议：使用与统计页一致的空态组件，说明“暂无报销单”并提供“上传凭证”“新建报销单”入口。

## 建议的修复顺序

1. 先修复假成功、付款凭证恢复、重复报销和权限问题。
2. 补齐企微配置模型、配置页面、控件 ID、回调 HTTPS 与配置预检。
3. 将费用数据从 `SystemSetting` JSON 迁移为发票、付款凭证、关联、报销单、归档和事件表，并增加事务与唯一约束。
4. 实现邮件发送队列和送达状态。
5. 修复动态日期、空态、服务错误提示和附件长期访问。
6. 增加完整自动化测试：
   - Service 单元测试：匹配阈值、重复报销、状态映射、部门隔离。
   - API 集成测试：权限、上传限制、事务回滚、配置预检、回调签名。
   - E2E：上传发票/凭证 → 关联 → 组单 → 企微模拟回调 → 归档 → 统计/导出。
