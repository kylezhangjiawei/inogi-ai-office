## 首轮测试结论（修复前）

基础页面、搜索、筛选、分页、详情、报价选择和库存到采购单跳转可以使用，但当前链路停在“已定价”之后：

1. 采购组名录为 0 人，3 个进行中任务全部未指派，个人工作台没有任何任务。
2. 畅捷通 T+ 显示“待授权”，自动同步失败，采购单镜像数为 0。
3. 单据匹配显示 660 条未匹配、0 条建议、0 条已确认，本地任务无法自动关联 T+ 采购单。
4. 下单登记没有自动带入已确认供应商，而且一个登记表单无法表达多供应商拆单。
5. 采购订单与库存数据存在状态矛盾，库存预警和履约进度目前不可完全信任。

因此现状更接近“本地采购任务 + 独立的历史 T+ 数据看板”，尚未形成“需求 → 报价 → 下单 → T+ 采购单 → 到货 → 库存”的可靠闭环。

## 阻塞问题

### PROC-QA-001：T+ 未完成授权，采购单和库存同步失败

- 严重级别：高
- 分类：集成 / 流程阻塞
- 现象：
  - 物料库的“T+ 集成”显示“凭据已配置、待授权”。
  - 已镜像数据为“供应商 552、库存 2632、采购单 0”。
  - 上次自动同步日志显示供应商 `fetch failed`，库存和采购单全量同步均因未授权失败。
  - 采购订单和库存页面显示“T+ 未授权”，同步按钮不可用。
- 影响：
  - 新采购单、到货进度和库存无法持续回流。
  - 页面现有 242 张采购单和 1882 个 SKU 可能是历史缓存，无法保证时效性。
- 复现：
  1. 打开“物料库”。
  2. 点击“T+ 集成”。
  3. 查看顶部授权状态、镜像数量和底部自动同步日志。
- 建议：
  - 完成生产应用 OAuth 回调授权并验证 token 刷新。
  - 授权成功后依次验证供应商、库存、采购单全量和每日自动同步。
  - 在业务页明确显示数据时间和“已过期”状态，避免把历史缓存误认为实时数据。

### PROC-QA-002：660 张 T+ 单据全部未匹配，本地任务与采购订单无追溯关系

- 严重级别：高
- 分类：集成 / 数据追溯
- 现象：
  - “T+ 单据匹配”显示：建议 0、未匹配 660、已确认 0。
  - 弹窗提示需先采购单全量同步，再运行匹配。
  - 抽查采购单 `PO-2026-07-0051`，关联采购任务为 0。
- 影响：
  - 本地任务不能自动进入在途。
  - T+ 到货数据不能可靠回推到对应需求。
  - 无法从采购单追溯原始需求、报价和审批记录。
- 复现：
  1. 打开“采购任务驾驶舱”。
  2. 点击“单据匹配”。
  3. 查看匹配统计和空状态。
  4. 打开“采购订单”，查看任一订单的“关联采购任务”。
- 建议：
  - 先修复 T+ 全量同步，再按采购任务号、物料编码、供应商、数量、金额和日期生成匹配建议。
  - 对无法自动匹配的记录提供人工搜索、批量确认和冲突说明。
  - 匹配确认后必须回写任务状态、订单号、到货进度和审计日志。

### PROC-QA-003：采购人员名录为空，进行中任务全部未指派

- 严重级别：高
- 分类：任务分派 / 运营配置
- 现象：
  - 采购人员管理显示“名录成员 0 人”。
  - 3 个进行中任务在批量转派弹窗中均显示“当前：未指派”。
  - 采购个人工作台显示进行中 0、待处理 0、已逾期 0。
  - 驾驶舱任务实际已经逾期 55～62 天。
- 影响：
  - 没有采购人员收到待办，任务不会被主动处理。
  - 逾期统计在驾驶舱与个人工作台之间失去业务意义。
- 复现：
  1. 打开“采购任务驾驶舱”，点击“人员管理”。
  2. 查看采购名录人数。
  3. 返回驾驶舱，点击“批量转派”。
  4. 打开“个人工作台”对比任务数量。
- 建议：
  - 系统初始化时自动把采购部门有效成员加入采购名录，或提供“一键同步采购部成员”。
  - 新建采购任务时强制指定负责人，或按采购组负载自动分配。
  - 名录为空时在驾驶舱顶部显示阻塞告警，不允许任务静默进入进行中。

### PROC-QA-004：已确认报价无法正确转换为多供应商采购单

- 严重级别：高
- 分类：业务流程
- 现象：
  - 任务 `PR-20260729-002` 已确认两条报价。
  - 点击“标记已下单”后，供应商输入框仍为空，没有自动带入已确认供应商。
  - 弹窗只提供一个供应商和一个 T+ 采购单号，无法表达多供应商分别下单。
- 影响：
  - 操作人员需要再次手工录入供应商，容易选错。
  - 多供应商报价合并确认后无法按供应商拆成多张采购单。
  - 报价快照与最终订单之间缺少可靠映射。
- 复现：
  1. 打开已定价任务 `PR-20260729-002`。
  2. 确认详情中有两条已确认报价。
  3. 点击“标记已下单”。
  4. 查看供应商和采购单号字段。
- 建议：
  - 按供应商自动分组生成“待登记采购单”。
  - 每组自动带出供应商、报价明细、数量、折扣后金额。
  - 允许每个供应商分别填写 T+ 单号和预计到货日，再一次确认保存。

## 重要问题

### PROC-QA-005：库存“缺货”判定与可用数量矛盾

- 严重级别：中高
- 分类：库存规则 / 数据映射
- 现象：
  - 缺货筛选结果 `ZR1-04-01-GYIII` 显示现存量 0、可用量 2、在途 0、安全库存 0，但状态仍为“缺货”。
  - 详情页仍显示未指定仓库且可用量为 2。
- 影响：
  - 缺料预警可能误报，采购人员无法据此决定是否补货。
- 建议：
  - 明确“缺货”按现存量、可用量还是可销售量计算。
  - 页面增加状态计算口径和来源字段；若采用 T+ 状态，则避免本地根据另一组字段重新解释。

### PROC-QA-006：已完成采购单仍显示“等待供应商确认交付方式”

- 严重级别：中
- 分类：状态机 / 履约展示
- 现象：
  - 采购单 `PO-2026-05-0020` 状态为“已完成”，到货进度 25/25、100%。
  - 履约进度仍显示“等待供应商确认交付方式”，预计到货和目标仓库仍为空。
- 影响：
  - 订单完成状态与履约步骤互相矛盾，容易误导采购人员。
- 建议：
  - 已完成订单应直接终结履约流程。
  - 对历史 T+ 单据缺失的交付字段显示“源系统未提供”，不要显示仍待处理的动作。

### PROC-QA-007：报价历史存在重复记录并触发 React 重复 key 错误

- 严重级别：中
- 分类：前端稳定性 / 数据质量
- 现象：
  - “电池上壳”的价格历史出现 3 条完全相同的“明博（原模具）/ ¥4.50 / 2026-07-29 / 已选定”记录。
  - 浏览器控制台连续产生 2 条 `Encountered two children with the same key` 错误。
  - key 值为 `2026-07-29明博（原模具）`，定位到 `PriceHistoryModal` 的趋势图。
- 影响：
  - 趋势点可能重复、遗漏或错位；后续 React 版本行为不稳定。
- 建议：
  - 前端使用报价记录 ID 作为 key。
  - 后端确认是否产生了重复历史快照，并增加唯一性约束或去重。

### PROC-QA-008：采购转派候选范围过宽

- 严重级别：中
- 分类：权限 / UX
- 现象：
  - 采购名录为空时，批量转派候选包含采购部、研发生产部、总经办、波士顿办公室、超级管理员、UI 设计师等全部用户。
- 影响：
  - 容易把采购任务错误分配给无采购职责人员。
- 建议：
  - 默认只展示采购名录成员。
  - 需要跨部门转派时增加“显示其他人员”开关并给出二次确认。
